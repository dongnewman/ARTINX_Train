三个视角看整车

信息流

遥控 → 主控；主控 ↔ 裁判系统；主控 → 灯条；图传 → 服务器

能量流

电池 → 电源管理 → 常电 + 动力电；超电并接做缓冲

控制关系

主控汇聚所有指令；裁判系统只记不执行

设备总览（上）：大脑与电源

设备属于谁一句话作用大致位置
主控板我们跑电控代码的「大脑」底盘舱内
裁判系统主控官方裁判裁判数据汇集与无线回传底盘舱内
电源管理模块官方裁判分电、测功率、断动力电电池后第一站
电池官方指定全车唯一能量来源电池架
超级电容模组自购 + 官方监测动力电的功率缓冲底盘舱内
DR16 接收机官方通用接收 DT7 遥控器数据车身上

型号与参数随赛季更新，一律以当赛季官方手册为准

设备总览（下）：感知与显示

设备属于谁一句话作用大致位置
装甲模块官方裁判检测被弹丸击中云台/底盘四周
测速模块官方裁判测弹丸初速与射速枪管两侧
灯条官方裁判显示血量与状态车顶四周
图传（发送端）官方裁判传回第一视角画面云台上
RFID 场地交互官方裁判补弹、增益等场地交互车底
UWB 定位官方裁判测量机器人在场地中的位置车顶

设备名片（一）：两套「大脑」

主控板裁判系统主控（MC02）
是什么跑我们代码的板子，行为决策中心官方「随车裁判」核心，汇集裁判数据
装在哪底盘舱内底盘舱内，安装要求以官方手册为准
和电控怎么交互收遥控（DBUS）、串口连裁判主控、CAN 控电机、驱动灯条串口与主控对话，无线回传服务器
出问题会怎样整车失控或停摆，被判离线裁判判离线，触发掉电保护

类比：一个是「司机」，一个是「随车监考老师的对讲机」

设备名片（二）：供电路上的两个盒子

电源管理模块（PM02）电池（官方智能电池）
是什么官方「电闸 + 电表」全车唯一能量来源
装在哪电池之后的第一站电池架
和电控怎么交互分常电/动力电，测功率，可断动力电流向电源管理，再分给全车
出问题会怎样电机突然断电，或全车重启全车瘫痪；鼓包必须立即停用

类比：家里的配电箱——总闸接市电，下面分照明回路与空调回路

设备名片（三）：挨打与射速

装甲模块测速模块
是什么官方「痛觉神经」，检测弹丸击中官方「测速枪」，测初速与射速
装在哪云台/底盘四周的装甲板背面枪管两侧，弹丸路径两旁
和电控怎么交互上报裁判系统，扣血由服务器计算测量数据经裁判系统上报
出问题会怎样误触发掉血，或漏触发不掉血射速读 0，热量计算异常

两者与主控均无直接连线，数据先到裁判系统主控

设备名片（四）：显示与画面

灯条（LI01）图传（发送端）
是什么官方「血条显示器」，显示血量与状态第一视角摄像头（FPV），发回画面
装在哪车顶四周云台上
和电控怎么交互由我们的主控直接控制显示效果画面无线直传服务器，不经主控
出问题会怎样操作手看不到血量状态操作手「失明」，先查供电与天线

控制方式与安装要求以官方手册为准

设备名片（五）：场地交互与定位

RFID 场地交互（FI02）UWB 定位（UW01）
是什么与场地道具交互的「读卡器」车载定位，超宽带无线测距
装在哪车底，靠近地面车顶，位置要求以官方手册为准
和电控怎么交互补弹/增益经裁判系统上报位置经裁判系统上报服务器
出问题会怎样补不了弹，增益不生效小地图位置漂移或消失

两者与主控均无直接连线

设备名片（六）：缓冲与遥控

超级电容模组 + CM01DT7 遥控器 + DR16 接收机
是什么功率「缓冲罐」；CM01 为官方监测模块操作手的手柄 + 车上的接收机
装在哪并接在动力电回路上手上 / 车身上
和电控怎么交互超限时垫功率，状态上报裁判DR16 经 DBUS 把遥控数据给主控
出问题会怎样缓冲耗尽，超功率被断电处罚车收不到指令，先查对频

类比：超电是「信用卡」——先刷缓冲额度，刷爆就断卡

信息流：谁给谁发什么

链路传什么走什么路
DR16 → 主控遥控数据DBUS 有线
主控 ↔ 裁判系统主控协议数据（双向）串口
装甲 / 测速 → 裁判主控打击、射速模块连线
RFID / UWB → 裁判主控场地交互、位置模块连线
主控 → 灯条显示控制主控直连
主控 → 电调 → 电机控制指令CAN
裁判主控 → 服务器全部裁判数据无线
图传 → 服务器 / 客户端视频画面无线

协议字段与频率一律以当赛季官方《裁判系统串口协议附录》为准

读图练习：遮住上页回答

问题答案
摇杆到电机走哪条链？DT7 → DR16 → 主控 → CAN → 电调 → 电机
扣血这条链路有主控参与吗？没有：装甲 → 裁判主控 → 服务器
剩余血量数据从哪里来？服务器 → 裁判主控 → 串口 → 主控
主控死机，图传会黑屏吗？不会，图传链路完全不经过主控
信息流只有三个入口「喂」给主控：遥控器、裁判系统主控、自己的传感器

能量流：信息用电不能断，动力电可以限

  • 常电：主控、裁判系统、传感器，永远在线
  • 动力电：电调与电机，可被限功率、断电
  • 超电并接动力电：超出上限的部分由缓冲垫付
电池 → 电源管理 → 常电（不能断）+ 动力电（可限）｜超电并联动力电

类比：手术室停电，监护仪靠备用电源继续工作

裁判系统的「算账」：功率判定流程

1. 底盘功率 ≤ 上限 → 正常输出，缓冲回充
2. 功率 > 上限且缓冲 > 0 → 消耗缓冲垫付
3. 缓冲耗尽仍超限 → 动力电被切断
4. 惩罚结束 → 恢复供电（数值以规则为准）

该流程即「功率缓冲演示」的动画逻辑，可拖动滑块复现

控制关系：司机与考官

主控 = 司机

遥控、裁判、传感器数据全部汇聚，由它决定电机与灯条

裁判系统 = 考官

只看血条、伤害、功率；违规就限功率、断电

裁判系统是「裁判的眼睛」，不是执行器——只记录和判罚

掉电保护：考官不说话，司机踩刹车

  • 定义：裁判离线（通信超时）时，必须停止射击等危险输出
  • 超时判定：每个控制周期检查裁判数据是否超时
  • 分级保护：先停射击，再停底盘运动，保留显示
  • 自动恢复：数据恢复后逐步恢复输出
/* 思路示意：裁判数据超时 -> 停止危险输出（接口名以战队代码为准） */
int referee_online = 1;

void referee_watchdog(void)            /* 每个控制周期调用 */
{
    if (referee_data_timeout_ms > 1000) {  /* 阈值以官方手册为准 */
        referee_online = 0;
        shooter_set_speed(0);             /* 停止射击 */
        chassis_set_speed(0);             /* 停止底盘输出 */
    } else {
        referee_online = 1;
    }
}

规则要求，也是安全要求：裁判看不见的车，不许在场上开火

常见问题与排查

现象可能原因排查方法
灯条不亮或全红供电或与主控通信异常查常电与线材（以官方手册为准）
客户端看不到我的车裁判系统离线查裁判主控供电与天线
没被打却掉血装甲误触发查安装缓冲与灵敏度设置
频繁被判超功率缓冲耗尽或功率策略问题读功率数据，检查超电状态
