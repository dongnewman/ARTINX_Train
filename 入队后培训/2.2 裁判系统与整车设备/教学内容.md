# 2.2 裁判系统与整车设备

> 本节目录 / 建议课时：90 分钟（讲课 60 + 实操 30）｜前置要求：1.7 入队综合作业

一句话：认识一辆 RoboMaster 战车上所有的「官方设备」，看懂它们之间流动的两样东西——**信息**和**电**，并且知道裁判系统「管你但不听你」。

## 学习目标

- [ ] 说出整车 11 类主要设备各自「是什么、装在哪、怎么和电控交互、出问题会怎样」
- [ ] 画出一张整车信息流图：谁给谁发什么数据
- [ ] 画出一张整车能量流图：区分常电与动力电
- [ ] 说清主控与裁判系统各自的角色：执行者 vs 裁判的眼睛
- [ ] 解释「掉电保护」：为什么裁判系统离线时机器人必须停止射击
- [ ] 知道协议细节去哪查：当赛季官方《裁判系统串口协议附录》
- [ ] 能复述裁判系统「功率判定」流程：正常 → 用缓冲 → 缓冲耗尽 → 断电

## 核心概念

### 概念〇：先看全景——一辆战车的「三张地图」

入队前你让一个模块动起来（点灯、转电机、跑 PID），现在要把视角拉到**整车**。看一辆战车，可以画三张地图：

1. **设备地图**：车上有哪些盒子、装在哪（本节概念二、三）。
2. **信息地图**：盒子们之间流动的数据（概念四）。
3. **能量地图**：盒子们之间流动的电（概念五）。

三张地图叠加起来，就是电控组的「整车世界观」：

```
                         ┌─── 云台：图传 · 大装甲 · 测速模块 ───┐
                         │        （感知与显示，挂在云台上）      │
  ┌── 车顶：UWB 定位 · 灯条 ──────────────────────────────────────┐
  │                                                              │
  │   ┌────────────── 底盘舱内 ──────────────┐                    │
  │   │  主控板 · 裁判系统主控 · 电源管理      │  ← 信息与能量的    │
  │   │  超电模组 · DR16 接收机 · 电池        │     汇聚中心       │
  │   └──────────────────────────────────────┘                    │
  └── 车底：RFID 场地交互 ── 四周：小装甲 ──────────────────────────┘
```

从今天起，每次看到一辆车，先问自己：**它在哪、它吃什么电、它和谁说话**。三个问题都能答上来，才算「认识」了这个设备。

**一句话总结：整车认识 = 设备地图 + 信息地图 + 能量地图，三张图叠起来就是电控组的整车世界观。**

### 概念一：裁判系统不是我们的设备，是「随车裁判」

先建立一个最重要的认知：车上有两套「大脑」，一套是我们的，一套是官方的。

- **我们的主控板**：我们自己选型、自己写代码的板子（很多队伍用官方开发板 C 型或自研板；**战队用的是达妙 DM_MC02，主控芯片 STM32H723**）。它听我们的。
- **裁判系统**：比赛官方装上车的一套电子裁判，全自动地记录血量、伤害、功率，并把数据无线发回赛场服务器。它**不听我们的**，反过来它还会管我们。

打个比方：裁判系统就像考试时坐在你旁边的监考老师——你有自己的草稿纸（主控代码），但考试规则（血条、功率限制）由监考老师说了算。再打个比方：它像健身房的智能手环，你跑步时它盯着你的心率和步数，但你没法让它闭嘴。

裁判系统由两部分组成：

1. **机器人端**：装在车上的模块，包括裁判系统主控（MC02）、电源管理模块（PM02）、灯条（LI01）、装甲模块、测速模块、场地交互模块（FI02，即 RFID 模块）、图传模块（发送端）、定位模块（UW01，即 UWB 模块）、超级电容管理模块（CM01）。具体型号和参数**以官方手册为准**。
2. **赛事引擎（服务器 + 客户端）**：赛场上的服务器汇总所有机器人和场地道具的数据；客户端是操作手用的第一视角软件，能看到血量、射速、功率、小地图等。

**一句话总结：裁判系统是官方装在车上的「随车裁判 + 记分牌」，它负责「看」和「判」，不负责「开」你的车。**

### 概念二：整车设备总览——先看一张地图

一辆战车上林林总总的设备，按「属于谁」分三类，先记住这张总表：

| 设备 | 属于谁 | 一句话作用 | 大致位置 |
|---|---|---|---|
| 主控板 | 我们（自研/开发板） | 机器人的「大脑」，跑我们的代码 | 底盘舱内 |
| 裁判系统主控（MC02） | 官方裁判 | 裁判数据的汇集与无线回传 | 底盘舱内 |
| 电源管理模块（PM02） | 官方裁判 | 分电 + 测功率 + 断动力电 | 底盘舱内 |
| 装甲模块 | 官方裁判 | 检测被弹丸击中 | 云台/底盘四周 |
| 测速模块 | 官方裁判 | 测弹丸初速与射速 | 枪管两侧 |
| 灯条（LI01） | 官方裁判 | 显示血量与状态 | 车顶四周 |
| 场地交互模块（FI02/RFID） | 官方裁判 | 与场地道具交互（补弹、增益） | 车底 |
| 定位模块（UW01/UWB） | 官方裁判 | 测量机器人在场地中的位置 | 车顶 |
| 图传模块（发送端） | 官方裁判 | 传回第一视角画面 | 云台上 |
| 超级电容模组 + 电容管理模块（CM01） | 模组自购，CM01 官方 | 动力电的功率缓冲器 | 底盘舱内 |
| 电池（官方智能电池，如 TB47） | 官方指定 | 全车唯一的能量来源 | 电池架 |
| DT7 遥控器 + DR16 接收机 | 官方通用 | 操作手 → 主控的指令通道 | 手上 / 车上 |

> 注：表中位置是「大致」位置，各队布局不同；型号与参数每年可能更新，**一律以当赛季官方手册为准**。

**一句话总结：一辆车 = 官方裁判设备（负责「看」）+ 官方通用设备（电池、遥控）+ 我们的设备（主控、电机等执行器）。**

### 概念三：11 个设备的「四行名片」

下面给每个设备一张「四行名片」：**是什么 → 装在哪 → 和电控怎么交互 → 出问题会怎样**。不确定的接线与协议细节一律写「以官方手册为准」。

#### 1. 主控板

- **是什么**：跑我们自己代码的板子，机器人行为的决策中心。常见选型：官方开发板 C 型（STM32F407 主控芯片），或战队自研板；**战队实际用的是达妙 DM_MC02（主控芯片 STM32H723，480 MHz）**。
- **装在哪**：底盘舱内，靠近各设备的连线汇聚点。
- **和电控怎么交互**：接收 DR16 的遥控数据；与裁判系统主控通过串口交换数据；通过 CAN 控制电调电机；直接驱动灯条显示；读取各种传感器。接口定义与接线**以官方手册和战队电气文档为准**。
- **出问题会怎样**：整车「脑死亡」——电机失控或停转、不响应遥控、裁判系统判你离线。这是电控组要保住的第一个设备。
- **类比**：主控板是「司机」，其余设备要么是司机的眼睛和手（传感器、电机），要么是监考老师（裁判系统）。
- **电控注意**：主控板上的每个外设接口（串口、CAN、DBUS 等）都对应一个外部设备，接线前先画好「接口分配表」，这是 2.6 节整车电气的前置功课。

#### 2. 裁判系统主控（MC02）

- **是什么**：裁判系统机器人端的核心，汇总装甲、测速、RFID、UWB、电容管理各模块的数据，通过无线发给赛场服务器，并把服务器下发的信息（血量、功率上限等）提供给我们的主控。
- **装在哪**：底盘舱内，官方指定安装要求（位置、朝向可能受规则约束，**以官方手册为准**）。
- **和电控怎么交互**：与我们的主控通过串口通信，交互数据格式见当赛季官方《裁判系统串口协议附录》；它自带无线链路，与服务器通信我们碰不到。
- **出问题会怎样**：裁判系统判你「离线」——服务器看不到你的车，触发掉电保护（见概念六），严重时整台机器人会被罚下。
- **类比**：它是「随车监考老师」的对讲机——场上的实时数据靠它发回考场服务器，断了线，老师就看不见你。
- **电控注意**：与它的串口通信是电控代码里最重要的外部数据源之一，接收代码必须带「超时检测」（见概念六的伪代码）。

#### 3. 电源管理模块（PM02）

- **是什么**：裁判系统的「电闸 + 电表」。给各设备分配电源（区分常电与动力电）、实时测量底盘功率、血量归零时自动切断动力电输出。
- **装在哪**：底盘舱内，电池之后的第一站。
- **和电控怎么交互**：它本身不直接和我们的主控通信，但它检测到的功率、以及它控制的动力电通断状态，会经裁判系统主控间接影响我们（我们也可以从裁判系统数据里读到功率信息）。接线定义**以官方手册为准**。
- **出问题会怎样**：动力电输出异常——电机突然断电（血量归零、功率惩罚）、或供电不稳导致全车重启。
- **类比**：它像家里的配电箱——总闸接市电，下面分「照明回路」（常电）和「空调回路」（动力电），跳闸只跳空调，不跳灯。
- **电控注意**：动力电被切断时，电机命令会突然失效。代码要能区分「电机坏了」和「裁判断电了」，否则会误报故障。

#### 4. 装甲模块

- **是什么**：裁判系统的「痛觉神经」，用传感器检测弹丸击中造成的振动/压力，把「我被打了」上报给裁判系统主控。
- **装在哪**：车身四周的装甲板上（云台两侧大装甲、底盘四周小装甲），板子背面安装，正面朝向被击中的方向。
- **和电控怎么交互**：与我们的主控没有直接连线；打击事件经裁判系统主控上报服务器扣血。我们只能「挨打」，不能干预。
- **出问题会怎样**：误触发（没被打也掉血）或漏触发（被打不掉血）——安装缓冲、灵敏度等细节**以官方手册为准**。

#### 5. 测速模块

- **是什么**：裁判系统的「测速枪」，测量弹丸出膛的初速度与射击频率。
- **装在哪**：枪管两侧，弹丸飞行路径的两边。
- **和电控怎么交互**：与我们的主控无直接连线；测量数据经裁判系统主控上报服务器，用于计算热量、判定超射速/超射频犯规。
- **出问题会怎样**：测不到弹丸——服务器上你的射速永远是 0，或误测导致热量异常。安装位置要求**以官方手册为准**。

#### 6. 灯条（LI01）

- **是什么**：裁判系统的「血条显示器」，用 LED 显示当前血量与机器人状态（如扣血、复活、超功率等）。
- **装在哪**：车顶四周，让操作手和观众都能看到。
- **和电控怎么交互**：这是少数「听我们话」的裁判设备——灯条的颜色与显示效果**由我们的主控直接控制**，控制方式（接口与数据格式）**以官方手册为准**。
- **出问题会怎样**：灯条不亮或全红——操作手看不到血条，也可能是灯条供电或与主控的通信出了问题。

#### 7. 图传模块（发送端）

- **是什么**：装在车上的摄像头 + 无线视频发射器，提供操作手的第一视角画面（FPV）。
- **装在哪**：云台上（往往是云台摄像头的位置），接收端在赛场/操作间。
- **和电控怎么交互**：与我们的主控无直接数据交互；画面经无线链路到接收端再进服务器/客户端。我们能做的是给它提供稳定的供电和安装。
- **出问题会怎样**：操作手「瞎了」——看不到第一视角就没法瞄准。黑屏先查供电与天线（**以官方手册为准**）。

#### 8. 场地交互模块（FI02，RFID）

- **是什么**：裁判系统与场地道具之间的「读卡器」，用于补弹、增益区等场地交互。
- **装在哪**：车底，靠近地面一侧。
- **和电控怎么交互**：与我们的主控无直接连线；交互数据经裁判系统主控上报服务器，服务器判定补弹/增益是否生效。我们只能在策略上决定「什么时候去踩那个点」。
- **出问题会怎样**：补不了弹、增益不生效——车没法持续作战。安装与参数**以官方手册为准**。

#### 9. 定位模块（UW01，UWB）

- **是什么**：裁判系统的「车载 GPS」，通过超宽带无线测距，测量机器人在场地中的实时位置。
- **装在哪**：车顶，位置与朝向可能受规则约束（**以官方手册为准**）。
- **和电控怎么交互**：与我们的主控无直接连线；位置数据经裁判系统主控上报服务器，用于小地图、自动判罚等。我们能从裁判系统数据中间接读到位置信息。
- **出问题会怎样**：服务器上你的车位置漂移或消失，影响战术与判罚。

#### 10. 超级电容模组 + 电容管理模块（CM01）

- **是什么**：超级电容是一个能快速充放电的「功率缓冲罐」——底盘瞬间大功率输出时，超出功率上限的部分由超电先垫着。CM01 是裁判系统的电容管理模块，监测超电的电压与容量状态并上报。
- **装在哪**：底盘舱内，并联在动力电回路上。
- **和电控怎么交互**：超电模组本身是能量设备；CM01 与我们的主控无直接连线，它把超电状态经裁判系统主控上报。功率策略（什么时候用缓冲能量）由我们的主控决定。
- **出问题会怎样**：缓冲能量用尽——底盘超功率立即被判罚（断电处罚），所以电控必须时刻关注剩余缓冲能量。
- **类比**：超电是「信用卡」——底盘瞬时大功率像冲动消费，先刷缓冲额度顶上，额度刷爆就「断卡」；平时功率小，额度慢慢「还款」回充。
- **电控注意**：功率规划是电控的核心策略之一（3.3 节专题）：什么时候可以「刷爆」、什么时候必须收着跑，都由主控读裁判功率数据来决定。

#### 11. 电池（官方智能电池，如 TB47）

- **是什么**：全车唯一的能量来源，官方指定的智能电池，自带电量管理。
- **装在哪**：车上的电池架里，上电第一步。
- **和电控怎么交互**：电池 → 电源管理模块 → 各设备，它本身不与主控通信；我们通过电压监测了解电量。充电、使用规范**以官方手册为准**。
- **出问题会怎样**：全车瘫痪——所有能量流断掉。鼓包、电压异常必须立即停止使用。

#### 12. DT7 遥控器 + DR16 接收机

- **是什么**：操作手的「手柄」。DT7 是遥控器（操作手拿在手上），DR16 是装在车上的接收机，两者对频后无线连接。
- **装在哪**：DR16 装在车身上（天线注意安装要求，**以官方手册为准**）。
- **和电控怎么交互**：DR16 通过 DBUS 接口把遥控数据（拨杆、拨轮、按键）发给我们的主控——这是电控代码里最早接触的输入之一（1.4 节我们已经让主控「听」指令）。
- **出问题会怎样**：操作手「手没了」——车收不到指令。先查对频、接收机供电和 DBUS 接线。

**一句话总结：每张名片问四个问题——它是什么、它在哪、它怎么和我们说话、它坏了会怎样。以后在车上见到任何新设备，都用这四问拆一遍。**

### 概念四：信息流——谁给谁发什么

把上面所有设备的「说话关系」画成一张图。箭头方向 = 数据流向：

```
                        ┌──────────── 赛场服务器 ────────────┐
                        │  ▲无线                  ▲无线       │
                        │  │                      │           │
  DT7遥控器──无线──▶ DR16接收机 ──DBUS──▶ 我们的主控 ◀─串口─▶ 裁判系统主控(MC02)
  (操作手手里)        (车上)        (遥控数据)    │  (协议数据)   ▲
                                        │        │              │
                                        ▼        │              │
                                       灯条(LI01)│       装甲/测速/RFID/UWB/CM01
                                        │        │        (打击/射速/交互/位置/超电)
                                        ▼        │
                              CAN──▶ 电调──▶ 电机（1.4 学过）
                                        │
                                        └──▶ 其他执行器/传感器
                       图传发送端(云台) ──无线──▶ 图传接收端 ──▶ 服务器/客户端
```

读这张图的关键结论：

1. **所有和操作相关的数据都汇聚到我们的主控**：遥控输入、裁判数据、电机反馈。
2. **裁判系统的传感器不和我们直接说话**：装甲、测速、RFID、UWB、CM01 的数据都先到裁判系统主控，我们只能从裁判系统主控的串口数据里「间接」读到其中一部分。
3. **图传是另一条独立链路**：画面不经过我们的主控，我们只管给它供电。
4. **与裁判系统主控的串口通信是「主控 ↔ 裁判系统」的唯一对话通道**，数据格式与含义**以当赛季官方《裁判系统串口协议附录》为准**，本节不做协议细节展开（3.1 长期学习再深入）。

**一句话总结：信息流只有三个入口会「喂」给我们的主控——遥控器、裁判系统主控、自己的传感器，其余信息要么我们拿不到，要么是间接拿到。**

#### 读图练习：遮住上图，回答四个问题

1. 操作手拨动摇杆，数据经过哪几个设备，最后到电机？——DT7 → DR16 → 主控 → CAN → 电调 → 电机。
2. 装甲被打中一下，扣血这条链路上有我们的主控吗？——没有。装甲 → 裁判系统主控 → 服务器。
3. 我们想读「当前剩余血量」，数据从哪里来？——服务器 → 裁判系统主控 → 串口 → 我们的主控。
4. 图传画面会不会因为主控死机而黑屏？——不会，图传链路完全不经过主控；反过来，主控死机图传正常，说明「画面在但车不动」。

答对 4 题，说明信息流这张图真正看懂了。

### 概念五：能量流——信息用电不能断，动力电可以限

再看电的流动。能量流的源头只有一个：电池。

```
                     ┌─常电(信息用电,不能断)─▶ 主控板 / 裁判系统(MC02等) / 灯条 / 传感器
电池(TB47) ──▶ 电源管理模块(PM02) ──┤
                     └─动力电(可限可断)──▶ 电调 ──▶ 电机(底盘/云台/发射机构)
                                    ▲
                          超级电容模组(并联在动力电上,功率缓冲)
```

这张图里有三个必须记住的设计原则：

1. **信息用电不能断**：主控、裁判系统、传感器吃的是「常电」，无论血量归零还是功率惩罚，它们都要保持在线——否则服务器看不到你的车，直接判离线。类比：手术室停电时，监护仪和无影灯必须靠备用电源继续工作。
2. **动力电可以限**：电机吃的「动力电」由电源管理模块控制，裁判系统可以限功率、可以断电（血量归零、超功率惩罚），这不会影响信息系统。
3. **超级电容是动力电的「缓冲垫」**：底盘瞬间需要大功率时，超出裁判功率上限的部分由超电垫上；缓冲能量是裁判系统记账的（有额度），用完就要挨罚。

**一句话总结：常电保命（信息在线）、动力电出力（可被裁判限流）、超电缓冲（垫一下超出的功率）。**

#### 功率判定：裁判系统怎么「算账」

底盘功率是裁判系统的核心考核项，判定流程大致是（**具体数值与规则以当赛季官方手册为准**）：

```
底盘功率 ──▶ 是否超上限？ ──否──▶ 正常，缓冲能量缓慢回充
                │
               是
                ▼
         缓冲能量 > 0？ ──是──▶ 消耗缓冲能量垫付，输出继续
                │
               否
                ▼
         动力电被切断（示例：数秒）──▶ 惩罚结束，恢复供电
```

这张流程图就是第 9 页演示文档里那个「功率缓冲演示」的动画逻辑，拖动滑块就能看到全过程：正常 → 用缓冲 → 缓冲耗尽 → 断电。

### 概念六：控制关系与「掉电保护」

最后把「谁说了算」讲清楚：

- **我们的主控是所有指令的汇聚点**：遥控指令、裁判数据、传感器数据都到它这里，由它决定电机怎么转、灯条怎么亮。执行器只听它的。
- **裁判系统是「裁判的眼睛」，不是执行器**：它看得见血条、伤害、功率、位置，但它不会替你踩油门。它用「规则后果」来约束你——扣血、限功率、断动力电、罚下。
- **掉电保护**：裁判系统离线（服务器收不到你的车，或主控与裁判系统通信超时）时，机器人**必须**停止射击、停止输出等危险动作。这一条同时是**规则要求**和**安全要求**——想象一辆「瞎了眼的裁判旁边」的车还在满场开火，既危险又违规。在代码层面，这就是 2.9 节要学的「通信丢失检测 + 安全状态」，最朴素的实现是：裁判数据超时 → 停止射击输出。

```
正常状态：裁判数据正常 ──▶ 正常输出
超时状态：裁判数据超时 ──▶ 停止射击/停止底盘输出 ──▶ 等数据恢复
```

**一句话总结：主控是「司机」，裁判系统是「考官」；考官不说话（离线）时，司机必须立刻踩刹车——这就是掉电保护。**

#### 掉电保护的三个实现要点

1. **超时判定**：每个控制周期检查「距上次收到裁判系统数据的时长」，超过阈值（阈值**以官方手册/战队代码为准**）判定为离线。
2. **分级保护**：先停最危险的输出（射击/摩擦轮），再停底盘运动，保持灯条等显示设备可工作，方便操作手判断状态。
3. **自动恢复**：数据恢复后按安全流程逐步恢复输出，而不是瞬间满功率复活（恢复策略详见 2.9 节可靠性）。

### 概念七：数据格式与协议——只做认识性介绍

「协议」这个词以后会天天遇到，本节只建立感性认识：**协议 = 通信双方的「信封格式」约定**。

- 就像寄快递要在信封上写地址、贴邮票，裁判系统主控发给我们的每一段数据也有固定格式：开头是「帧头」（识别这是一帧数据的开始），接着是「命令码」（说明这帧数据是干什么的），然后是「数据内容」，最后是「校验」（检查路上有没有损坏）。
- 双方约定好格式和对话节奏（多久发一次），通信才成立。如果格式对不上——比如赛季更新了协议版本而代码没更新——就会解析出一堆乱码。
- **本节不展开任何具体字段**：交互数据的字段名、长度、频率、数值含义，**一律以当赛季官方《裁判系统串口协议附录》为准**。拿到手的第一步是读目录，不是背字段（见任务三）。

**一句话总结：协议是通信双方的「信封格式」约定，细节以当赛季官方协议手册为准，先读目录建立框架再查字段。**

## 课后自测

1. 主控与裁判系统主控，谁是「执行者」、谁是「裁判」？它们之间通过什么对话？
2. 血量归零时电机全部断电，为什么裁判系统还能继续上报数据？（提示：常电/动力电）
3. 「掉电保护」为什么既是规则要求又是安全要求？至少列出两条理由。
4. 超级电容并联在哪个回路上？「缓冲能量耗尽」之后会发生什么？
5. 装甲模块检测到被击中后，扣血这件事是谁算的？我们的主控能不能阻止扣血？
6. 说出 3 个「和我们的主控没有任何直接连线」的裁判设备。

<details>
<summary>参考答案</summary>

1. 我们的主控是执行者（所有指令的汇聚点），裁判系统是「裁判的眼睛」（记录血条、伤害、功率，不是执行器）。两者通过串口对话，数据格式**以当赛季官方《裁判系统串口协议附录》为准**。
2. 因为供电分两路：电机吃「动力电」（血量归零被电源管理模块切断），而主控、裁判系统吃「常电」始终在线——信息用电不能断，动力电可以限。
3. 规则上：裁判系统离线时继续射击属于违规（服务器无法记录你的行为）；安全上：裁判看不到的车在场上继续输出是危险行为；工程上：通信超时不做处理，程序可能继续执行错误指令。所以离线必须停止射击等输出。
4. 超级电容并联在**动力电**回路上，作为功率缓冲。缓冲能量耗尽后，底盘功率超出上限部分不再有缓冲，会被裁判系统按超功率处理（限功率/断电处罚）。
5. 扣血由**裁判系统（服务器）**计算：装甲上报打击事件 → 裁判系统主控 → 服务器扣血。我们的主控无法阻止扣血。
6. 装甲、测速、场地交互（RFID）、定位（UWB）、电容管理（CM01）、图传发送端等——它们的数据都先到裁判系统主控。

</details>
