核心概念：四步链路

① 规则

读官方文件

手册 + 规范 + 协议 → 约束清单

② 需求

翻译成指标

约束 + 兵种任务 → 需求清单

③ 设计

搭系统方案

需求清单 → 模块 / 接口 / 策略

④ 实现

编码与调试

系统方案 → 可运行功能

链条有方向：需求错了，设计与代码全白做。

每步做什么：输入 / 输出 / 电控职责

步骤输入输出电控组职责
① 规则规则手册 / 制作规范 / 裁判系统协议读懂的规则约束通读手册，圈出与电控相关条款
② 需求规则约束 + 兵种任务可验证的需求清单条文 → 「系统必须做到什么」
③ 系统设计需求清单模块划分 / 接口 / 控制策略划分模块、定接口、画框图
④ 功能实现系统方案可运行、可验收的功能编码、调试、逐条对照验收
一句话总结：规则决定边界，需求决定方向，实现决定结果。

为什么先读规则

类比一句：装修不看物业规定就动工，轻则返工，重则拆墙罚款。
发现需求错误的阶段修改代价
读规则阶段（还没动工）改一行字，几小时
系统设计阶段重画方案，几天
装车调试之后重写代码，数周，还连累机械返工
每一条规则都可能决定车能否上场、是否被判罚。

读规则方法一：关键词检索

  1. 官网下载当赛季 PDF → 先看目录，定位电控相关章节
  2. 用 PDF 搜索框检索关键词 → 通读命中段落，而非硬啃全本

高频关键词：

功率 裁判系统 传感器 限制 禁止 判罚 检录

读规则方法二：边读边写需求清单

# 固定格式：来源 → 一句话需求 → 初判设计方向
[规则手册·功率] -> 底盘功率全程不超过限制值 -> 功率监控 + 缓冲 + 限幅
[制作规范·传感器] -> 按允许清单选型 -> 器件选型核对表

划线会忘，清单才是后续开发的直接输入；格式固定便于归档与评审。

读规则方法三：赛季对比表

对比维度要回答的问题
功率 / 热量限制数值变了吗？缓冲规则变了吗？
兵种功能新增 / 删除了什么功能要求？
传感器限制哪些传感器新增允许 / 被禁止？
裁判系统交互新增了什么数据交互要求？

官方文件附版本号与更新说明，以当赛季最新版本为准；变化处 = 旧方案要改处。

需求拆解示范一：底盘功率限制

规则条文（示意）提炼需求电控设计方向
底盘限制功率 80 W（历史赛季常见值，以当赛季手册为准）任意工况功率 ≤ 限制值；瞬时与平均都要达标功率监控 + 缓冲策略 + 超限保护
  • 「任意工况」= 叠加工况：全功率加速、爬坡、边射击边移动最危险
  • 需求写成可验证形式：四轮全功率加速 3 秒，功率峰值不超过限制值
  • 设计顺序：先监控（知道实时功率）→ 再缓冲（削平尖峰）→ 最后保护（限幅）

交互演示：底盘功率需求拆解表

需求拆解示范二：射击时云台稳定

规则条文（示意）提炼需求电控设计方向
射击产生后坐力，命中精度影响得分（方向示意，以当赛季手册为准）射击瞬间云台 Pitch 不低头；连发不抖、指向稳定Pitch 抗后坐力前馈 + 串级控制 + 摩擦轮转速闭环
  • 后坐力是发射瞬间的扰动，纯 PID 靠误差反应会慢半拍
  • 前馈：知道要开火，提前给一个补偿量
  • 单环位置控制抗扰能力弱，云台常用串级（位置环 + 速度环），2.5 节详讲

什么样的需求才合格

不合格（愿望清单）合格（可验证需求）
跑得飞快写出目标速度与加速时间，可实测对比
云台要稳连发射击 N 发，Pitch 角度跌落 ≤ 设定阈值，可录数据验证
功率别超全功率加速 3 秒，功率峰值 ≤ 限制值，看功率曲线验收
三要素：要什么（指标）、什么时候要（工况）、怎么验证（可测试）。

资源一：官方资料站

  • 官网按赛季发布规范文件列表，附版本号与更新日期
  • 规则手册 / 制作规范 / 参赛手册 / 裁判系统协议均在此下载
  • 官方规则答疑与文件同等效力，理解分歧以答疑为准
  • 原则：一切以官网最新版本为准，二手转载只作参考

资源二：RM Search 全文搜索

  • RM 专属全文搜索引擎（华南理工华南虎团队开发，已开源）
  • 搜：论坛文章 / 问答 / 专栏、官网公告与 PDF 内文本
  • 用：查「规则怎么理解」「硬件怎么选」类问题，比通用搜索精准
  • 入口：官方论坛搜索顶部已接入，可直接跳转

入口地址见「延伸资源」页。

资源三：开源仓库的阅读顺序

  1. README：仓库解决什么问题、目录结构说明
  2. 文档目录（如 doc/）：设计文档、控制方案、器件清单
  3. 架构图：模块分层与数据流
  4. 带需求定位关键代码：如功率控制 → 功率控制模块
反例：从第一行 main.c 开始通读 = 低效十倍的无效努力。
