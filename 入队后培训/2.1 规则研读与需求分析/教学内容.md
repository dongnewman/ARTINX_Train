# 2.1 规则研读与需求分析

> 本节目录 / 建议课时：90 分钟（讲课 60 + 实操 30）｜前置要求：入队前培训（1.1~1.6）

欢迎入队！从今天起，你不再只是「让一个电机转起来」，而是要和队友一起「让一辆完整机器人上场比赛」。

这一节是入队后培训的第一课。我们不讲代码，先讲一件更划算的事：**读规则**。

---

## 学习目标

- [ ] 能说清「规则 → 需求 → 系统设计 → 功能实现」四步链路，以及电控组在每一步做什么
- [ ] 知道规则手册、制作规范、裁判系统协议分别是什么、在哪里下载
- [ ] 能把一条规则条文拆解成可执行的「电控需求」和「设计方向」
- [ ] 掌握读规则的方法：关键词检索、需求清单、赛季对比表
- [ ] 会使用官方资料站、RM Search、优秀战队开源仓库三种资源
- [ ] 独立产出一份「需求清单」（≥10 条），作为后续所有开发的输入

---

## 核心概念

### 概念一：规则 → 需求 → 系统设计 → 功能实现（四步链路）

**生活类比**：假设你要装修一套房子。物业规定（规则）说「阳台不许封窗、承重墙不能敲、晚上 8 点后不许施工」。如果你不看规定直接开工，轻则返工，重则罚款拆墙。

做比赛机器人完全一样。RoboMaster 有厚厚的一摞规则，每一条都可能直接决定你的车能不能上场、上场会不会被判罚。所以我们的开发流程固定是四步：

```
  规则 ────▶ 需求 ────▶ 系统设计 ────▶ 功能实现
  (读什么)    (要什么)     (怎么搭)        (做出来)
```

**一句话总结：规则决定「什么不能做、必须做到什么」，需求把这些翻译成电控的开发任务清单。**

每一步的输入、输出，以及电控组在其中的工作：

| 步骤 | 输入 | 输出 | 电控组在这步做什么 |
|---|---|---|---|
| ① 规则 | 比赛规则手册、机器人制作规范手册、裁判系统协议（官方文件） | 读懂的规则约束：功率上限、机构限制、交互要求、判罚条件 | 通读手册，圈出所有与电控相关的条款，整理成约束清单 |
| ② 需求 | 规则约束 + 本兵种任务（如步兵要打输出、工程要取矿） | 可验证的需求清单（「系统必须做到什么」，能测试、能验收） | 把规则条文翻译成技术指标，例如「底盘功率全程 ≤ 限制值」 |
| ③ 系统设计 | 需求清单 | 设计方案：硬件选型、通信方式、软件分层、控制策略 | 划分模块、定接口、定数据流，画出系统框图 |
| ④ 功能实现 | 设计方案 | 可运行、可验证的机器人功能 | 写代码、调试、逐条对照需求清单验收 |

**注意一个残酷的事实**：链条是有方向的。第 ② 步需求错了，第 ③④ 步做得再好也是白做；第 ① 步规则没读对，后面全错。这也是为什么这一节值得你先花一整个晚上。

### 概念二：规则手册结构导读

RoboMaster 官方会发布若干份文件（各赛季名称和结构可能略有调整，**以当赛季官方发布为准**）：

| 文件 | 大致内容 | 电控关注度 |
|---|---|---|
| 比赛规则手册 | 总则、各兵种规则、比赛流程、判罚条款 | ★★★ 必读 |
| 机器人制作规范手册 | 各兵种允许的机构、传感器、执行器、重量尺寸限制 | ★★★ 必读 |
| 参赛手册 / 增补说明 | 赛程、场地、签到检录要求 | ★★ 浏览 |
| 裁判系统相关文件（协议附录等） | 裁判系统各模块功能、数据交互协议 | ★★★ 必读 |

拿到规则手册后，**电控组不必逐字背全本**，但以下内容必须精读（具体章节位置以当赛季手册目录为准）：

- **功率与能量限制**：底盘功率、发射机构热量、缓冲能量等限制，以及超限的判罚方式——这直接决定你的控制策略。
- **裁判系统交互**：主控需要和哪些裁判系统模块通信、需要回传什么数据、指示灯和 UI 的要求。
- **传感器与执行器限制**：什么传感器允许用、什么禁止；电机/电调的类型限制；气压、射频等特殊限制。
- **兵种功能与判罚条款**：本兵种在场上必须做什么（如步兵射击、工程取矿）、哪些行为会被判罚。
- **检录规则**：车检时查什么——很多限制不是写在「电控」章，而是写在检录和判罚里。

**一句话总结：电控必读四件事——功率限制、裁判系统交互、传感器限制、判罚条款；不确定的内容一律以当赛季手册为准。**

### 概念三：需求拆解示范（把规则条文翻译成电控任务）

**生活类比**：规则是「合同」，需求清单是「施工任务书」。合同说「外墙必须防水」，施工任务书就要写成「所有窗框缝隙打胶，淋水测试 30 分钟不渗漏」——具体、可执行、可验收。

下面拆解两个真实例子：

**例 1：底盘功率限制**

| 规则条文（示意） | 提炼需求 | 电控设计方向 |
|---|---|---|
| 底盘限制功率 80 W（历史赛季常见数值，**以当赛季手册为准**） | ① 底盘功率在任意工况下不超过限制值；② 瞬时功率和平均功率都要管 | ① 功率监控：实时获取功率数据并记录；② 缓冲策略：超级电容补能、限制加速斜率、错峰用电；③ 超限保护：输出限幅，宁可慢一点也不超限 |

细节推演：

- 「任意工况」意味着不能只在匀速时达标——全功率加速、原地旋转、爬坡、边射击边移动这些叠加工况才是最危险的。
- 所以需求要写成可验证的形式，例如：「四轮全功率加速 3 秒，功率曲线峰值不超过限制值」。
- 对应的设计方向就有了：先有**监控**（知道实时功率），再有**缓冲**（把瞬时尖峰削平），最后有**保护**（万一还是超了，主动限幅保护）。

**例 2：射击时云台稳定**

| 规则条文（示意） | 提炼需求 | 电控设计方向 |
|---|---|---|
| 发射机构射击产生后坐力；命中精度影响得分（规则方向示意，**具体以当赛季手册为准**） | ① 射击瞬间云台 Pitch 不因后坐力明显低头；② 连发时云台不抖、指向稳定 | ① Pitch 抗后坐力：基于发射时刻的前馈补偿；② 串级控制：位置环 + 速度环提升抗扰能力；③ 摩擦轮转速闭环，保证弹速稳定 |

细节推演：

- 后坐力是「扰动」，只在射击瞬间出现。纯 PID 靠误差反应会「慢半拍」，所以引入**前馈**：知道要开火了，提前给一个补偿量。
- 单环位置控制抗扰能力弱，所以云台普遍用**串级控制**（外环位置、内环速度），这部分会在 2.5 节详细学。

**一句话总结：拆解需求就是回答三个问题——要什么（指标）、什么时候要（工况）、怎么验证（可测试）。**

### 概念四：怎么读规则（三个方法）

**方法 1：关键词检索**。拿到 PDF 后不要从头硬啃，先搜索关键词：「功率」「裁判系统」「传感器」「限制」「禁止」「判罚」，把命中段落通读一遍。电子版 PDF 的搜索框就是你最好的导航。

**方法 2：边读边写需求清单**。读到一条可能影响电控的规则，立刻在清单里记一行，格式固定：

```
[规则来源：手册名+章节] → [一句话需求] → [初判设计方向]
```

不要只划线不记录——划线会忘，清单会变成后面的开发输入。

**方法 3：赛季对比表**。把「本赛季 vs 上赛季」的变化列成表格。规则变化是每年最重要的信息：老代码、老方案里凡是与新规则冲突的部分都要改。官方发布文件时会附版本号和更新说明，**以当赛季最新版本为准**。

| 对比维度 | 示例问题 |
|---|---|
| 功率/热量限制 | 数值变了吗？缓冲规则变了吗？ |
| 兵种功能 | 新增/删除了什么功能要求？ |
| 传感器限制 | 哪些传感器新增允许/被禁止？ |
| 裁判系统交互 | 新增了什么数据交互要求？ |

**一句话总结：读规则 = 检索关键词 + 随手写需求清单 + 对比赛季变化。**

### 概念五：资源怎么用

**1. 官方资料站（RoboMaster 官网）**。规则手册、制作规范、裁判系统协议等一切官方文件的源头。官网会按赛季发布文件列表和版本号，**一切以官网最新版本为准**，其他网站转载的旧文件只作参考。

**2. RM Search（RM 专属搜索引擎）**。一个专为 RoboMaster 打造的全文搜索引擎，可以一键搜索官方论坛的文章、问答、专栏，以及官网公告和 PDF 内的文本。查「XX 规则怎么理解」「某硬件怎么选」这类问题时，用它比用通用搜索引擎精准得多。官方论坛也接入了 RM Search，在论坛搜索时可以直接跳转过去。

**3. 优秀战队开源仓库**。很多强队会开源自己的代码和文档，这是最宝贵的免费教材。但**不要一上来就啃代码**，正确打开顺序：

1. 先读 **README**：这个仓库是什么、解决什么问题、目录结构说明；
2. 再看 **文档目录**（如 `doc/`）：设计文档、控制方案、器件清单；
3. 再看**架构图**（README 或文档里通常有）：理解模块分层和数据流；
4. 最后**带着需求定位关键代码**：例如想看功率控制，就去找功率控制模块，而不是从第一行 `main.c` 开始读。

带着问题读代码，比通读整个仓库高效十倍。

**4. 战队历史资料**。往届的车、往届的代码、往届的比赛复盘都沉淀在战队内部（讲解时结合战队现有资料展示）。看历史资料时重点看三样：**当年遇到的问题和解决方案、历届车的技术选型变化、赛场上吃过的亏**。规则在变，但「哪里容易翻车」的教训不过时。

**一句话总结：官方文件定规则，RM Search 查问题，开源仓库学方案，历史资料避坑。**

## 动手实践

### 任务一：30 分钟速读规则，产出第一版需求清单（20 分钟）

1. 打开当赛季《比赛规则手册》和《机器人制作规范手册》的 PDF（下载地址见「延伸资源」，**以当赛季最新版本为准**）。
2. 用关键词检索法通读：功率、裁判系统、传感器、限制、禁止、判罚。
3. 按固定格式记录需求，**至少 10 条**，例如：
   ```
   [规则手册·功率章] → 底盘功率全程≤限制值 → 功率监控+缓冲+限幅
   ```
4. 自查点 ✔：每条需求都写清了「要什么」；每条都能想到一种验证方法（怎么测它达标了）。

### 任务二：用 RM Search 查一个具体问题（10 分钟）

1. 打开 RM Search，搜索一个你真想知道答案的问题，例如「超级电容 功率缓冲」「云台 后坐力 前馈」。
2. 浏览结果，挑 1 篇有价值的帖子/文档读完。
3. 自查点 ✔：能说出这个问题的 2 种常见解法；把来源链接记进你的需求清单备注。

### 任务三：给一个开源仓库写三行「导读」（10 分钟）

1. 打开深大 RobotPilots 麦轮步兵电控开源仓库（链接见「延伸资源」）。
2. 按「README → 文档目录 → 架构图 → 定位关键代码」的顺序浏览，**不写代码**。
3. 写三行导读：
   - 这个仓库是什么兵种、哪一年、用什么方案；
   - 它的代码大致分哪几层/几个模块；
   - 如果我想学它的功率控制，应该先看哪个文件。
4. 自查点 ✔：三行里没有一行是「我不懂」，说明你真的读了。

## 常见问题与排查

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 读规则读不进去，读完就忘 | 通篇硬读，没有目标 | 改成关键词检索 + 边读边写需求清单 |
| 需求清单写成了「愿望清单」（如「跑得飞快」） | 没有量化、不可验证 | 每条需求补上数值或可测试描述，写不出就查规则和旧方案 |
| 两个队友对同一条规则理解不一致 | 看的文件版本不同 / 没看答疑 | 统一到官网最新版本；官方规则答疑和论坛有解释 |
| 开源仓库完全看不懂 | 一上来就啃代码 | 退回 README 和文档目录，先看架构图再定位代码 |
| 不确定规则细节该信哪个来源 | 看了二手转载 | 一律以当赛季官方文件为准，二手资料只作参考 |

## 课后自测

1. 说出四步链路每一步的输入和输出，并举例说明电控组在「系统设计」这一步做什么。
2. 「底盘功率限制 80 W」这条规则，你会在需求清单里写成哪几条可验证需求？
3. 为什么「射击时云台稳定」这个需求，只用单环 PID 往往不够？
4. 拿到一份新赛季规则手册，你的阅读顺序是什么？为什么先做赛季对比表？
5. 打开一个陌生的开源仓库，你的浏览顺序是什么？为什么不能一上来啃代码？
6. 解释这句话：需求分析错了，后面全白做。

1. 见「概念一」表格。系统设计这步：输入需求清单，输出设计方案；电控组负责划分软件模块、定义模块间接口、确定通信方式和控制策略。
2. 例如：① 任意工况（含全功率加速、爬坡、边射击边移动）下底盘功率不超过限制值；② 超级电容缓冲后瞬时功率尖峰被削平；③ 超限时主动限幅，不发生持续性超功率。验证方式：实车测功率曲线、裁判系统功率数据回放。
3. 后坐力是发射瞬间的扰动，纯 PID 靠误差事后反应会慢半拍，需要发射时刻的前馈补偿；单环位置控制抗扰能力弱，常用串级（位置环+速度环）提升刚度。
4. 先查目录定位电控必读章节，再用关键词检索通读（功率、裁判系统、传感器、限制、禁止、判罚），边读边写需求清单；赛季对比表能快速暴露「旧方案哪里要改」。

6. 四步链路有方向性：需求是系统设计和功能实现的唯一输入，需求错了，后面设计与代码做得再好，验收时也不符合规则或比赛要求，只能推倒重来。
