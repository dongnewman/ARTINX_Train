定义：能运行 vs 能稳定运行

能运行能稳定运行
前提一切正常任何环节都可能出问题
表现它能动继续工作，或安全停下
失控可能发生绝不失控
赛场上的问题都不是假设：电机掉线、通信超时、堵转、低电压，全部真实发生过。可靠性 = 检测 + 保护 + 恢复。
一句话总结：能运行 = 一切正常时它能动；能稳定运行 = 任何环节出问题时，要么继续工作、要么安全停下。

Timeout：等不到反馈，就降级

定义：超时（Timeout）——等待反馈超过约定时限仍未到达，即按最坏情况处理（降级或停机）。

等待对象超时阈值超时动作
遥控器新数据100 ms急停，所有目标置 0
电机 CAN 反馈200 ms该电机断电并报障
裁判系统数据1 s停止射击，保留运动
上位机（视觉）指令500 ms自动瞄准降级为手动
两条纪律：喂狗（每收到有效数据刷新时间戳）；超时后置 0，绝不保持旧指令继续冲。类比：发消息不回，不干等，按最坏打算行动。

Timeout 代码骨架

遥控器数据超时

/* 收到一帧数据 → 喂狗 */
last_rc_tick = now_tick;

/* 控制周期检查：无符号减法防回绕 */
if ((uint32_t)(now_tick - last_rc_tick) > 100u)
    target_speed = 0;  /* 急停 */

send_current(target_speed);

电机反馈超时（4 电机）

/* CAN 回调喂狗 */
last_fb_tick[id] = now_tick;

/* 控制周期逐电机检查 */
for (uint8_t i = 0; i < 4; i++)
    if ((uint32_t)(now_tick - last_fb_tick[i]) > 200u)
        send_current_to(i, 0); /* 断电 */

(uint32_t)(now − last) 在时间戳回绕时依然正确，优于 now > last + TH。

演示：遥控器超时保护（看门狗计时）

25Hz 数据帧 · 100ms 阈值 · 超时急停，恢复后输出缓升

输出限幅（Output Limit）

定义：发送给执行器的控制量，在发送前钳位（Clamp）到硬件允许范围。

为什么必须限幅

  • 溢出反转：int32 算出 100000，存入 int16 被截断成负数，电机瞬间反转
  • 电流上限就是电机与电调的保险丝
  • 积分项也要单独限幅，防积分饱和

纪律

  • 限幅放在最后一道关卡：CAN 发送函数内部
  • 限幅值取硬件允许范围，勿拍脑袋
  • 升降双向都要限幅
一句话总结：输出出门前先压范围——不设限的代码等于把车钥匙交给一个疯子。

输入验真（Input Check）

定义：传感器读数进入控制逻辑前，验证其物理合理性；离谱数据一律不信。类比：眼睛报假消息比眼睛瞎了更危险。

检查层判据示例
范围检查超出物理极限转速 99999 / 电压 0
跳变检查两次读数差太多角度 1ms 跳 180°
连续检查连续 N 次全异常判定传感器故障
处理策略：异常读数丢弃、用上次可信值顶上；连续异常则断电降级。范围边界要符合物理事实（车最快 ±8000 RPM，±10000 以上即可判假）。

限幅与验真代码

输出限幅

int16_t clamp_i16(int32_t v, int16_t lo, int16_t hi)
{
    if (v > hi) return hi;
    if (v < lo) return lo;
    return (int16_t)v;
}

/* 发送函数内：最后一道关卡 */
cmd = clamp_i16(raw, -16384, 16384);
can_send_motor_cmd(cmd);

输入验真

/* 超出物理范围一律不信 */
if (!rpm_looks_valid(rpm)) {
    rpm = last_valid_rpm;    /* 旧值顶上 */
    if (++bad_count > 50)  /* 50ms */
        send_current(0);      /* 断电 */
} else {
    last_valid_rpm = rpm;
    bad_count = 0;
}

输出不设限会溢出反转；输入不验真就是用假数据开车。

演示：输出限幅「削平」PID 输出

紫虚线 = PID 原始输出 · 绿实线 = 实际发送，被削掉的部分永远到不了电机

通信中断（Communication Loss）：断联不是停机

判断标准只有一条：没了这条数据，我还能不能安全地干这件事？按此提前设计离线策略，断联照表执行。

中断对象还能安全干必须停掉 / 降级
遥控器（DR16）无一切，超时 100ms 急停
某电机 CAN 反馈其余电机正常动该电机断电 + 报障
裁判系统运动、云台射击（离线时射击无效）
上位机（视觉）手动控制自动瞄准，降级为手动
离线状态必须可观测（LED / UI 指出谁离线）；CAN 断线后要复位控制器，防止错误计数满进入 bus-off 拖垮整条总线。

电机掉线：反馈沉默 = 最危险的状态

定义：电机掉线——CAN 反馈帧停止更新（数据停住不动或完全收不到）。常见原因：线松、接插件氧化、电调死机。

危险在哪

速度闭环「以为」电机在转：误差不变，积分项持续累积，输出越推越大；线重新接上，电机可能瞬间满功率狂转。

处理三步

  • 超时断电：200ms 无反馈，电流置 0
  • 积分清零，消灭「憋着的大招」
  • 报障 + 恢复流程，绝不瞬间复活
一句话总结：反馈沉默本身就是故障信号——超时就断电，重连走恢复流程。

传感器异常与机械卡死（堵转）

传感器异常

与掉线区别：数据仍在更新，但内容是错的。识别靠三层检查（范围 / 跳变 / 连续），处理为丢弃验真、连续异常降级（见第 8 页）。

机械卡死（堵转）

堵转信号：电流拉满 + 转速约等于 0，电能全变成热量，几秒烫手、几十秒烧线圈。

堵转判据三条件缺一不可：|电流| > 阈值 且 |转速| < 阈值 且 持续 > 500ms → 断电 + 报障。瞬时「大电流低转速」可能只是启动瞬间；摩擦轮等常堵转机构单独对待。堵转是物理问题，代码解决不了，必须人来查。

堵转检测代码

/* 每 1ms 控制周期调用一次 */
void stall_check(int16_t rpm, int16_t cur)
{
    /* 电流大 + 转速≈0 */
    if ((rpm > -100 && rpm < 100) &&
        (cur > 12000 || cur < -12000)) {
        stall_ms++;          /* 计时 */
    } else {
        stall_ms = 0;        /* 清零 */
    }

    if (stall_ms > 500) {   /* 500ms */
        send_current(0);   /* 断电 */
        fault_led_on();   /* 报障 */
    }
}
三个条件同时满足才判堵转：大电流 + 零转速 + 持续 500ms。
触发后不自动恢复：机械卡死是物理问题，需人工确认后解锁。
阈值按实车标定：记录堵转瞬间日志，取正常爬坡电流之上。

注入故障：

电源异常：低电压与功率超限

电池电压是整车的体能条：电压低还硬拉满输出，主控会先断电重启——场上直接「死机」，比降档可怕得多。

电压区间档位允许动作
> 24.0 V满血全功率输出
22 ~ 24 V降档限功率、减加速度
< 22.0 V保命仅云台与基本运动，禁止射击，提示换电
功率超限：预测下一拍输出会超限，主动按比例降档，不等裁判系统判罚（本质是动态输出限幅）。电压采样要做短时平均 + 滞回比较，防止保护抖来抖去。

缓启动（Ramp）：输出别跳崖，让它走坡道

定义：目标值突变时，输出按固定斜率逼近目标，限制每周期变化量。上电瞬间全功率阶跃 = 三重冲击。

阶跃启动的危害

  • 电流冲击：电池与电调瞬间最大电流
  • 机械冲击：齿轮「啪」地一响
  • 云台猛地甩头，威胁队友与机械

Ramp 的纪律

  • 斜率平衡：太慢反应迟钝，太快形同虚设
  • 底盘 / 云台 / 摩擦轮可用不同斜率
  • 升降双向都 ramp；安全急停可直接置 0

RAMP_STEP = 50（每 1ms）时，5000 满值约 100ms 爬满。Ramp 解决「指令突变」，解决不了「负载突变」——真堵转，该断电还是断电。

缓启动代码

/* 每 1ms 调用一次 */
void ramp_to(int16_t target)
{
    if (out_now < target) {
        out_now += RAMP_STEP; /* +50 */
        if (out_now > target) out_now = target;
    } else if (out_now > target) {
        out_now -= RAMP_STEP;
        if (out_now < target) out_now = target;
    }
    send_current(out_now); /* 发送前已限幅 */
}
到顶后钉在目标：先加步长再比较，防超调。
恢复时也走 ramp：目标先同步到当前值，再爬升，防「诈尸式」弹起。
对比：阶跃是瞬间拉满（冲击），斜坡是平稳爬升（无冲击）。

演示：缓启动 · 阶跃 vs 斜坡

保护触发之后：恢复设计

故障状态机

正常 → 保护 → 恢复确认 → 正常

  • 软故障（通信抖动 / 低电压）自动恢复
  • 硬故障（堵转 / 传感器损坏）人工确认
  • 恢复走 ramp，清积分，防诈尸式弹起

必须可观测

  • LED 灯语：颜色 + 闪烁频率区分故障（红灯常亮 = 堵转，慢闪 = 通信断，黄灯 = 低电压）
  • 日志：类型 / 时间 / 关键数据（电流、电压、误差），赛后复盘靠它
  • 上电自检亮一遍灯，验证 LED 没坏
一句话总结：保护要看得见，恢复要分轻重——软故障自动恢复，硬故障人工确认。保护触发了却没人知道，等于没保护。

常见问题与排查

现象可能原因排查方法
超时保护频繁误触发阈值太小 / 周期不稳日志看实际间隔，阈值取 3~5 倍
电机「诈尸」瞬间狂转掉线期间积分累积掉线清积分，恢复走 ramp
堵转保护误触发持续时间太短 / 没区分爬坡加长 500ms，按实车改阈值
限幅后仍溢出反转限幅不在发送函数内最后一道关卡放 CAN 发送前
低电压保护抖动采样没滤波 / 没滞回短时平均，降档恢复用不同阈值
拔一根 CAN 线全车瘫控制器进入 bus-off掉线检测中复位 CAN 控制器
保护触发但灯不亮灯语在保护逻辑外 / LED 坏上电自检 + 日志与灯语交叉验证
