# 2.4 运动学与坐标系

> 本节目录 / 建议课时：120 分钟（讲课 60 + 实操 60）｜前置要求：1.5 PID 与闭环控制、2.3 软件架构

这一节回答一个问题：**「机器人怎么知道自己朝哪儿、往哪儿走、炮口指向哪儿？」**
答案分成三块：坐标系（方向怎么描述）、底盘（四个轮子怎么配合出任意方向）、云台（炮口角度怎么算）。

## 学习目标

- [ ] 能说出世界系 / 机器人系 / 云台系分别以什么为基准，并举出「同一个矢量在不同系里坐标不同」的例子

- [ ] 能解释麦克纳姆轮为什么能横移（45° 辊子 + 力的分解）

- [ ] 能说出全向轮、舵轮与麦轮的核心区别和优缺点
- [ ] 能区分相对角 / 绝对角，以及位置控制 / 速度控制的差别
- [ ] 能把「视觉给的世界系目标」换算成「云台要转到的角度」这条链路讲给队友听

## 核心概念

### 概念一：坐标系——同一个箭头，三种「地图」

**生活类比**：你在教学楼里找教室。有人给你画了校园地图（世界系），有人站在你旁边指路「往前走」（以你为基准），有人站在天桥上指路「就是那栋楼的第三扇窗」（以他所在位置为基准）。三句话都能指到同一个目标，但「前、左、右」的含义完全不同。

机器人上也有三张「地图」：

| 坐标系 | 类比 | 基准 | 谁在用 |
|---|---|---|---|
| 世界坐标系（World） | 校园地图 | 场地固定，不动 | 视觉、裁判系统、导航 |
| 机器人坐标系（Robot/Body） | 车上的人 | 车体，X 轴 = 车头方向 | 底盘控制、IMU 输出 |
| 云台坐标系（Gimbal） | 云台上的人 | 云台本体，X 轴 = 炮口方向 | 云台控制、射击 |

```
世界系（场地俯视图，永远不动）
  ↑ Y
  |
  +-----→ X

机器人系（X 永远指向车头，车转它也转）      云台系（X 永远指向炮口，云台转它也转）
        ↑X（车头）                                ↑X（炮口）
        |                                          |
        +--→ Y（左侧）                              +--→ Y
```

**为什么需要变换？** 因为协作的模块各自用各自的系：

- 视觉在图片里算出的敌人位置是**世界系**坐标；
- 云台电机只知道「相对车体转了多少度」（机器人系/云台系）；
- 车一边自转（小陀螺）一边要打中敌人，就必须把世界系目标**转换**到云台系，算出炮口该指的角度。

**同一个矢量在不同系里坐标不同**——比如「敌人」这个矢量：世界系里可能是 (5, 3)，但车转了 30° 后，在机器人系里就是 (2.8, 4.8)。矢量本身没变，是「地图」转了。

变换的工具是 2×2 旋转矩阵（别怕，只有四个数）：

```
机器人系 → 世界系：  [ x_w ]   [ cosθ  -sinθ ] [ x_r ]
                    [ y_w ] = [ sinθ   cosθ ] [ y_r ]

θ = 车头相对世界系 X 轴的夹角（逆时针为正）
```

**直觉解释**：这个矩阵就是「把机器人系的地图转 θ 度，对齐到世界系」的公式。车头向量在机器人系是 (1, 0)，乘上矩阵得到世界系 (cosθ, sinθ)——正好是转了 θ 的车头方向，你可以手算验证。

**手算一遍（一定要动手）**：θ = 90°，机器人系里有个点 (2, 0)（车头正前方 2 m）：

```
世界系坐标 = [cos90°  −sin90°]·[2] = [0  −1]·[2] = [0]
            [sin90°   cos90°] [0]   [1   0] [0]   [2]
```

得到 (0, 2)：车头朝世界系 Y 轴正方向（地图正上方），正前方 2 m 就是地图 (0, 2)。合理！

**θ 的符号约定**：θ = 车头相对世界系 X 轴的夹角，**逆时针为正**。θ = 90° 表示车头朝「地图正上方」；θ = −90° 朝「地图正下方」。比赛里还会约定场地坐标系（红方/蓝方视角），原理相同，只是零点和方向的定义不同。

> **一句话总结：坐标系就是「以谁为基准说话」，三个系说同一件事要用旋转矩阵翻译；机器人转多少度，坐标系就跟着转多少度。**

### 概念二：Yaw / Pitch / Roll——车头的三种「摇头」

**生活类比**：Yaw 像人左右摇头说「不」，Pitch 像点头说「是」，Roll 像歪头卖萌。

在机器人语境下：

| 轴 | 英文 | 机器人动作 | 哪个电机/传感器负责 |
|---|---|---|---|
| Z 轴 | Yaw（偏航） | 车头左右摆（原地转、小陀螺） | 底盘差速 + IMU |
| Y 轴 | Pitch（俯仰） | 点头（炮口抬高压低） | 云台 Pitch 电机 |
| X 轴 | Roll（翻滚） | 侧翻（车左右倾） | 一般不主动控制，IMU 观测 |

```
        ↑ Z（Yaw 绕它转）
        |
        |
        +------→ Y（Pitch 绕它转，车宽方向）
       /
      ↙ X（Roll 绕它转，车头方向）

右手定则：右手握轴，拇指指向轴正方向，四指弯曲方向 = 正方向
```

**为什么电控必须知道这些**：IMU（惯性测量单元，可以理解为车上的「陀螺仪传感器」）输出的就是这三个角。底盘自转时 Yaw 在变，云台要反方向补偿同样的角度，炮口才能稳定指向敌人——这就是后面「绝对角」的来源。

> **一句话总结：Yaw = 左右摆头、Pitch = 点头、Roll = 侧翻；IMU 负责实时报告这三个角度。**

### 概念三：麦克纳姆轮——45° 的魔法

**生活类比**：普通轮子像「只能直行的行李箱」，麦克纳姆轮像「机场里的万向登机箱」——不用拐弯，横着推、斜着推都行。

#### 第一步：单轮原理

麦克纳姆轮（Mecanum Wheel）由一个主轮毂 + 一圈斜 45° 安装的小辊子（roller）组成。小辊子能绕自己的轴自由转动。

- 轮毂正转时，地面摩擦力的方向被辊子「掰」成**与辊子垂直的方向**（45° 斜向）；
- 这个斜向力可以分解成「前后分量」+「左右分量」——这就是横移力量的来源；
- 辊子自己也在空转，把沿辊子方向的分量「吃掉」了。

```
俯视图（单轮，轮轴沿 ←→ 方向）：

  ╲ ╲ ╲          ← 辊子斜 45° 安装
   ╲ ╲ ╲
    ╲ ╲ ╲

轮子向前滚 → 摩擦力方向：↗（斜 45°）
               分解：↑ 向前分量 + → 向右分量
```

**45° 是关键**：0°（普通轮）只有向前分力；90°（就是全向轮）只有左右分力；45° 让两个方向各占一半，四个轮子配合就能拼出任意方向。

#### 第二步：四个轮子组合

四个麦轮对角安装（从上方看，辊子走向对角相同，形似「X」型布置）。每个轮子的斜向力组合起来：

```
前进：四个轮同向同速 → 左右分力两两抵消，只剩向前 ✓
横移：对角两个轮正转、另外两个反转 → 前后分力抵消，只剩左右 ✓
旋转：左边两个反转、右边两个正转 → 合力为零，只剩力矩，原地转 ✓
斜移：前进 + 横移按比例叠加 → 任意方向 ✓
```

**核心思想是「抵消」**：要前进就把左右分量抵消掉，要横移就把前后分量抵消掉，要旋转就把平动分量抵消掉。

#### 第三步：解算公式（逆运动学）

已知：车体想要的速度 Vx（前）、Vy（左）、ω（逆时针转），求四个轮速。

约定（重要，全节通用）：
- 机器人系：**X 前、Y 左、Z 上**（右手系）；
- ω 为正 = 俯视**逆时针**（左转）；
- 轮子编号：1 左前 FL、2 右前 FR、3 左后 RL、4 右后 RR；
- a = 车长的一半，b = 车宽的一半（轮子到车中心的纵向/横向距离）。

```
V1(左前) = Vx − Vy − ω·(a+b)
V2(右前) = Vx + Vy + ω·(a+b)
V3(左后) = Vx + Vy − ω·(a+b)
V4(右后) = Vx − Vy + ω·(a+b)
```

**不用背。理解两个规律即可**：

1. 平移项：Vx 全部同号（前进四个都转）；Vy 的符号「左前、右后为负，右前、左后为正」——对应「对角同转、邻轮反向」的横移图案；
2. 旋转项：右前、右后为正，左前、左后为负——右边转向前、左边转向后，车就左转。

> 严格推导会多出一个 √2 系数（45° 分解的代价），工程实现里把它当整体比例处理，由速度环 PID 自己补偿，所以公式直接这么写。

**速度溢出**：前进 + 横移 + 旋转同时拉满时，某个轮速可能超过电机上限。处理办法：找出四个轮速里绝对值最大的，若超上限，全部等比例缩小（方向比例不变，轨迹不变形）。

#### 两个容易问的问题

**Q1：X 型和 O 型布置有什么区别？**
麦轮分 A、B 两种手性（辊子方向镜像）。装车时对角轮同型、左右不同型叫「X 型」（从上方看辊子走向像 X）；左右同型、对角不同型叫「O 型」。两种都能全向移动，只是公式里 Vy 和 ω 的符号图案不同。**全队必须统一用一种并写进注释**，混装就会出现「横移变斜线」的经典故障。

```
X 型（对角相同，本教程采用）：        O 型（左右相同）：
  左前=右后=A 型   右前=左后=B 型       左前=右前=A 型   左后=右后=B 型
```

**Q2：为什么旋转项是 (a+b)？**
轮子到车中心的纵向距离是 a、横向距离是 b。车体以 ω 旋转时，轮子处的切向线速度在矩形底盘的角点上正好是 ω·(a+b)。底盘长宽越接近正方形，四个轮子旋转项的系数越接近，车转起来越「圆」。所以步兵底盘都尽量做成方形。

**代入数字试试**：Vx=1、Vy=0.5（前进 + 左移）、ω=0.2，a=b=0.15（k=0.3）：

```
V1 = 1 − 0.5 − 0.2×0.3 = +0.44
V2 = 1 + 0.5 + 0.2×0.3 = +1.56
V3 = 1 + 0.5 − 0.2×0.3 = +1.44
V4 = 1 − 0.5 + 0.2×0.3 = +0.56
```

四个都是正转（车以前进为主），但右前、左后转得更快（叠加了左移和左转的成分）。这就是「合成」的含义。

> **一句话总结：麦轮 = 45° 辊子把摩擦掰成斜向力；四个轮子按「抵消」图案配合，就能合成任意方向的平动 + 旋转。**

### 概念四：全向轮与舵轮——另两位「全能选手」

**生活类比**：麦轮是「斜纹轮胎」；全向轮是「横条纹轮胎」；舵轮是「每个轮子自己会打方向盘」。

| | 麦克纳姆轮 | 全向轮（Omni Wheel） | 舵轮（Steering Wheel） |
|---|---|---|---|
| 结构 | 轮毂 + 45° 斜辊子 | 轮毂 + 90° 竖辊子（像横条纹） | 普通轮 + 转向电机（像超市购物车轮） |
| 安装 | 四轮平行装，像普通车 | 3~4 个轮按角度斜装（如互成 45°/120°） | 四个轮各带转向机构 |
| 横移 | ✓ 任意方向 | ✓ 任意方向 | ✓ 但要先转轮，慢 |
| 优点 | 装车简单、RoboMaster 主流 | 结构简单、侧向力大 | 抓地最好、负载大、过障碍强 |
| 缺点 | 辊子交替接地，略颠；怕滑 | 接地不连续、震动大、越障差 | 结构复杂、转向有延迟、控制最麻烦 |
| 解算 | 线性公式（本节重点） | 类似的向量分解 | 转向角要用反三角函数求 |

在 RoboMaster 赛场上，步兵/英雄几乎都用麦轮（结构紧凑、解算简单）；工程机器人取弹机构常用舵轮式的小车（负载重、需要精确对准）。

**舵轮解算为什么更麻烦**：舵轮的转向电机必须先转到目标角度，轮子才能出正确的力，这中间有机械延迟；而且四个轮的转向角要满足几何约束（各轮转向圆要共圆心，否则轮子会互相「别劲」），需要按底盘尺寸解三角函数。相比之下麦轮解算只是四则运算，这也是它受欢迎的原因之一。

> **一句话总结：三者的目标一样——不拐弯就能全向移动；麦轮靠斜辊子，全向轮靠竖辊子，舵轮靠给每个轮子装方向盘。**

### 概念五：云台角度——相对角与绝对角

**生活类比**：你转动脖子看黑板。脖子转了 30° 是「相对角」（相对你的身体）；但如果你的椅子也转了 20°，你的脸相对教室黑板就是 50°——这是「绝对角」。

| | 相对角 | 绝对角 |
|---|---|---|
| 定义 | 云台相对车体转的角度 | 云台相对场地/车头基准方向的角度 |
| 谁来测 | 云台 Yaw/Pitch 电机编码器 | 编码器 + 底盘 IMU Yaw 合成 |
| 特点 | 上电归零，掉电就忘记 | 不受车体转动影响，指哪儿就是哪儿 |

**多圈编码器**：普通编码器转到一圈会「归零跳变」，多圈编码器能记住累计转了几圈，超过 360° 也不丢角度。

**为什么需要绝对角**：车原地自转（小陀螺）时，云台要保持炮口指向敌人的话，云台相对车体必须**反向转同样的角度**：

```
云台绝对角 = 云台相对角 + 底盘 Yaw（IMU）

俯视图（角度逆时针为正，0° = 场地正前方）：
  底盘 Yaw = +30°（车左转了 30°）
  云台想指 0°（正前方）
  → 云台相对角 = 0° − 30° = −30°（云台相对车体向右打 30°）
```

例如底盘 Yaw 转到 +30°，云台想指向场地正前方（绝对角 0°），那云台相对角就要转到 −30°。这就是云台控制里著名的「反向补偿」。

**这条链路的完整版**（视觉给目标 → 云台瞄准）：

```
视觉在世界系算出敌人方位角 target_world（相对场地）
    → 减底盘 Yaw：得到敌人相对车头的角度
    → 减云台当前相对角：得到云台还差多少度
    → 位置环输出目标角速度 → 速度环执行
```

每个环节的角度都要用回绕函数包到 (−180°, 180°]，避免跨圈跳变。

> **一句话总结：相对角是「脖子转了多少」（编码器），绝对角是「脸朝哪儿」（编码器 + IMU 合成）；车转多少，云台就反着补多少。**

### 概念六：位置控制 vs 速度控制

**生活类比**：拧瓶盖，位置控制 =「转 180° 就停」，速度控制 =「匀速转起来，不关心停在哪」。

| | 位置控制 | 速度控制 |
|---|---|---|
| 目标 | 转到某个角度（°） | 保持某个角速度（°/s） |
| 输入 | 目标角度 | 目标角速度 |
| 反馈 | 编码器角度 | 编码器角度差分出的角速度 |
| 典型场景 | 云台瞄准、舵轮转向角 | 底盘轮速、云台跟随时 |

云台电机常用的做法是**串级**：外环位置控制算出「需要转多快」，交给内环速度控制去执行——「想去 30°，先算出该用 20°/s 冲过去，快到再减速」。串级结构会在 2.5 节详细展开，这里先记住「位置包着速度」即可。

```
云台瞄准控制链（串级，先有个印象）：

  目标角度(°)
      │ 误差 = 目标 − 当前
      ▼
  ┌─────────┐   目标角速度(°/s)   ┌─────────┐   电流/电压   ┌──────┐
  │ 位置环 PID │ ─────────────────► │ 速度环 PID │ ──────────► │ 电机  │
  └─────────┘                     └─────────┘               └──────┘
      ▲                                ▲                        │
      │ 当前角度（编码器）              │ 当前角速度（角度差分）      │
      └────────────────────────────────└────────────────────────┘
                    云台实际转动（编码器测量）
```

**底盘为什么只跑速度环**：底盘的目标通常来自摇杆或导航，本身就是「速度指令」（推多快走多快），不需要「停在哪」；而云台要「指向某个角度」，所以外环是位置。等你在 2.5 学会 PID 整定，就能理解为什么云台调参比底盘多一层。

> **一句话总结：位置控制管「转多少度」，速度控制管「转多快」；云台瞄准用位置环，底盘轮子用速度环。**

### 任务二：C 语言实现麦轮解算（25 分钟）

**做什么**：把公式写成函数，并用三种简单运动测试输出。

```c
/* mecanum_solve.c —— 麦轮逆解算
 * 约定：X 前、Y 左、ω 逆时针为正；1=左前 2=右前 3=左后 4=右后
 * 注意：输出的轮速是归一化单位（真实轮速差一个整体比例系数），
 *       直接作为速度环目标使用即可，比例由 PID 整定补偿。
 */
#include <stdio.h>
#include <math.h>

typedef struct { float vx, vy, vw; } ChassisVel;   /* 车体目标速度 */
typedef struct { float w1, w2, w3, w4; } WheelSpd;  /* 四个轮速 */

/* 麦轮解算：车体速度 -> 四个轮速 */
WheelSpd mecanum_solve(ChassisVel v, float a, float b)
{
    WheelSpd w;
    float k = a + b;               /* 旋转项的公共系数 */
    w.w1 = v.vx - v.vy - v.vw * k; /* 左前 */
    w.w2 = v.vx + v.vy + v.vw * k; /* 右前 */
    w.w3 = v.vx + v.vy - v.vw * k; /* 左后 */
    w.w4 = v.vx - v.vy + v.vw * k; /* 右后 */
    return w;
}

/* 限幅：任一超限则四个等比例缩小，保住方向比例 */
void mecanum_limit(WheelSpd *w, float max_spd)
{
    float m = fmaxf(fmaxf(fabsf(w->w1), fabsf(w->w2)),
                    fmaxf(fabsf(w->w3), fabsf(w->w4)));
    if (m > max_spd) {
        float s = max_spd / m;
        w->w1 *= s; w->w2 *= s; w->w3 *= s; w->w4 *= s;
    }
}

int main(void)
{
    ChassisVel go  = {1.0f, 0.0f, 0.0f};   /* 前进 */
    ChassisVel strafe = {0.0f, 1.0f, 0.0f}; /* 左横移 */
    ChassisVel spin = {0.0f, 0.0f, 1.0f};  /* 逆时针转 */
    WheelSpd w;

    w = mecanum_solve(go, 0.15f, 0.15f);
    printf("前进:    %+.2f %+.2f %+.2f %+.2f\n", w.w1, w.w2, w.w3, w.w4);

    w = mecanum_solve(strafe, 0.15f, 0.15f);
    printf("左横移:  %+.2f %+.2f %+.2f %+.2f\n", w.w1, w.w2, w.w3, w.w4);

    w = mecanum_solve(spin, 0.15f, 0.15f);
    printf("逆时针:  %+.2f %+.2f %+.2f %+.2f\n", w.w1, w.w2, w.w3, w.w4);
    return 0;
}
```

**预期现象**：输出应为——
- 前进：四个全 +1；
- 左横移：左前 −1、右前 +1、左后 +1、右后 −1；
- 逆时针：左前 −0.3、右前 +0.3、左后 −0.3、右后 +0.3（k=0.3）。

**自查点 ✔**：横移输出是「对角同号」吗？旋转输出是「右正左负」吗？都符合就说明公式和你的直觉对齐了。

### 任务三：云台角度换算（20 分钟）

**做什么**：写两个小函数：世界系目标 → 云台相对角；角度回绕到 (−180°, 180°]。

```c
/* gimbal_angle.c —— 云台角度换算（演示用，单位统一为度） */
#include <stdio.h>
#include <math.h>

/* 把任意角度回绕到 (-180, 180] */
float wrap180(float deg)
{
    while (deg > 180.0f)  deg -= 360.0f;
    while (deg <= -180.0f) deg += 360.0f;
    return deg;
}

/* 世界系目标角 -> 云台相对车体的角度（底盘 Yaw 来自 IMU） */
float target_to_gimbal_rel(float target_world_deg, float chassis_yaw_deg)
{
    return wrap180(target_world_deg - chassis_yaw_deg);
}

int main(void)
{
    float target = 0.0f;          /* 敌人在地图正前方 */
    float yaw = 30.0f;            /* 底盘 Yaw = 30 度 */
    float rel = target_to_gimbal_rel(target, yaw);
    printf("底盘 Yaw = %.1f 度，瞄准正前方需要云台相对角 = %.1f 度\n",
           yaw, rel);
    /* 期望输出：-30.0 度（车左转了 30 度，云台要反着补 30 度） */
    return 0;
}
```

**预期现象**：输出 −30.0 度——正是「反向补偿」。

**自查点 ✔**：把 yaw 改成 −90、target 改成 45，手算一下再运行对照。手算和程序一致才通过。

## 常见问题与排查

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 横移走成斜线 / 原地转圈 | 某个轮子装反（A/B 型装错）或公式符号反了 | 纸笔推一遍符号；单独给 Vy，看车是否纯横移 |
| 原地旋转时车会漂移 | 轮径不一致、摩擦不同或四个轮系数不统一 | 空转校准轮径；检查限幅后比例是否被破坏 |
| 满速前进时轨迹变形 | 速度溢出没限幅 | 检查 mecanum_limit 是否在每个周期调用 |
| 云台上电自转 / 乱甩 | 相对角零位没初始化、绝对角补偿符号错 | 上电标零；核对「绝对角 = 相对角 + 底盘 Yaw」符号 |
| 云台角度转到一圈时跳变 | 编码器单圈回绕没处理 | 用 wrap180 类函数统一回绕到 (−180°, 180°] |
| 麦轮在滑的场地上走不直 | 辊子打滑，纯开环速度控制兜不住 | 加底盘 IMU 反馈（后续调车章节展开） |

## 课后自测

1. 车头朝世界系 Y 轴正方向（θ = +90°，即地图正上方）。敌人从车的角度看在车头正前方 2 m。敌人在世界系坐标是多少？
2. 四个轮速分别为：左前 −1、右前 +1、左后 +1、右后 −1，车会怎么动？
3. 车底盘 Yaw = −20°，云台想指向世界系 +70° 方向，云台相对角该是多少？
4. 全向轮和麦轮的结构差在哪？为什么 RoboMaster 主流用麦轮而不用全向轮？
5. 「位置控制」和「速度控制」的目标量、反馈量分别是什么？云台瞄准为什么用位置环？
6. 满速前进的同时满速横移，为什么某个轮速会超过电机上限？怎么处理？
7. 为什么舵轮小车横移前必须先「转轮」，而麦轮不用？

<details><summary>参考答案</summary>

1. 机器人系 (2, 0) 旋转 θ=90°：世界系 = (2·cos90° − 0·sin90°, 2·sin90° + 0·cos90°) = (0, 2)。车头朝地图正上方，正前方 2 m 就是世界系 (0, 2)。
2. 对照公式：Vx 四个同号、Vy 项对角同号且邻轮异号、旋转项为零 → 只有 Vy = +1 → 纯左横移。
3. 相对角 = wrap180(70 − (−20)) = wrap180(90) = 90°。
4. 麦轮辊子斜 45°，全向轮辊子垂直轮轴 90°；全向轮辊子交替接地、震动大、越障差，麦轮装车简单（四轮平行）更适合赛场。
5. 位置控制：目标角度（°）、反馈编码器角度；速度控制：目标角速度（°/s）、反馈角度差分。云台瞄准关心「最终指向」，所以外环用位置。
6. 轮速是 Vx、Vy、ω 三者的线性叠加，|Vx| 和 |Vy| 都拉满时，某个轮子的叠加值可达上限的 2 倍。处理：四个轮速等比例限幅（mecanum_limit），方向比例不变。
7. 舵轮的轮子只能沿自身朝向出力，横移前必须先用转向电机把轮子转到侧向（有机械延迟）；麦轮的 45° 辊子让任意方向都能即时出力，不需要等待。
