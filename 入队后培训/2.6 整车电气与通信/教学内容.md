# 2.6 整车电气与通信

> 本节目录 / 建议课时：90 分钟（讲课 45 + 实操 45）｜前置要求：1.4 电机与基础控制、2.2 裁判系统

在 1.4 节你已经让单台电机转了起来。这一节把视野从「一块板子 + 一台电机」放大到**整台车**：全车十几台电机、主控、裁判系统、图传是怎么连在一起供电、通信、协同工作的。学完本节，你应该能对着整车线束图讲清楚「电从哪来、信号怎么走、出问题往哪查」。

---

## 学习目标

- [ ] 能用「车间广播」讲清楚 CAN 总线的工作原理，说明差分信号为什么抗干扰
- [ ] 能说出标准帧各字段（SOF、ID、DLC、数据、CRC、ACK、EOF）的作用，指出仲裁是谁先说话
- [ ] 能解释 120Ω 终端电阻为什么两端各一个，并会用万用表测量判断终端电阻是否齐全
- [ ] 能对照官方手册说出电机控制帧 / 反馈帧的 ID 规律，知道波特率不匹配会怎样
- [ ] 能对比 UART 与 USB 的差别，说清各自在整车上的用途
- [ ] 能画出整车电源树：电池 → 电源管理模块 → 常电 / 动力电 两条支路，并解释超级电容的作用
- [ ] 能说清一点接地、共地、线材粗细的原则，列举电磁干扰的三大来源与对策
- [ ] 会按「症状 → 排查 → 修复」套路处理供电 / 接线 / 接地 / 干扰四类整车电气问题

## 核心概念

### 概念一：CAN 总线 —— 车间的广播喇叭

**生活类比**：想象一个嘈杂的车间，所有工人（设备）面前都挂着一个公共广播喇叭（总线）。谁都可以喊话，喊出来的话**所有人都听得见**；只是每句话开头都会报上「我是谁、说给谁听」的编号，其他人听了编号发现不是找自己的，就不理它。CAN（Controller Area Network，控制器局域网）就是机器人的这个公共广播系统。

**为什么整车用 CAN 而不是一对一的线**：假设全车 8 台电机 + 主控 + IMU，如果用一对一的线连，就是一大把线束；而 CAN 只需要**两根线**把所有设备挂在一起。CAN 由汽车工业发展而来（我们的机器人本质就是一辆小车），成熟、抗干扰、能挂很多设备、还有硬件级错误检测。

**两根线怎么传数据 —— 差分信号（Differential Signal）**：

```
         CAN_H ──────────────────────────────►  3.5V
         CAN_L ──────────────────────────────►  1.5V
                  显性(逻辑0)：H 高 L 低，压差 ≈ 2V
         CAN_H ──────────────────────────────►  2.5V
         CAN_L ──────────────────────────────►  2.5V
                  隐性(逻辑1)：两根线一样高，压差 ≈ 0V
```

CAN 用 CAN_H、CAN_L 两根线，靠**两根线的电压差**表示 0 和 1。干扰（比如电机启动时的大电流）通常同时抬升或拉低两根线，但**差值几乎不变**——就像两个人并排走路，地面一起晃动时，两人之间的「距离」没变。这就是差分信号抗干扰的秘密。CAN 线一般做成**双绞线**（两根线拧成麻花），让两根线受到的干扰更一致。

> 注：上图的电平数值是 ISO 11898-2 高速 CAN 的典型值，用于建立认识；具体到某款收发器芯片以数据手册为准。

**一句话总结**：CAN 是挂所有设备的「车间广播」，用两根线的电压差传数据，差值不受共模干扰影响，所以天生抗造。

### 概念二：CAN ID —— 门牌号兼优先级

**生活类比**：广播里的每条消息都自带「门牌号」：**CAN ID**。就像车间广播喊「3 号工位注意」，只有 3 号工位的设备才会处理这条消息。

**ID 的两个作用**：

1. **地址（谁的消息）**：设备靠 ID 过滤，只收自己关心的消息。例如电调发回的反馈帧 ID 是 `0x201`，主控一看就知道「这是 1 号电调在汇报」。
2. **优先级（谁先说话）**：总线同一时刻只允许一个人「广播」。两台设备同时开讲怎么办？靠**仲裁（Arbitration）**：ID 小的优先。为什么？因为 CAN 是「线与」结构——显性（0）能压过隐性（1），谁先发出 0 谁就赢。ID 小的数字在前面的位就有更多 0，所以 ID 越小优先级越高。

```
  设备A 想发 ID = 0x200（010 0000 0000）
  设备B 想发 ID = 0x201（010 0000 0001）
  两设备同时开讲：
      逐位比较，前 10 位相同……
      第 11 位：A 发 0，B 发 1 → 0 压过 1 → A 胜出，B 自动闭嘴等下次
```

标准帧的 ID 有 11 位（0~2047）。**没有「主机」概念**——任何设备想说话就可以尝试，抢输了自动重发，这叫多主（Multi-master）结构。这也是 CAN 和 UART（一对一、有主从之分）的本质区别之一。

**一句话总结**：CAN ID 既是消息的「门牌号」（谁该收），又是「优先级」（ID 越小越先讲），仲裁靠显性压隐性自动完成。

### 概念三：数据帧 —— 一封信的固定格式

**生活类比**：车间广播虽然随意，但「喊话格式」是严格规定的：先喊「注意！」（起始），再报编号（ID），再报内容长度，再说正文，最后报「完毕」。CAN 的**数据帧（Data Frame）**就是这样一个固定格式的信封。

**标准帧各段作用**（本节只讲标准帧，扩展帧区别在 ID 位数，认识即可）：

| 字段 | 位数 | 作用 | 类比 |
|---|---|---|---|
| SOF 帧起始 | 1 | 一个显性位，宣布「我开始发了」 | 喊「注意！」 |
| 仲裁 ID | 11 | 门牌号 + 优先级 | 报编号 |
| RTR | 1 | 区分数据帧/远程帧，数据帧为显性 | 说明「这是通知，不是问句」 |
| DLC | 4 | 数据长度码，说明数据段有几个字节（0~8） | 报「正文几句话」 |
| 数据段 | 0~8 字节 | 有效载荷，具体含义各协议自定 | 正文 |
| CRC | 15 | 校验码：发送方按内容算一个数，接收方再算一遍比对，不一致说明传错了 | 信末的防伪码 |
| ACK | 1 | 确认位：发送方发隐性（1），任何一个接收方收到后回显性（0）把它「压」住，表示「有人收到了」 | 听众回「收到！」 |
| EOF | 7 | 帧结束，7 个隐性位 | 喊「完毕」 |

> 注：为便于入门，上表省略了 IDE 位、保留位以及各段之间的界定符（delimiter）等细节位，完整定义见 ISO 11898（延伸资源里的维基百科条目）。

**为什么不背电机协议字段**：数据段里每个字节代表什么，是**上层协议**自己规定的。比如 DJI 电机的反馈帧 8 个字节里，哪两个字节是转速、哪两个是角度、单位换算多少——这些**以官方电机手册为准**，本节只让你建立「帧 = 标准信封」的认识。拿到新设备，第一件事永远是翻官方手册找它的帧格式。

**位填充（Bit Stuffing）**：CAN 规定连续 5 个相同的位后必须塞一个相反位，用来保证接收方始终有「跳变沿」可以对齐时钟——细节知道存在即可，硬件自动完成。

**一句话总结**：数据帧是一封格式固定的信：SOF 起头、ID 报号、DLC 报长度、数据是正文、CRC 防错、ACK 确认、EOF 收尾。

### 概念四：波特率与终端电阻

**波特率（Baud Rate）＝大家说话的语速**。总线上的**所有设备必须用同一个波特率**，否则就像一个人用 2 倍速说话，别人听成乱码。RoboMaster 常用 **1 Mbps**（每秒 100 万位）。波特率由时钟分频 + 位时间（TQ）配置出来，具体寄存器配置以你的单片机和官方例程为准——你只需要记住：**全车波特率必须统一，换板子先对波特率**。

**终端电阻（Termination Resistor）＝水管两端的堵头**：

**生活类比**：一根水管两端如果敞着，水冲到管口会「弹回来」形成回波；在两端各装一个堵头，水流到尽头就平静地结束了。电信号在导线里传播也一样：高频信号传到导线尽头会**反射**回来，和后面的信号叠加成一团「毛刺」。解决方法是**在总线物理两端各接一个 120Ω 电阻**，把信号能量吸收掉，反射就没了。

```
   ┌────[120Ω]──────────────────────────[120Ω]────┐
   │                                              │
 主控板 ── 电调1 ── 电调2 ── 电调3 ── …… ── 电调8（都挂在中间）
```

**几个要点**：

- 120Ω 只在**总线两端**各一个，不是每个设备都加——加多了信号反而衰减。
- 整车 CAN 上，通常主控端 / 某个板载位置就有一个 120Ω 终端电阻，另一端在总线另一头（以战队实际布线为准）。
- **万用表检查法**：整车断电后，用电阻档量 CAN_H 与 CAN_L 之间，两端电阻都正常时约 **60Ω**（两个 120Ω 并联）。测到 120Ω 说明少了一个；测到 0Ω 附近说明线短路；测到开路说明线断了。
- CAN 常见故障速查表（背下来，调车快人一步）：

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 某台电机完全没反馈（掉线） | 该节点 CAN 线断 / 接插件松动 | 量该节点 CAN_H-CAN_L 通断，重插接插件 |
| 上电后所有设备都没通信 | CAN_H 与 CAN_L 接反 / 波特率不匹配 | 查收发器引脚接线；核对所有设备波特率配置 |
| 通信时好时坏、偶发错误帧 | 总线缺终端电阻 / 线太长 / 干扰大 | 断电量总线电阻是否为约 60Ω；缩短线、用双绞线 |
| 新接入一台设备后全网瘫痪 | 该设备波特率/ID 冲突 / 接反拉死总线 | 先单独接新设备测试，再并入整车 |
| 数据能收到但内容全乱 | 波特率两端不一致 | 用示波器或回环测试核对实际波特率 |

**一句话总结**：波特率是全员统一的语速；终端电阻是水管两端的堵头，防反射毛刺，两端各 120Ω、并联测得约 60Ω。

### 概念五：电机通信与主控通信

**电机通信**：主控通过 CAN 给电调发**控制帧**，电调通过 CAN 回**反馈帧**——这就是 1.4 节你跑通的那条回路，现在放到整车视角看：

| 帧 | ID 规律（DJI 官方电机） | 说明 |
|---|---|---|
| 控制帧 | `0x200`（发给全部）或 `0x1FF`/`0x2FF`（分组发） | 主控 → 电调，内含目标电流，内容以官方手册为准 |
| 反馈帧 | `0x200 + 电调ID`（如 1 号电调回 `0x201`） | 电调 → 主控，内含角度/转速/电流/温度 |

> 注：上表是 DJI 官方电调手册的 ID 约定，具体字段与分组方式**以官方手册为准**。8 台电机共用一条 CAN 总线，靠 ID 区分谁是谁——这就是概念二「门牌号」在整车上的落地。

**主控通信**：整车往往不止一块主控（例如底盘一块、云台一块，具体架构**以战队实际为准**），板间也用 CAN 或串口互相通信。多板之间同样要约定好各自的 ID、波特率、帧格式——套路和电机通信完全一样：**先对波特率，再对 ID，再对帧格式**。

**一句话总结**：电机的控制/反馈靠 ID 规律区分；主控之间的板间通信也是同一套「波特率 + ID + 帧格式」三步对齐套路。

### 概念六：UART 与 USB —— 两种「点对点」通信

CAN 是广播，而整车还有两种**一对一**的通信：UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）和 USB（Universal Serial Bus，通用串行总线）。

| | UART | USB | CAN（对比参考） |
|---|---|---|---|
| 拓扑 | 一对一（一根收一根发） | 一对多（经集线器分叉） | 一对多（总线广播） |
| 典型速率 | 115200 bps 常见（可调） | USB 2.0 达 480 Mbps | 1 Mbps 常见 |
| 距离 | 数米内 | 数米内 | 数十米 |
| 特点 | 两根线、简单、需约定波特率 | 差分、带供电（5V）、即插即用 | 差分、仲裁、抗干扰强 |

**整车上的用途**：

- **UART**：调试打印（printf 看变量）、和**裁判系统**通信——裁判系统通过电源管理模块的**用户串口**把血量、比赛状态等信息发给主控（接线与协议**以官方手册为准**）；一些传感器（如测距）也用串口。
- **USB**：下载程序（DFU）、连接仿真器/调试器、接 Mini PC 等。开发板 C 型的 Micro USB 口即可用于 DFU 下载（见官方手册）。

按需学习：UART 是必会（裁判系统就用它）；USB 协议本身不必深挖，会用下载/调试功能即可。

**一句话总结**：UART 是简单的一对一「电话线」，USB 是一对多且自带供电的「扩展坞」；整车用 UART 伺候裁判系统和调试，用 USB 下载和调试。

### 概念七：整车电气布局 —— 电源树

**生活类比**：家里的总电表把电分给「照明回路」和「空调大功率回路」两条线，互不干扰。整车电气也是一棵**电源树**：

```
                       电池
                        │  (总电源)
                  电源管理模块（PM）
                  ╱              ╲
        常电（弱电/信号电）      动力电（大电流）
         ┌────┼────┐           ┌────┼────┐
        主控  裁判系统  IMU等   电调→电机  发射机构等
        (逻辑电路)  (传感器)   (功率负载)
```

- **常电**：给主控、裁判系统、IMU 等逻辑电路供电，电流小（安培级以下）、要求**干净稳定**。
- **动力电**：给电调 → 电机、发射机构等大功率负载供电，电流大（可达几十安培）、波动大。
- 两条支路**分开布线**，动力线的大电流波动才不会通过导线、地线干扰到常电——这是整车布局的第一原则：**强电弱电分家**。

**电气布局：分层走线**。整车线束按功能分层，各层互不纠缠：

```
┌─ 动力层：电池 → 电源管理 → 电调 → 电机    （大电流：线粗、短、直）
├─ 常电层：电源管理 → 主控 / 裁判系统 / 传感器（小电流：稳定优先）
├─ 信号层：CAN、串口、DBUS 等信号线          （双绞/屏蔽，远离动力层）
└─ 射频层：图传、遥控接收天线               （远离一切大电流器件）
```

布线要点：动力线与信号线**不要长距离并行走**（并行走线就是干扰的传送带）；信号线必须穿过动力线时尽量**垂直交叉**；线束固定留余量，别在转弯处绷紧（绷紧的线 = 迟早断的线）。

**一句话总结**：整车电气是一棵电源树，电池经电源管理模块分成「常电」和「动力电」两条支路，强电弱电分开走；线束按动力/常电/信号/射频分层布置。

### 概念八：电池、电源管理与超级电容

**电池**：全车能量的源头。RoboMaster 常用航模锂电池（具体型号、串数、容量**以战队实际为准**）。电池最怕两件事：**过放**（电压低于保护值会永久损坏）和**短路**（大电流瞬间烧毁）。上电前先确认电压、检查插头，是电控组的基本习惯。

**电源管理模块（PM，Power Management Module）**：车上的「总电表 + 总闸」。以 RoboMaster 官方电源管理模块为例（参数来自官方产品页，**以官方手册为准**）：

- 供电 DC 24V（经 XT60 等接口输入）；
- 给**底盘 / 云台 / 发射机构**提供 3 路 24V 动力输出，并实时监测各通道电流、电压、功率；
- 给裁判系统各模块提供 5V / 12V / 24V 常电；
- 通过**用户串口**向主控输出裁判系统信息（血量、状态等，协议见官方手册）；
- 能按裁判系统服务器的指令做电源通断控制（比赛中裁判系统可以断电，这是比赛机制的一部分）。

**超级电容（Supercapacitor）＝ 水库**：

**生活类比**：突然开大用水量时（比如全车电机同时急加速），水管里的压力会瞬间掉下去。如果旁边并一个水库，平时蓄水，瞬间大用水时水库先放水补上，压力就稳住了。超级电容就是动力电总线上的「水库」：平时充电，电机瞬时大电流时**并接放电补充**，削平电压尖峰和跌落——这叫**功率缓冲**。具体容量、接入位置**以战队实际方案为准**。

**上电与断电的仪式感**：整车电气操作遵守「先检查、后上电；先断电、后动手」的原则。上电前按任务三的流程检查，断电后等电容放电再插拔。具体顺序**以战队操作规范为准**——目的都是避免「半身带电」时插拔接插件，产生打火冲击、烧坏端子。

**一句话总结**：电池是源头，电源管理模块是总电表兼总闸，超级电容是并接在动力电上的「水库」做功率缓冲。

### 概念九：电调与主控在整车上的角色（复习 + 整车视角）

这两个老朋友在 1.4 节认识过，这里只补充整车视角的要点：

**电调（ESC）**：每台电机配一个（如 M3508 ↔ C620、M2006 ↔ C610），挂 CAN 收指令、输出三相动力电。整车视角注意三点：动力线粗短、远离信号线；电调发热大，注意散热与通风（官方手册有安装要求）；电调自身的告警（过流/堵转/温度）要接到主控的告警处理逻辑里。

**主控（如 RoboMaster 开发板 C 型）**：整车的大脑。官方产品页参数：输入电压 8~28V、板载 IMU、2 路 CAN、UART、DBUS、USB 等接口（完整参数**以官方手册为准**）。主控常挂在常电支路上，通过 CAN 向所有电调发指令、收反馈，通过串口和裁判系统对话。

**一句话总结**：电调管动力、主控管决策；整车视角下，电调的告警必须被主控看到，主控的供电必须干净稳定。

---

### 概念十：接插件、线材与接地

**接插件（Connector）**：车上几百根线全靠接插件连接。要点：动力电用**大电流接插件**（如 XT30 / XT60 系列，具体型号**以战队实际为准**），防松、防反接；信号线用小间距连接器；所有插头**插上后要能听到/感觉到到位**，松动的插头是整车故障第一大来源。

**线材（Wire）**：粗细用 **AWG**（American Wire Gauge）标号，号数越小线越粗。大电流必须用粗线（线细了会发热、压降大，电机「没劲」）；CAN 用**双绞线**抗干扰；信号线尽量短、远离动力线。

**接地（Ground）三条铁律**：

1. **一点接地（星型接地）**：各路的地线汇集到一个公共点（如电源管理模块的地），而不是随便在车架上乱接。地线上一旦有大电流流过，各处「地电位」就不再相等，传感器读到的电压全都会漂。
2. **共地**：两个设备之间传信号（比如主控和裁判系统串口），**地必须相连**，信号才有参考基准。通信不正常时先问一句「共地了吗」。
3. **粗细匹配**：动力地线要和动力正极一样粗；信号地线单独走，别借动力地「顺路」回。

```
   ✔ 星型一点接地                  ✘ 随便乱接地
       ┌─设备A                      设备A ──┐
   共地┤─设备B                      设备B ──┤ 绕成一团
   点 ─┘─设备C                      设备C ──┘
   （各地线一样长、汇集一点）        （地回路串扰、电位不等）
```

**一句话总结**：插头要插紧、大电流走粗线、信号走双绞；接地三铁律是一点接地、必须共地、粗细匹配。

---

### 概念十一：图传与电磁干扰

**干扰从哪来**：整车最大的电磁干扰（EMI，Electromagnetic Interference）源是**电机的 PWM 大电流开关**——电调以几万赫兹的频率快速开关几十安培的电流，就像在车中央放了一台大功率「电磁喇叭」，会通过辐射和电源线向四面八方传播噪声。其次还有发射机构、继电器等开关器件。

**干扰伤到谁**：

- **图传**：图传工作在高频段，图像信号弱，被干扰后出现雪花、花屏。所以**图传天线要远离电调、动力线、电机**，常放在云台高处或车尾（以战队实际布置为准）。
- **传感器与通信**：IMU、串口、CAN 被干扰后数据乱跳、偶发错误。
- **电源**：干扰串进常电，主控可能复位、ADC 读数乱飘。

**四大对策**：

| 对策 | 做法 | 原理 |
|---|---|---|
| 远离 | 图传天线、信号线远离动力线与大电流器件 | 距离远了，辐射干扰按平方衰减 |
| 屏蔽 | 信号线用屏蔽线，屏蔽层一端接地 | 金属网把干扰挡在外面 |
| 双绞 | CAN 等差分信号用双绞线 | 两根线受扰一致，差分一减就消掉 |
| 滤波 | 电源入口加电容（超级电容 / 滤波电容） | 把电源线上的毛刺「吸平」 |

**一句话总结**：电机 PWM 大电流开关是整车的电磁喇叭，图传和信号线要「远离、屏蔽、双绞」，电源要滤波。

---

### 概念十二：整车其他外设一览

除了电调、电机、主控，车上还有一批「配角」。它们接口五花八门，但归纳起来就几种（具体接口与协议**以官方手册 / 战队实际为准**）：

| 外设 | 典型作用 | 典型连接方式 |
|---|---|---|
| IMU 惯性测量单元 | 报出姿态角（Yaw / Pitch / Roll） | 板载，或经 CAN / 串口 |
| 裁判系统各模块 | 血量、状态、图传链路 | 模块间互联，信息经电源管理模块用户串口汇总 |
| 遥控器接收机 | 接操作手指令 | DBUS 等接收接口 |
| 传感器（测距 / 光电等） | 环境感知 | 串口 / IO / ADC |
| 灯光、蜂鸣器 | 状态指示 | PWM / IO |

接新外设的三连问：**① 走什么接口（CAN？串口？IO？）；② 供电是常电还是动力电；③ 协议 / 时序以哪份手册为准。** 答不上来就先查手册，别急着上电。

**一句话总结**：外设千千万，接口就几种——CAN、串口、IO、PWM；接新外设先问接口、供电、协议三件事。

## 动手实践

### 任务一：整车 CAN 总线体检（断电测终端电阻）

**目标**：养成「上电前先体检」的习惯，用万用表确认 CAN 总线物理层健康。

1. **整车断电**：断开电池，等待几秒让电源管理模块等电容放电。
2. 万用表打到**电阻档**，表笔搭在 CAN_H 和 CAN_L 上（可在任一节点处测）。
3. **预期现象**：读数约 **60Ω**（两端各 120Ω 并联）。
   - ✔ 自查点：读数在 55~65Ω 之间为正常。
   - 读数约 120Ω → 只找到一端终端电阻，另一端缺失；
   - 读数接近 0 → CAN_H 与 CAN_L 短路；
   - 读数无穷大 → 总线断线。
4. 逐个轻轻拉动各节点的 CAN 接插件，观察读数是否跳动。**读数跳动 = 接触不良**，换插头或压紧端子。

### 任务二：读一帧电机反馈（整车视角看 ID）

**目标**：在整车总线上抓到电机的反馈帧，用 ID 认出「谁在说话」。

```c
#include "main.h"

CAN_HandleTypeDef hcan1;
CAN_RxHeaderTypeDef rxHeader;   // 收到的帧头（含 ID）
uint8_t rxData[8];              // 收到的 8 字节数据

/* 初始化 CAN1：42MHz 时钟 ÷7 = 6MHz，6 个 TQ 一位 → 1 Mbps */
/* （时钟树与分频以你自己的工程为准，关键是整车波特率统一！） */
void can_init(void) {
  hcan1.Instance = CAN1;
  hcan1.Init.Prescaler = 7;               // 分频：42M / 7 = 6M
  hcan1.Init.Mode = CAN_MODE_NORMAL;
  hcan1.Init.SyncJumpWidth = CAN_SJW_1TQ;
  hcan1.Init.TimeSeg1 = CAN_BS1_3TQ;      // 1 + 3 + 2 = 6 TQ → 1 Mbps
  hcan1.Init.TimeSeg2 = CAN_BS2_2TQ;
  hcan1.Init.TimeTriggeredMode = DISABLE;
  hcan1.Init.AutoBusOff = DISABLE;
  hcan1.Init.AutoWakeUp = DISABLE;
  hcan1.Init.AutoRetransmission = ENABLE;
  hcan1.Init.ReceiveFifoLocked = DISABLE;
  hcan1.Init.TransmitFifoPriority = DISABLE;
  HAL_CAN_Init(&hcan1);

  /* 过滤器：全接收（掩码全 0），整车总线上什么帧都先收进来 */
  CAN_FilterTypeDef filter = {0};
  filter.FilterActivation = ENABLE;
  filter.FilterBank = 0;
  filter.FilterFIFOAssignment = CAN_FILTER_FIFO0;
  filter.FilterScale = CAN_FILTERSCALE_32BIT;
  filter.FilterMode = CAN_FILTERMODE_IDMASK;
  filter.FilterIdHigh = 0;
  filter.FilterIdLow = 0;
  filter.FilterMaskIdHigh = 0;
  filter.FilterMaskIdLow = 0;
  HAL_CAN_ConfigFilter(&hcan1, &filter);

  HAL_CAN_Start(&hcan1);
  HAL_CAN_ActivateNotification(&hcan1, CAN_IT_RX_FIFO0_MSG_PENDING);
}

/* 收到任意一帧就进这个回调 */
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan) {
  if (HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &rxHeader, rxData) != HAL_OK)
    return;
  uint16_t id = rxHeader.StdId;   // 标准帧 ID
  /* DJI 电机反馈帧：ID = 0x200 + 电调ID（1~8 → 0x201~0x208，以官方手册为准）*/
  if (id >= 0x201 && id <= 0x208) {
    uint8_t motorNum = (uint8_t)(id - 0x200);   // 几号电机在说话
    /* 8 字节数据按官方手册解析：角度、转速、电流、温度…… */
    /* 这里先打印 ID，确认「听到了谁」 */
    (void)motorNum;
    (void)rxData;
  }
}
```

**预期现象**：接上整车 CAN 总线并上电后，回调被频繁触发，`id` 在 0x201~0x208 之间变化。
- ✔ 自查点：收不到任何帧 → 检查波特率、终端电阻、接线（回到任务一）；能收到但 ID 全是乱的 → 波特率不匹配或干扰（见常见问题表）。

### 任务三：整车供电检查流程（上电前三问）

**目标**：建立「上电前检查」的标准流程，按顺序过一遍：

1. **问电压**：电池电压是否在正常范围（数值**以战队实际电池为准**）？插上电源管理模块后看其指示灯 / 裁判系统客户端状态。
2. **问接线**：动力线插头是否插到底、有无发烫痕迹？常电与动力电是否分开走线？接插件是否松动？
3. **问负载**：上电瞬间观察——电源管理模块是否报过流？电机是否有异常声音？主控是否正常启动（指示灯/串口打印）？

- ✔ 自查点：任何一步异常都先断电再查，**不要带电插拔动力接插件**（容易打火花、烧端子）。

## 常见问题与排查

本节实战核心：四类整车电气问题的「症状 → 排查 → 修复」表。遇到问题先归类，再按表排查。

### 供电问题

| 症状 | 排查 | 修复 |
|---|---|---|
| 全车无反应、主控不亮 | 量电池电压；查总开关/保险；查电源管理模块输入 | 充电/换电池；换保险；重插输入接口 |
| 大油门时电机「没劲」、电压表往下掉 | 量动力线压降；查线材是否过细过长；查电池内阻 | 换粗线、缩短线；加超级电容做功率缓冲 |
| 电机急加速瞬间主控重启 | 看是否常电被动力电拖垮；查电源管理模块告警 | 常电动力电分开供电；加滤波电容/超级电容 |
| 比赛时间明显变短 | 查电池老化；查是否某路长期漏电 | 换电池；检修漏电设备 |

### 接线问题

| 症状 | 排查 | 修复 |
|---|---|---|
| 某台电机时有时无 | 轻轻拉动该节点插头、线束 | 重插/更换端子，压紧线束固定 |
| 上电后某路直接报过流 | 查该路正负是否接反、是否短路 | 断电重接；量通断后再上电 |
| 通信偶发中断、动一下线就好 | 查信号线插头与焊点 | 更换插头/重新焊接；线束留余量别绷紧 |

### 接地问题

| 症状 | 排查 | 修复 |
|---|---|---|
| 传感器读数乱飘、串口偶发乱码 | 查两设备是否共地；查地线是否松动 | 接好公共地；压紧地线端子 |
| 接上某外设后主控 ADC 读数全偏移 | 查地线回路上是否串了大电流 | 一点接地：各处地线直连公共点，不借道 |
| 图传画面有条纹随电机油门变化 | 查图传地与动力地是否混用 | 信号地与动力地分开；图传远离动力线 |

### 电磁干扰问题

| 症状 | 排查 | 修复 |
|---|---|---|
| CAN 偶发错误帧、电机反馈丢失 | 干扰源（电调/发射机构）靠近总线做对比测试 | CAN 线换双绞/屏蔽；远离动力线 |
| 图传雪花随电机启动出现 | 把图传天线挪远动力线验证 | 天线远离电调/电机；屏蔽线；电源加滤波 |
| 程序偶发死机/复位 | 观察是否大电流动作时发生；查复位脚是否被干扰 | 常电加滤波电容；信号线远离动力线；屏蔽 |

## 课后自测

1. 用一句话解释：为什么差分信号比单端信号抗干扰？
2. 标准帧里，如果发送方发的 CRC 和接收方算出来的不一致，会发生什么？ACK 位是怎么工作的？
3. 整车断电后量 CAN_H-CAN_L 之间电阻为 120Ω，说明什么？为 0Ω 呢？
4. 新加入一台电调后全网通信瘫痪，最先怀疑哪三件事？
5. 说出整车电源树：电池之后是什么？常电和动力电分别给谁供电？超级电容接在哪、干什么用？
6. 图传画面随电机油门出现雪花，按「症状→排查→修复」给出你的排查思路。

<details><summary>参考答案</summary>

1. 干扰通常同时抬升/拉低两根线（共模干扰），而差分信号看的是两根线的**差值**，差值几乎不受共模干扰影响，所以抗干扰强。
2. 接收方会认为帧有错误，不回 ACK（不发显性位）；发送方发现 ACK 位没人「压住」会重发。ACK 是发送方发隐性（1），任一接收方收到正确帧后回显性（0）覆盖它，表示「有人收到」。
3. 120Ω 说明两端终端电阻少了一个（只剩一个 120Ω）；0Ω 附近说明 CAN_H 与 CAN_L 短路。正常应为约 60Ω（两个 120Ω 并联）。
4. 最先怀疑：① 波特率是否与整车一致；② CAN 线是否接反/拉死总线；③ 该设备 CAN ID 是否与其他设备冲突。应先单独测试新设备再并入整车。
5. 电池 → 电源管理模块（PM）→ 分两支：常电（主控、裁判系统、IMU 等逻辑电路）与动力电（电调→电机、发射机构等功率负载）。超级电容并接在动力电上，做功率缓冲（瞬时大电流时先由电容补充，稳住电压）。
6. 归类为「电磁干扰问题」：排查——把图传天线挪离动力线/电调，观察雪花是否随距离减小（定位干扰源）；修复——天线远离电调电机、动力线与信号线分开走、图传供电加滤波、必要时上屏蔽线。

</details>
