## 核心概念

### 0. 三十秒复习：1.5 里你认识的 PID

在 1.5 中你已经知道：PID 是一套「看着误差调输出」的规则，三个字母各管一段：

| 项 | 看什么 | 生活类比 | 一句话 |
|---|---|---|---|
| P | 现在 | 差多少补多少 | 误差越大，出力越大 |
| I | 过去 | 老是差一点？慢慢加把劲 | 攒历史误差，消除静差 |
| D | 未来 | 冲得太快，先收一脚 | 按误差变化趋势提前刹车 |

闭环的含义也复习一下：**边做边看结果边修正**（闭环），而不是闷头做（开环）。

```
目标 ──→(±)──→ [PID] ──→ [电机/云台] ──→ 实际角度
          ↑                                  │
          └────────── 编码器/陀螺仪 ─────────┘
```

本节全部内容都建立在一句大实话上：

> **PID 在纸上很美，接到真实电机上需要一堆「护栏」：限幅、抗饱和、滤波。这就是本节要学的。**

### 1. 输出限幅：电机没有无限力气

**先看问题**：PID 公式里，误差 × Kp 可以算出任意大的数——3 倍最大电流、10 倍最大电压。但电机最大电流就那么大，超出部分给不出去，只会带来两个副作用：
1. 执行器被「顶死」在极限值，实际行为和算出来的不一样；
2. 给积分饱和埋下伏笔（下一节讲）。

生活类比：**水龙头拧到头，出水量就到顶了，再拧不会多出一滴水，只会把手拧坏。**

**解法**：输出限幅（output limit）= 把控制量钳位（clamp）到一个范围：

```
算出的输出：  -3.7  -0.8  0   1.2  4.9
限幅 ±2：    -2.0  -0.8  0   1.2  2.0   ← 超出部分被削平
```

限幅值怎么定？按执行器真实能力：电机最大电流/最大电压对应值，再留一点余量。具体数值查电机手册或实测（讲解时结合战队现有电机数据展示）。

**一句话总结：输出限幅就是把「算出来的理想输出」砍到「执行器实际能做到」的范围，是保护电机也保护控制效果的第一道护栏。**

### 2. 积分饱和：误差大时，积分会「存爆」

**先看问题**：目标突然大跳变、或者云台被卡住堵转时，误差长时间保持很大。I 项的工作方式是把误差「攒」起来，于是积分像雪球一样越滚越大。但输出早就被限幅封顶了——积分攒再多也出不去。等误差终于回零、输出退出限幅，积分已经攒成巨量，输出会长时间顶在反方向，表现就是：**大超调 → 来回振荡 → 半天稳不下来**。这个现象叫积分饱和（integral windup，俗称「积分攒爆」）。

生活类比：**迟到的人不断往你心里记账（积分累积），但你嘴上只能客气（输出限幅）；等哪天憋不住，直接爆炸。**

**解法是两件套，缺一不可**：

1. **积分限幅**：I 项最多攒到 ±int_max，雪球永远滚不出这个范围。
2. **饱和时停止/回退积分**（抗积分饱和 anti-windup）：检测到输出被限幅「压住」时，
   - 方案 A（条件积分）：误差方向和输出同号时，暂停积分累积；
   - 方案 B（反计算）：把积分反算成「恰好让输出等于限幅值」的量，从源头不让它超过。

两者都做，效果对比（示意）：

```
无抗饱和：      ____      /\      /\        ← 大超调，来回荡
               /    \    /  \    /  \
目标 ──────────────────────────────────

有抗饱和：      ____________
               /            \________      ← 干净地追上去
目标 ──────────────────────────────────
```

**一句话总结：积分限幅管住雪球的大小，饱和时停止积分管住雪球继续滚——两件事一起做，才叫抗积分饱和。**

### 3. 微分噪声：编码器毛刺被放大成抖动

**先看问题**：D 项是对误差求导——「求变化快慢」。而编码器数值天生带毛刺：量化台阶、机械振动、电磁干扰都会让读数微微跳动。求导会放大这些高频毛刺，D 项输出剧烈抖动，直接传给电机，云台就「抽搐」了。很多新手调 D 越调越抖，原因就在这。

生活类比：**看每分钟的股价（毛刺多）预测涨跌，会被微小波动吓得上蹿下跳；看日线就平稳多了。**

**解法**：先滤波，再求导。常见两种：
1. **对误差做一阶低通滤波**，再用滤波后的误差做微分——毛刺被平滑掉，D 才敢用。
2. **直接用角速度传感器（陀螺仪）代替位置差分**——陀螺仪直接输出角速度，天然不需要求导（1.4 学过）。

注意权衡：滤波系数越小滤波越重，毛刺越少，但 D 的反应也越迟钝；滤波太轻又压不住毛刺。这个系数要在「干净」和「跟手」之间试出来。

**一句话总结：对带噪声的信号求导 = 放大噪声；先低通滤波再求导（或用陀螺仪），微分项才敢用。**

### 4. 串级 PID：一个环不够，套两个

**先看问题**：只控位置的单环有个弱点——外界力矩扰动（撞一下、拨一下、摩擦突变）进来时，必须等「位置」已经偏了，环才知道，反应慢而且软。

**解法**：把两个环套起来，内环专门管速度，外环专门管位置。以云台 Pitch 为例：

```
目标角度 →(±)→ [位置环 PID] → 目标角速度 →(±)→ [速度环 PID] → 电流 → [电机+云台]
             ↑   （外环，慢）                    ↑  （内环，快）         │
             │                                 │                    ↓
             └─────── 实际角度(编码器) ─────────┴──── 实际角速度(陀螺仪)
```

- **外环（位置环）**：输入 = 目标角度 − 实际角度；输出 = **目标角速度**。
- **内环（速度环）**：输入 = 目标角速度 − 实际角速度；输出 = 电机电流。

关键一句话：**外环的输出，就是内环的目标。** 外环像不慌不忙的「决策者」，只管决定「该以多快的速度追过去」；内环像手脚麻利的「执行者」，把速度死死稳住。

**为什么比单环抗干扰强**：扰动（比如手拨云台）进来，第一瞬间改变的是**角速度**——内环立刻发现并顶回去，位置几乎还没动；而单环必须等位置偏差出现才反应。所以串级的抗扰能力高出一截。

两条实战经验：
1. **整定顺序必须先内后外**：先把外环断开，单独把内环（速度环）调好，再接上外环调。顺序反了越调越乱。
2. 外环通常只用 P 或 PI，D 少用（外环本来就慢，位置信号求导噪声大）。

**一句话总结：串级 PID = 外环定速度目标、内环稳速度；扰动刚冒头就被内环吃掉，位置几乎不动。**

### 5. 位置环、速度环：「环」到底指什么

「X 环」= 反馈量是 X 的闭环。把几个环从小到大排：

| 环 | 反馈量 | 输出 | 机器人里谁常用 |
|---|---|---|---|
| 电流环 | 电流（力矩 ≈ 电流） | 电压/PWM | 电机驱动内部，我们一般不碰 |
| 速度环 | 转速/角速度 | 电流 | 摩擦轮、底盘 |
| 位置环 | 角度/位置 | 目标速度 | 云台 Pitch/Yaw |

常见搭配：云台 Pitch/Yaw 用「位置环套速度环」（串级）；摩擦轮只做速度环；底盘一般做速度环（结合 2.4 运动学把底盘速度分解到四个轮子）。

注意：环数不是越多越好。每多套一层，就多一组要整定的参数、多一份延迟。够用就好（讲解时结合战队现有代码展示每个执行器用了哪些环）。

**一句话总结：「X 环」= 反馈 X 的闭环；云台常用位置+速度双环，摩擦轮只用速度环。**

### 6. 前馈：别等误差出现，提前把劲儿给上

**先看问题**：PID 是「看到误差才反应」——误差为零时输出基本为零（只剩 I）。跟踪快速运动的目标时，永远在「追」，天生慢半拍。

**前馈（feedforward）的思路完全相反：不看误差，直接按「目标本身」算出需要多少输出，提前给上。** 常见四种：

| 前馈 | 按什么算 | 解决什么 |
|---|---|---|
| 速度前馈 | 目标速度 × 系数 | 跟踪运动目标慢半拍 |
| 加速度前馈 | 目标加速度 × 系数 | 惯性大的对象加速时跟不上 |
| 重力补偿 | 按角度算重力力矩 | Pitch 停不同角度需要的力矩不同 |
| 摩擦补偿 | 补一个固定量 | 克服静摩擦那「第一下」 |

组合方式：**u = u反馈 + u前馈**。反馈负责纠错（把剩余的小误差修掉），前馈负责给大头（提前把主要的量给够）。两者是队友不是对手。

两个注意点：
1. 前馈系数也要整定：给多了会过冲，给少了留残差——和 PID 一样实车试。
2. 前馈用的是「目标」信号，目标如果是阶跃（突变），速度前馈会在突变瞬间给一个尖峰——所以前馈的目标一般要先做平滑（如斜坡、S 形轨迹）。

**一句话总结：反馈是「错了再改」，前馈是「提前给够」；两者相加，又稳又跟手。**

### 7. 各执行器调参方向（只讲方向，数值自己试）

| 执行器 | 物理特点 | 调参方向与理由 |
|---|---|---|
| 云台 Pitch | 重力始终往下拽 | 需要足够的 I 或重力补偿来「扛住」重力，否则垂头/抬头回中慢 |
| 云台 Yaw | 摩擦大、有静摩擦 | 适当的 I 克服静摩擦，P 决定跟手程度；I 太大会低频抖 |
| 底盘 | 惯性大、整车重 | P 不宜过大，否则来回冲、点头；以速度环为主 |
| 摩擦轮 | 只需转速稳定、要求快响应 | 转速环为主，往「快响应」方向调，波动小即达标 |

**重要：本节不提供具体数值。** 每台车的机械结构、重心、摩擦力都不同，参数必须实车试出来。整定顺序记住五个步骤：

1. 确认传感器正常（陀螺仪零漂、编码器方向）再动手；
2. 先内环后外环（串级时）；
3. 先 P，让系统能「大致跟上」；
4. 再 D 压超调，最后加 I 消静差；
5. 确认限幅与抗饱和都已生效，再上剧烈目标。

**一句话总结：调参先保证「传感器对、方向对」，再按 先内后外、先P后I再D 的顺序实车整定。**

## 动手实践

### 任务一：进阶 PID 代码骨架

**做什么**：把 1.5 的裸 PID 升级成带「四道护栏」的版本，接到自己的电机上。

**步骤**：
1. 抄写下面的 `pid_adv` 结构体与更新函数到自己的工程。
2. 先给很大的输出限幅，确认行为和 1.5 的裸 PID 一致。
3. 把输出限幅调到电机允许范围的八成，给一个剧烈阶跃目标，观察电机不再「猛抽」。
4. 把目标从 0 直接跳到很大值再跳回，观察积分是否被压住。
5. 自查点 ✔：输出限幅、积分限幅、抗饱和、微分滤波四处都在代码里真实生效。

```c
/* pid_adv.h —— 进阶 PID：输出限幅 + 积分限幅 + 抗饱和 + 微分滤波 */
typedef struct {
    float kp, ki, kd;
    float out_max;      /* 输出限幅：电机最大电流/电压对应值，按手册设 */
    float int_max;      /* 积分限幅：积分最多攒这么多 */
    float filt_coef;    /* 微分低通滤波系数 0~1，越小滤波越重 */
    float err_sum;      /* 积分累积量 */
    float prev_err;     /* 上一次误差（微分用） */
    float prev_filt;    /* 上一次滤波后的误差 */
} PidAdv;
```

```c
/* pid_adv.c */
static float clampf(float v, float lo, float hi)
{
    return v < lo ? lo : (v > hi ? hi : v);
}

void pid_adv_init(PidAdv *p, float kp, float ki, float kd,
                  float out_max, float int_max, float filt_coef)
{
    p->kp = kp; p->ki = ki; p->kd = kd;
    p->out_max = out_max; p->int_max = int_max;
    p->filt_coef = filt_coef;
    p->err_sum = 0.0f; p->prev_err = 0.0f; p->prev_filt = 0.0f;
}

/* 每个控制周期调用一次（如 1kHz），dt 为周期秒数 */
float pid_adv_update(PidAdv *p, float target, float measure, float dt)
{
    float err = target - measure;

    /* ① 微分项：误差先过一阶低通，再差分——滤掉编码器毛刺 */
    float filt_err = p->prev_filt + p->filt_coef * (err - p->prev_filt);
    float d_term = p->kd * (filt_err - p->prev_filt) / dt;

    /* ② 积分项：正常累积 */
    p->err_sum += p->ki * err * dt;

    /* ③ 输出限幅：先算理想输出，再砍到执行器范围 */
    float out = p->kp * err + p->err_sum + d_term;
    float out_lim = clampf(out, -p->out_max, p->out_max);

    /* ④ 抗积分饱和（反计算法）：
       输出被限幅「压住」时，说明积分再攒也没用，
       把积分反算成「恰好让输出等于限幅值」的量，雪球不再滚大。 */
    if (out != out_lim) {
        p->err_sum = out_lim - (p->kp * err + d_term);
    }
    /* ⑤ 积分限幅：双保险，任何情况下积分都不超过 ±int_max */
    p->err_sum = clampf(p->err_sum, -p->int_max, p->int_max);

    p->prev_err = err;
    p->prev_filt = filt_err;
    return out_lim;
}
```

### 任务二：串级 PID 代码骨架（云台 Pitch）

**做什么**：用两个 `PidAdv` 实例搭出「位置环（外环）→ 速度环（内环）」的串级结构。

**步骤**：
1. 实例化 `pos_loop`（外环）与 `vel_loop`（内环），按下面骨架初始化。
2. **先把外环输出固定成常数**（如目标角速度 60°/s），只调内环，调到实际角速度能快速、平稳地跟上。
3. 接上外环，给目标角度阶跃，观察响应。
4. 轻轻手拨云台（注意安全！），观察内环输出迅速反向顶住、位置几乎不动——这就是串级抗扰。
5. 自查点 ✔：外环输出直接作为内环目标；两个环各有各的限幅。

```c
PidAdv pos_loop;   /* 外环：角度误差 → 目标角速度 */
PidAdv vel_loop;   /* 内环：角速度误差 → 电机电流 */

void gimbal_pitch_init(void)
{
    /* 参数仅为示意占位，具体数值实车整定（讲解时结合战队现有代码展示） */
    pid_adv_init(&pos_loop, 4.0f, 0.2f, 0.0f, 180.0f, 90.0f, 0.15f);  /* 外环输出=目标角速度 */
    pid_adv_init(&vel_loop, 2.0f, 0.5f, 0.05f, 8000.0f, 4000.0f, 0.3f); /* 内环输出=电流 */
}

/* 云台 Pitch 控制周期（1kHz 中断或任务中调用） */
void gimbal_pitch_tick(float target_deg, float cur_deg,
                       float cur_vel_dps, float dt)
{
    /* 外环：角度误差 → 目标角速度（这就是「外环输出 = 内环目标」） */
    float target_vel = pid_adv_update(&pos_loop, target_deg, cur_deg, dt);

    /* 内环：角速度误差 → 电流输出 */
    float out = pid_adv_update(&vel_loop, target_vel, cur_vel_dps, dt);

    motor_set_current(PITCH_MOTOR, out); /* 结合战队现有电机接口使用 */
}
```

### 任务三：前馈代码骨架（速度前馈 + 重力补偿）

**做什么**：在反馈 PID 旁边加一条「提前给」的通道，体验「反馈 + 前馈」的组合。

**步骤**：
1. 先不加前馈，让云台 Pitch 跟踪一个正弦摆动目标，记下最大跟随误差。
2. 只加速度前馈，只调 `kv` 一个数，观察误差是否明显减小。
3. 云台停在 0°（水平）和 60°，分别感受「需要手扶的力矩」的差别；再加重力补偿，验证不同角度都能停住。
4. 自查点 ✔：前馈只看目标、不看误差；静止时前馈输出 ≈ 维持力矩。

```c
typedef struct {
    float kv;        /* 速度前馈系数 */
    float ka;        /* 加速度前馈系数 */
    float grav;      /* 重力补偿系数：重力力矩 = grav * cos(角度) */
    float friction;  /* 摩擦补偿：克服静摩擦的固定量 */
} FeedForward;

#define DEG2RAD (3.14159265f / 180.0f)

float pitch_tick_with_ff(float target_deg, float target_vel, float target_acc,
                         float cur_deg, float cur_vel, float dt)
{
    /* 1) 反馈：PID 负责「纠错」 */
    float u_fb = pid_adv_update(&vel_loop, target_vel, cur_vel, dt);

    /* 2) 前馈：按目标直接算出「大概需要多少输出」 */
    float u_ff = ff.kv * target_vel                          /* 速度前馈：动得越快给得越多 */
               + ff.ka * target_acc                          /* 加速度前馈：克服惯性 */
               + ff.grav * cosf(cur_deg * DEG2RAD)           /* 重力补偿：水平时力矩最大 */
               + ff.friction * (target_vel > 0 ? 1.0f : -1.0f); /* 摩擦补偿：补静摩擦 */

    return u_fb + u_ff;   /* 反馈修误差 + 前馈给大头 */
}
```

## 常见问题与排查

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 云台一到限位附近就猛抽 | 堵转时积分攒爆（积分饱和） | 检查抗饱和是否生效；给积分限幅 |
| 云台高频抖动、有电流声 | 微分项用了带噪声的位置差分 | 微分加低通滤波，或用陀螺仪角速度 |
| 目标大跳变时超调严重 | 输出限幅后积分继续累积 | 开启饱和时停止/回退积分 |
| 串级越调越乱 | 先调了外环 | 固定外环输出，先把内环调好 |
| 跟踪快速目标总慢半拍 | 只有反馈、没有前馈 | 加速度/加速度前馈 |
| 云台特定角度停不住、缓慢下滑 | 重力力矩没被补偿 | 增大 I 或加重力补偿 |

## 课后自测

1. 为什么输出限幅之后，I 项会「越攒越危险」？输出限幅和抗积分饱和是什么关系？
2. 用一句话向学弟解释：串级 PID 为什么比单环抗干扰强？
3. 云台 Pitch 从 0°（水平）转到 90°（竖直），重力补偿项该怎么变？为什么？
4. 微分滤波的滤波系数调得过小（滤波过重）会有什么副作用？
5. 设计题：给「跟踪移动目标的云台 Yaw」列一份控制方案：用几个环？加什么前馈？为什么？

<details><summary>参考答案</summary>

1. 输出被封顶后，I 仍随误差累积，但攒再多也出不去；等误差回零，积分要「还债」很久，造成大超调与振荡。限幅是保护执行器，抗饱和是保护积分——两者配套使用。
2. 干扰先改变的是速度，内环（速度环）立刻抵消，位置还来不及变；单环必须等位置误差出现才反应，所以慢。
3. 重力力矩 = m·g·L·cosθ（θ 为仰角），θ 增大时 cosθ 减小，补偿项应随之减小；90° 时理论上为 0。
4. 滤波过重会引入明显滞后：D 项反应迟钝，跟踪高频目标跟不上，甚至因相位滞后而振荡。
5. 示例：位置环（外环）+ 速度环（内环）串级；加速度前馈（目标角速度 × kv）+ 摩擦补偿（克服静摩擦）。机械间隙大时 P、D 保守、I 适中。（开放题，合理即可）

</details>
