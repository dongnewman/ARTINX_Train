2.8　整车调车

整车调车

十步，把上一代整车调成「能上场的车」——分模块调试、逐步集成、问题记录、回归验证
电控组长 董心宇

本节学什么

调车纪律

一次只调一个变量；从最底层往上调。

10 步调车顺序

电气 → 遥控 → 方向 → 云台 → 单轮 → 整车 → 联动 → 视觉。

记录与回归

日志七字段；修完必回归。

安全红线

架空、急停、看护、电池、上电顺序。

核心纪律 ① 一次只调一个变量

定义

一次只改变一个影响现象的输入（参数、线束、代码分支），观察并记录后再动下一个。

三条配套规则

  • 动手前，先记录现状，保证可回滚
  • 动一个，观察，记录结果
  • 不「顺手」改别的东西
做法判定
把左前轮 Kp 从 0.8 改成 1.0一个变量
四个轮子的 Kp 一起改四个变量，无法归因
换了线，顺便改了代码两个变量

核心纪律 ② 从最底层往上调

层内容不查就上的后果
1 电气供电、线束、CAN间歇掉线，伪装成任何 bug
2 输入遥控映射、行程、死区「响应不对」可能只是指令不对
3 方向与反馈转向、编码器符号参数白调；反馈反成正反馈
4~10 控制与集成闭环、解算、联动、功能一切现象不可读

口诀：电气没查完不动软件；方向没对完不调 PID。

每层「已知正确」，上层结论才有意义——调车是排除法。

顺序本身就是排查策略

① 电气→ ② 遥控→ ③ 方向→ ④ Pitch→ ⑤ Yaw→ ⑥ 单轮→ ⑦ 整车→ ⑧ 联动→ ⑨ 视觉→ ⑩ 功能

跳步：第 3 步方向错 → 第 7 步「乱窜」无法定位，嫌疑 = 全部步骤，查一下午。

按序：1~6 步全过 → 只查第 7 步新增部分（解算、四轮配合），十分钟定位。

分模块调试，逐步集成

分模块调试

每个模块（云台 Pitch、底盘单轮……）单独闭环达标，再进入集成。

逐步集成

每次集成只引入一个新模块，出问题就知道找谁。

单轮（⑥）先于整车（⑦）：整车 = 解算 + 四个速度环；环没调好，跑偏分不清来源。

模块越多，现象越不可读——类比：拼乐高，拼一块验一块。

步骤 ① 整车电气与设备检查

项内容
检查什么线束、接头、供电、CAN 连通、电池电压
怎么看断电肉眼查 + 轻拉接头；上电看指示灯、模块在线状态、电压读数
通过标准全模块在线、无掉线、电压正常、轻拉线束无复位
常见坑接头虚接（跑起来才断）、线束老化、电池鼓包

任何一盏灯不对、一个模块不在线，就停在这一步。

步骤 ② 遥控器与输入检查

项内容
检查什么对频、通道映射、行程、死区
怎么看上位机 / 串口打印遥控值，逐通道拨动观察
通过标准数值稳定、方向与直觉一致、松开回中
常见坑通道映射反、没设死区

记录每个通道的最小值 / 中值 / 最大值，写进日志。

步骤 ③ 电机方向与反馈检查

项内容
检查什么单电机正指令转向 + 编码器读数方向
怎么看开环给小电流，看转向；同时打印编码器读数
通过标准同指令同方向（相对车体）、反馈同号
常见坑方向装反；反馈反成正反馈（给目标满速疯转）
/* 第 3 步：开环给单电机小电流，查方向与反馈 */
Motor_SetCurrent(can_id, 1000);          /* 小电流 */
for (int i = 0; i < 100; i++) {
    printf("enc=%u\r\n", Encoder_GetCount(can_id));
    HAL_Delay(20);
}
Motor_SetCurrent(can_id, 0);             /* 测完立刻停 */
/* 判据：转向符合预期？读数方向与运动一致？ */

步骤 ④ 云台 Pitch

项内容
检查什么Pitch 电机方向 → 反馈 → 零位 → 限位 → PID
怎么看先复做第 3 步方向反馈检查；再给小目标角度观察响应
通过标准小角度阶跃稳定到位、无震荡；限位生效不硬顶
常见坑先调 PID 后才发现方向反；限位没接或逻辑反

五件事按顺序确认，别跳。方向反了，参数白调。

步骤 ⑤ 云台 Yaw

项内容
检查什么Yaw 电机方向反馈；IMU 安装方向与坐标轴映射
怎么看手转云台读角度，确认数值方向与实际一致；再给目标角度
通过标准指向稳定、无持续漂移、阶跃无震荡
常见坑IMU 坐标轴映射错（转 90° 读成 −90°）

联动补偿方向反的问题，留到第 8 步查。

步骤 ⑥ 底盘单轮（速度环先行）

项内容
检查什么单轮速度环阶跃跟随（PID 上场）
怎么看一次只控一个轮子，串口打印目标 / 实际速度
通过标准跟得上、无持续震荡、稳态误差小
常见坑跳单轮直接整车；反馈反成正反馈
/* 第 6 步：单轮速度环阶跃，观察跟随 */
int16_t target = 1000;                   /* 按实车取安全值 */
for (int i = 0; i < 1000; i++) {
    if (i == 500) target = 2000;         /* 阶跃 */
    float cur = Encoder_GetSpeedRPM(can_id);
    float out = PID_Calc(&speed_pid, target, cur, 0.001f);
    Motor_SetCurrent(can_id, (int16_t)out);
    if (i % 10 == 0) printf("tgt=%d cur=%.1f\r\n", target, cur);
    HAL_Delay(1);
}
Motor_SetCurrent(can_id, 0);

步骤 ⑦ 底盘整体运动

项内容
检查什么前进 / 横移 / 旋转的运动学解算与跑偏
怎么看低目标速度，分别只发一种指令，观察车身轨迹
通过标准走直线、横移不歪、原地旋转不漂
常见坑某轮方向反 → 乱窜；轮距参数与实车不符

故障走查：「前进变打转」且 1~6 步已过 → 打印四轮指令，核对是否同号同幅。

步骤 ⑧ 云台—底盘联动

项内容
检查什么底盘旋转 / 运动时云台指向、机械干涉
怎么看慢速原地旋转底盘，看云台是否反向补偿
通过标准补偿方向正确、指向稳定、全行程无干涉
常见坑补偿方向反（转向翻倍）；供电波动；线束被挂

先慢速确认补偿方向，再提速。

步骤 ⑨ 视觉联调（与视觉组配合）

项内容
检查什么视觉目标 → 云台执行；通信链路稳定性
怎么看视觉给目标，观察云台指向；抓通信数据核对
通过标准指哪打哪；长跑数据帧无乱码丢包
常见坑坐标系不统一、弧度 vs 度、协议字段错位

坐标系、单位、协议——三方先对接口文档，再上机。

步骤 ⑩ 其他整车功能 + 收尾

项内容
检查什么拨弹、发射、裁判系统状态、模式切换，逐项过
怎么看每项单独触发，看执行结果与裁判系统反馈
通过标准各项按需求运行、互不干扰
常见坑发射瞬间底盘限流；不常用功能被跳过

收尾三件事：日志未闭环标红；更新回归清单；写一句话交接。

问题记录：调车日志七字段

字段填什么反例
日期当天日期，跨天调车才有时序不填，分不清先后
车辆哪辆车、哪个车架「那辆车」
步骤对应 10 步中的哪一步不填，不知现象属哪层
现象客观事实：「前进时车身右偏」「车坏了」
数据读数、截图、曲线、参数值「转速有点低」
改动从几到几：「Kp 0.8→1.0」「调了下参数」
结果改完现象如何、要不要回归不填，等于白改

三条纪律：现象写客观事实；改动可回滚；当场记。没记录的问题 = 没修过。

回归验证：防「修好一个、弄坏三个」

定义

修完一个问题，回头把之前通过的步骤（回归清单）重跑一遍。

□ ① ② ③ ④ ⑤ ⑥ 已通过
□ ⑦ 底盘整体 ← 当前步骤
修改 → 验证 → 回归重勾 → 记录

为什么要回归

系统耦合：底盘限幅改小 → 整车加速变慢，第 7 步「走直线」标准不再满足。

节奏：改 Kp 后先复验第 6 步单轮，再复验第 7 步，10 分钟拦住隐患。

五条安全红线

红线要求
架空调车时车轮架空或车辆垫起，底盘不贴地
急停遥控急停随时可触发，上车先试急停
看护至少两人在场，安全员盯电源与线束
电池充电有人看护，鼓包、破损即停用
上电顺序先开遥控再上电；先断车电再关遥控

红线不是建议：任何一条被破坏，立即停工处理。

为什么「先断车电」：让车先失去动力，而不是先失去控制信号。

与校内赛结合

节奏建议

  • 第 1 周：完成 ①~⑥，打好地基
  • 第 2 周：完成 ⑦~⑩，进入能打状态
  • 每次训练前：回归清单快过一遍
  • 赛后：问题入日志，带清单来调车

校内赛练什么

在有压力、有时间限制的场景里，把这套调车纪律变成肌肉记忆。

第一场考核往往是：底盘能否稳定按指令走——就是第 ⑦ 步。

常见问题与排查

现象可能原因排查方法
上电后电机不转供电 / CAN 掉线 / 虚接回第 1 步；再单电机开环
给目标满速疯转编码器反馈方向反第 3 步核对反馈符号
前进变成原地打转某轮方向反 / 解算错回第 3 步；打印四轮指令
云台到位不停震荡增益过大 / 噪声 / 虚位减增益；查反馈与机械
底盘转云台跟着转联动补偿方向反第 8 步补偿取反再试
「昨晚还好好的」参数被动 / 线松 / 电池老化查日志、接头、电池内阻
修好一个坏三个系统耦合回归清单从头重勾
