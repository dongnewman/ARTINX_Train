### 概念一：电机 —— 机器人的「肌肉」

**生活类比**：人的肌肉把吃进去的能量变成动作，电机把电能变成转动。机器人的每一个轮子、每一个关节，背后都有一块「肌肉」。

**定义**：电机（Motor）是把电能转换成机械能（转动）的装置。RoboMaster 上用的几乎都是**直流无刷电机**（BLDC，Brushless DC Motor）——「无刷」指没有靠摩擦接触的碳刷换向，寿命长、效率高、转速高。你不需要先搞懂它内部的三相绕组怎么工作，只需要知道三件事：

**① KV 值：每伏电压能换多少转速**

KV 是电机的「转速/电压」换算系数，单位 rpm/V（每伏特对应的每分钟转数）。同一电机在允许范围内，电压给得越高，转得越快。KV 高的电机像自行车的高档位——转速快但没力气；KV 低的像低档位——转速慢但力气大。**具体到某一款电机，看官方手册给的空载转速和额定电压即可，不需要自己背 KV 换算。**

**② 减速箱：用转速换力气**

电机转子的转速通常太快（每分钟几千上万转）、扭矩太小，直接带轮子会「高速空转但推不动车」。所以 RoboMaster 电机大多**自带减速箱**——一组齿轮，把「快而无力」变成「慢而有力」：

```
输入：电机转子      减速箱 N:1         输出：输出轴
   19 圈/分   ──────►  19:1  ──────►   1 圈/分（转速 ÷19）
   1 份力气           （齿轮组）         约 19 份力气（扭矩 ×19，忽略损耗）
```

例如 M3508 的减速比约 19:1：转子转 19 圈，输出轴才转 1 圈。**一句话总结：减速箱用转速换扭矩，是机器人电机「有劲」的秘密。**

**③ 堵转：最需要小心的状态**

当负载太重、机械卡死，电机想转转不动时，就发生了**堵转**（stall）。堵转时转速为 0，电流会飙升到很大，能量全部变成热量——就像你用力推一堵墙：一点没动，但憋得满头大汗。RoboMaster 电调都有**堵转/过流保护**，检测到异常会报警并降低功率，这也是为什么调试时听到异响、看到电机发抖要立刻断电检查。

**补充：怎么看懂官方手册的参数表**

第一次打开电机手册会被参数淹没，其实只需先看懂这几个词：

| 名词 | 意思 | 你怎么用 |
|---|---|---|
| 额定电压 | 设计工作电压 | 决定用什么电源供电 |
| 空载转速 | 不带负载的最高转速 | 看「最快能转多快」 |
| 额定扭矩 | 能长期持续输出的扭矩 | 看「能一直出多大力」 |
| 堵转扭矩 | 转不动时能顶住的极限扭矩 | 看「极限力气」，但别长期用 |
| 减速比 | 减速箱齿轮比 N:1 | 换算输出转速与扭矩 |

对比 M3508（约 19:1）和 M2006（约 36:1）：减速比越大，输出越慢、越有力——这也是为什么它们一个去推底盘、一个去带云台（详见概念七）。

> 记忆口诀：**「转得快就没力气，有力气就转不快」**，减速箱就是在这两者之间做交换的。

**一句话总结**：电机 = 机器人的肌肉；KV 值决定「电压换转速」，减速箱用转速换扭矩，堵转是最危险的状态。

### 概念二：电调 —— 翻译官兼驾驶员

**生活类比**：假设你（STM32）只会说中文，而电机只会听「三相电流」这种电流语言，你俩无法直接对话。电调（ESC，Electronic Speed Controller，调速器）就是中间的**翻译官**：你说「目标电流 3000」，它翻译成三相线上精确的电流波形。

**为什么无刷电机必须有电调**：无刷电机要持续转动，需要按顺序给三根动力线通电换向，就像三个人轮流推旋转木马，谁先推、推多大力、什么时机换人，一点都不能错。电调内部用 **FOC**（Field-Oriented Control，磁场定向控制）算法，让磁场始终以最佳角度「垂直推着」转子转——像荡秋千，总在最合适的时机推一把，效率最高、转动最平稳。

**驾驶员的一面**：电调不只翻译，还负责执行——控制三相电流的大小和方向，同时监测温度、过流，出问题时自动保护。所以说它是「翻译官兼驾驶员」。

**RoboMaster 里怎么配套**（均为官方产品，参数以官方手册为准）：

- M3508 电机 ↔ **C620 电调**（一对一配套）
- M2006 电机 ↔ **C610 电调**（一对一配套）
- GM6020 电机 ↔ **内置驱动器**，不需要外接电调，还内置了编码器

**电调收到的指令长什么样**

RM 电机的控制量分为两类（具体范围以官方手册为准）：

| 电机 | 控制量类型 | 含义 |
|---|---|---|
| M3508 / M2006（配 C620 / C610） | 电流（int16） | 正负号决定方向，绝对值决定出力大小 |
| GM6020（内置驱动） | 电压（int16） | 正负号决定方向，绝对值决定出力大小 |

**为什么控制量是「电流」而不是「转速」**：你给的是「用多大力气」，不是「转多快」——同样的力气，空载转得快、带负载转得慢。想让「转速」这个结果听话，需要 1.5 节的闭环控制根据反馈不断调整力气的大小。

**无刷电机的换相，一图理解**：

```
电调按顺序给三相线通电，磁场牵着转子转：

   A 相 ──► B 相 ──► C 相 ──► A 相 ……（循环换相）
   （转子上的磁铁总被下一个方向的磁场“勾引”着转）

普通直流电机靠碳刷机械换相（有摩擦、会磨损）；
无刷电机把换相交给电调用电子方式完成——更快、更准、更耐用。
```

**一句话总结**：电调把 CAN 总线上的数字指令翻译成三相电流，再用 FOC 精准执行——翻译官兼驾驶员。

### 概念三：编码器 —— 里程表

**生活类比**：出租车上的里程表告诉你跑了多少公里；编码器（Encoder）告诉主控「电机转了多少、现在转多快」。

**定义**：编码器是装在电机上的**角度传感器**。RoboMaster 电机的反馈帧里就带着编码器数据：

| 反馈项 | 含义 | 举例 |
|---|---|---|
| 机械角度 | 转子转到哪了，一圈 0~8191 | 4096 表示半圈 |
| 转速 | 每分钟多少转（rpm） | +3000 表示正向快速转 |
| 实际电流 | 现在真正通了多少电流 | 越接近控制量说明跟得越好 |
| 温度 | 电机温度 | 太高就该降负载 |

> 注：上表数值范围与含义以官方手册为准，这里只建立「反馈帧里有角度和转速」的认识。

**增量式 vs 绝对式**（认识即可）：

- **增量式**：只数「转了多少步」，上电时不知道自己在哪一圈，需要校准（M3508/M2006 的编码器属于这类，靠电调配合工作）。
- **绝对式**：上电就知道当前绝对位置（GM6020 内置的编码器支持绝对位置反馈）。

**为什么编码器重要**：没有它，主控就是「盲人发命令」——发了让电机转 10 圈，实际转了几圈完全不知道。有了反馈，才谈得上后面 1.5 节的闭环控制。

**编码器是怎么测角度的**

常见做法：转子上装磁铁/磁环，电路板上的磁传感器（霍尔芯片）感应磁场方向，换算成角度——一圈分成 8192 个刻度（13 位分辨率），所以反馈里的角度是 0~8191。分辨率位数越高，测角越细（GM6020 的定位精度可达 0.05° 左右，以官方手册为准）。

**反馈帧的「一秒 1000 次」**：电机每 1 ms 通过 CAN 报一次数据（约 1 kHz）。你的控制周期和它对齐，闭环才能做得又快又稳。这个数字在 2.3 节「控制周期」会再次遇到，先留个印象。

**一句话总结**：编码器是电机的里程表，把「转了多少、转多快」报回主控，是一切闭环控制的前提。

### 概念四：CAN —— 整车神经总线

**生活类比**：一个班级群聊——所有人挂在同一条「线」上，一条消息发出去大家都能听见，只是上面写着「谁的消息、给谁看」。CAN（Controller Area Network，控制器局域网）就是机器人的这条总线。

**为什么用它**：CAN 是汽车工业的成熟总线（我们的机器人本质就是一辆小车）。它用两根差分信号线 CAN_H / CAN_L 传输，抗干扰强；速率常用 **1 Mbps**；一根总线能挂很多设备，坏了还能继续通信。整车所有电调、主控、其他板子都挂在这条总线上：

```
                         CAN 总线（CAN_H / CAN_L，1 Mbps，两端需终端电阻）
   ┌────────┐──────────────────┬──────────────────┬─────────────────┐
   │ STM32  │            ┌─────┴─────┐      ┌─────┴─────┐     ┌─────┴─────┐
   │ 主控板  │            │  C620 电调 │      │  C620 电调 │     │  IMU 等   │
   └────────┘            │   →电机1   │      │   →电机2   │     │  其他设备  │
                         └───────────┘      └───────────┘     └───────────┘
```

**ID：每条消息的门牌号兼优先级**

CAN 标准帧的 ID 是 11 位二进制（0~2047）。它有两个作用：

1. **地址**：设备只收「发给自己的 ID」。比如 1 号电机的反馈帧 ID 是 `0x201`，主控收到后一看 ID 就知道「这是 1 号电机的消息」。
2. **优先级**：总线是单车道，两台设备同时发消息时，**ID 越小的帧优先级越高**，先通过；冲突的另一方自动退让重发。这个机制叫「仲裁」。

**一条标准帧长什么样**（先建立印象，细节见演示文档的帧动画）：

```
┌──────────┬──────────────────┬──────────────┬────────────────────┬────────────┬──────────┐
│ 帧起始 SOF │  ID 仲裁段(11位)   │ 控制段 DLC    │   数据段 (0~8 字节)  │ CRC 校验段  │ 帧结束 EOF│
└──────────┴──────────────────┴──────────────┴────────────────────┴────────────┴──────────┘
   广播开始     地址＋优先级        数据有多长        真正的内容（控制量！）  收方验算    一轮结束
```

类比快递面单：帧起始＝开始装货，ID＝收件人地址，DLC＝货有几箱，数据段＝货物本身，CRC＝封箱前的核对清单，帧结束＝装完关门。

**RoboMaster 电机的 CAN 约定**（通用认识，具体以官方手册为准）：

- 通信速率 **1 Mbps**，反馈帧约 **1 kHz**（每 1 ms 报一次）。
- **控制帧**（主控 → 电机）：发目标电流/电压。C620/C610 用 ID `0x200` 一帧同时控制 1~4 号电机；GM6020 用 ID `0x1FF`/`0x2FF` 按组控制。
- **反馈帧**（电机 → 主控）：ID = `0x200 + 电机ID`，即 1 号电机 `0x201`、2 号 `0x202`……8 字节数据依次是角度、转速、电流、温度等。

**仲裁：单车道上的让行规则**

总线上同一时刻只允许一帧通行。两台设备同时开讲怎么办？——它们**一边发一边听**：ID 按二进制逐位比较，谁先出现「隐性位（1）」谁就让行。例：ID `0x201`（010 0000 0001）和 `0x200`（010 0000 0000）同时发，前 10 位相同，第 11 位 `0x201` 是 1、`0x200` 是 0，于是 `0x200` 这一帧先通过。**结论：ID 越小优先级越高**，所以高优先级的控制帧往往占用更小的 ID。

**两个电气小知识**（接线上电时会用到）：

- **差分信号**：CAN 用 CAN_H 和 CAN_L 两根线的**电压差**表示 0/1。外界干扰会同时影响两根线，差值几乎不变——这就是它抗干扰强的原因。
- **终端电阻**：总线两端各需接一个终端电阻，否则信号会在端点反射形成噪声，轻则收包出错、重则总线瘫痪。「接上能通、拔了不通」的怪毛病常常是它引起的。

**一次通信的时序**（一个控制周期约 1 ms）：

```
 0 ms   STM32 发控制帧 0x200（目标电流）           ──┐
 之后    电调收到，翻译成三相电流，电机出力          │
 之后    编码器持续测得角度与转速                    │ 同一条总线，
 1 ms   电调发反馈帧 0x201（角度/转速/电流/温度）    │ 指令与反馈轮流转
 1 ms   STM32 收到反馈，开始下一轮控制              ──┘
```

每 1 ms 循环一次，一秒 1000 次——这就是机器人「心跳」。你写的控制代码，最终都嵌在这个循环里。

**RM 电机 CAN 帧 ID 速查**（本节用到的约定，具体以官方手册为准）：

| 帧 | ID | 方向 | 数据段含义 |
|---|---|---|---|
| 控制帧（C620/C610） | `0x200`（ID 1~4）/ `0x1FF`（ID 5~8） | 主控 → 电机 | 4 组 int16 电流 |
| 反馈帧（C620/C610） | `0x200 + 电机ID`（如 `0x201`） | 电机 → 主控 | 角度 / 转速 / 电流 / 温度 |
| 控制帧（GM6020） | `0x1FF` / `0x2FF` | 主控 → 电机 | 4 组 int16 电压 |
| 反馈帧（GM6020） | `0x204 + 电机ID` | 电机 → 主控 | 角度 / 转速 / 电流 / 温度 |

**一句话总结**：CAN 是一条大家都能听的「神经总线」，靠 ID 区分地址与优先级；RM 电机的指令和反馈都是 8 字节数据的标准帧。

### 概念五：控制量与反馈量 —— 命令与实况

**生活类比**：你闭眼指挥队友走路——你喊「往前走三步」是**控制量**（命令）；队友喊回来「现在走了两步半」是**反馈量**（实况）。

**定义**：

- **控制量**：你发给执行器的命令。对 RoboMaster 电机来说就是目标电流（int16，正负号决定方向、绝对值决定出力），比如 `+3000`。
- **反馈量**：传感器报回来的真实状态。对电机来说就是编码器报的角度、转速，以及实际电流和温度。

**完整回路**（本节的核心图，务必记住）：

```
       控制量(目标电流)               三相电流                  转动
 STM32 ──────────────► CAN ────────► 电调 ────────────────► 电机
   ▲                                                   （编码器跟着转）
   │             反馈量(角度/转速/温度)                        │
   └────────────────── CAN ◄────────────────────── 编码器 ◄───┘
```

**开环 vs 闭环**（这是 1.5 节 PID 的引子）：

- **开环 = 蒙眼开车**：只发命令、不看反馈。命令发对了还好，一旦有坡、有风（扰动），车就偏离目标，而你完全不知道。
- **闭环 = 睁眼开车**：不断读反馈，和目标的差距（误差）大了就修正命令。给电机装上了「眼睛」。

在任务四里你会亲眼看到开环的局限：同一个控制量，空载时转得飞快，用手一捏转速立刻掉下来——因为没人「看见」并补偿。

**一个例子串起来**

你想让 1 号电机「正转、中等力气」，完整流程是：

1. **发命令**：控制量 `current_target = +6000`，装进 CAN 帧（ID `0x200`）发出去。
2. **执行**：电调把指令翻译成三相电流，电机开始转动。
3. **收实况**：电调以 1 kHz 回报「角度 1234、转速 2850 rpm、实际电流 5972、温度 32℃」。
4. **核对**：你观察到实际电流 ≈ 控制量，说明命令执行到位。

**开环为什么「不稳」**：控制量只是「命令」，不是「结果保证」。空载时 6000 转得飞快；轻轻一捏，转速腰斩，可命令还是 6000——因为它根本不知道转速掉了。**闭环**要做的，就是每毫秒问一句：「现在转速多少？和目标差多少（**误差**）？该加还是该减力气？」这个「边看边修」的算法，就是 1.5 节的 PID。本节先种下直觉：**误差 = 目标 − 实际**。

**开环 vs 闭环对比表**：

| | 开环 | 闭环 |
|---|---|---|
| 用不用反馈 | 不用 | 用 |
| 受扰动后 | 偏了就偏了，无人纠正 | 自动修正命令 |
| 生活类比 | 蒙眼开车 | 睁眼开车 |
| 本节体验 | 任务四：捏住电机转速掉 | 1.5 节 PID 解决 |

**一句话总结**：控制量是你说出去的命令，反馈量是传感器报回来的实况；开环只喊不看，闭环边看边修。

### 概念六：IMU 与 Yaw / Pitch / Roll

**生活类比**：你手机里的陀螺仪就是 IMU 的一部分——手机一翻转，屏幕跟着转，就是它在测量姿态。

**定义**：IMU（Inertial Measurement Unit，惯性测量单元）集成了**陀螺仪**（测角速度）和**加速度计**（测加速度），能解算出设备当前的**姿态角**——也就是它「朝向哪里」。

**三个姿态角，用头来记**（现在就跟着做）：

| 角度 | 英文 | 头部动作 | 机器人里常见用法 |
|---|---|---|---|
| Yaw | 偏航角 | 左右摇头（说「不」） | 底盘朝向、云台水平旋转 |
| Pitch | 俯仰角 | 上下点头（说「是」） | 云台上下打角（最重要！） |
| Roll | 翻滚角 | 左右歪头（卖萌） | 车身倾角、坡道检测 |

想象你是一台步兵机器人：Yaw 决定「炮口朝哪个方向」，Pitch 决定「炮口抬多高」，Roll 则是「整台车有没有侧倾」。云台上装的 IMU 主要是看 Yaw 和 Pitch；底盘被顶起来时 Roll 会明显变化。

> 注意：IMU 的三轴习惯上对应 机体坐标系——X 指前、Y 指左、Z 指上。不同设备、不同库的轴方向和旋转顺序约定不同，**具体以所用设备的官方手册为准**，本节只需要建立「摇头/点头/歪头」的直觉。

**陀螺仪与加速度计，各自管什么**

- **陀螺仪**：测「转得有多快」（角速度）。响应快，但长时间积分会有漂移。
- **加速度计**：测「哪个方向在受力」。静止时靠重力方向知道「哪边是下」，能帮陀螺仪纠偏。
- 两者数据融合（传感器融合算法），才能解算出稳定可靠的姿态角——这是 IMU 内部算法的核心思路，认识即可。

**机器人里怎么用**：云台控制器每秒上千次读取 IMU 的 Yaw/Pitch，结合电机反馈一起做闭环（2.5 节串级控制的由来）；底盘用 Yaw 判断朝向，用 Roll 判断车有没有被顶起来或侧倾。

**一个必须养成的习惯**：不同设备的坐标轴定义可能不同（有的 X 指前、有的 Z 指前），**接入新 IMU 第一件事是读官方手册确认轴方向与旋转顺序**，否则「摇头」和「点头」会互相串。

**课堂小实验（1 分钟）**：拿出手机，打开自带的指南针或水平仪 App，跟着做三件事——左右摇头（Yaw 变化）、上下点头（Pitch 变化）、左右歪头（Roll 变化）。你会发现「姿态角」不是什么高深概念，你每天都随身带着一块 IMU。RoboMaster 云台上的 IMU 干的正是同一件事，只是每秒做上千次。

**一句话总结**：IMU 是机器人「前庭系统」，Yaw 左右摇头、Pitch 上下点头、Roll 左右歪头。

## 动手实践

> **安全与准备（务必先读）**
> 1. 上电前：电机固定好或输出轴架空，轮子/负载不要装，手和线远离转动部件。
> 2. 起步控制量用最小值（如 3000），先转起来再逐步加大。
> 3. 出现异响、抖动、冒烟、烫手：立刻断电，按「常见问题」排查。
> 4. 接线以战队现有硬件为准（讲解时结合战队现有代码与实车展示）；本节代码为**通用伪代码骨架**，战队实际封装处的函数名以现有工程为准。

### 任务零：认识实物（5 分钟，不动电）

先别急着上电，拿到电机组件后完成三件事：

1. **找零件**（做什么）：指出哪根是三相动力线（电机 ↔ 电调）、哪根是 CAN 线（电调 ↔ 主控）、哪根是电源线。预期：能对着实物说出每根线连到哪。自查点 ✔ 三相线通常更粗，CAN 线只有两根。
2. **感受减速比**（做什么）：慢慢转动输出轴一圈，数一数转子（通过后盖孔观察或听声音）转了多少圈。预期：M3508 输出轴转 1 圈，转子约转 19 圈——这就是 19:1 减速箱「转速换扭矩」的直接体验。
3. **找到编码器**（做什么）：观察电机尾部/内部电路。预期：找到磁传感器电路的位置，理解「里程表」就在电机身体里，不是外挂设备。

四个任务对应一条能力主线：**会读（反馈）→ 会写（控制）→ 会改（方向）→ 会调（控制量）**。

**上机前检查清单**：

| 项目 | 要求 | 检查方法 |
|---|---|---|
| 供电 | 24 V 电源/电池，电压正常 | 万用表量电压、看电调指示灯 |
| CAN 接线 | 主控 CAN 口 ↔ 电调，总线两端有终端电阻 | 万用表通断档 |
| 通信参数 | 波特率 1 Mbps，主控与电调一致 | 能收到任意反馈帧即通过 |
| 安全 | 电机架空或固定、无负载、起步电流小 | 手动转输出轴确认无阻碍 |

### 任务一：获取电机反馈

**目标**：让主控收到 1 号电机的反馈帧，打印出角度与转速；用手转电机，观察数字变化。

**步骤**：

1. **检查接线**（做什么）：确认 24 V 供电、电调 CAN 线接到主控板的 CAN 口、总线两端有终端电阻。预期：电调指示灯正常。自查点 ✔ 波特率统一 1 Mbps。
2. **写接收与解析**（做什么）：初始化 CAN 后，收到 ID 为 `0x201` 的帧就按「高字节在前」解析 8 字节数据。代码骨架：

```c
// ===== 解析电机反馈帧（通用伪代码骨架）=====
// 反馈帧 ID = 0x200 + 电机ID：1 号电机的反馈帧 ID 是 0x201
#include <stdint.h>
#include <stdio.h>

typedef struct {
    uint16_t angle;   // 机械角度：0~8191 对应一圈 0~360°（以官方手册为准）
    int16_t  speed;   // 转速，单位 rpm
    int16_t  current; // 实际扭矩电流
    uint8_t  temp;    // 电机温度
} MotorFeedback;

// rx 为 CAN 接收到的帧，8 字节数据段
MotorFeedback parse_feedback(uint8_t data[8]) {
    MotorFeedback fb;
    fb.angle   = (data[0] << 8) | data[1];                       // 高 8 位在前（大端）
    fb.speed   = (int16_t)((data[2] << 8) | data[3]);            // 强转 int16：可能有负号
    fb.current = (int16_t)((data[4] << 8) | data[5]);
    fb.temp    = data[6];
    return fb;
}

// 主循环里每收到一帧就打印（伪代码）：
//   rx = can_receive(&hcan1);            // ← 战队实际接收函数占位
//   if (rx.id == 0x201) {                // 只看 1 号电机
//       MotorFeedback fb = parse_feedback(rx.data);
//       printf("angle=%u speed=%d temp=%u\r\n", fb.angle, fb.speed, fb.temp);
//   }
```

3. **观察现象**：用手慢慢转动电机输出轴——预期 `angle` 在 0~8191 间循环变化；捏住输出轴再转，`current` 变大；电机静置时 `speed` 接近 0。
4. **自查点** ✔ 收到帧且 ID 正确？角度随手动旋转变化？数据没有乱跳（乱跳可能是波特率不对或解析错位）。

### 任务二：控制电机旋转

**目标**：发送控制帧，让 1 号电机以稳定速度旋转。

**步骤**：

1. **理解控制量**（做什么）：C620/C610 的控制量是**目标电流**，int16 类型，正负号决定方向。以官方手册为准，`-16384~16384` 约对应 `-20 A~+20 A`，这里先用小值 `3000`。
2. **写发送代码**（做什么）：把控制量按大端（高字节在前）填入数据段的前两个字节，ID 用 `0x200`，周期发送：

```c
// ===== 发送 CAN 控制帧（通用伪代码骨架）=====
// 控制帧 ID 0x200：一帧同时控制 ID 1~4 的电机，数据段 = 4 组 int16
#include <stdint.h>

int16_t current_target = 3000;   // 控制量：目标电流，正 = 正转，负 = 反转

int main(void) {
    // can_init(&hcan1);                    // ← 战队实际 CAN 初始化占位（1 Mbps）

    while (1) {
        uint32_t id = 0x200;                // 控制帧 ID（ID 5~8 用 0x1FF，以官方手册为准）
        uint8_t data[8] = {0};

        data[0] = (current_target >> 8) & 0xFF;   // 1 号电机电流：高 8 位在前
        data[1] = current_target & 0xFF;          // 1 号电机电流：低 8 位
        // data[2..7] 依次是 2/3/4 号电机的电流，这里先都置 0

        // can_send(&hcan1, id, data);       // ← 战队实际发送函数占位

        // delay_1ms();                      // ← 电调期望约 1 kHz 指令流（以官方手册为准）
    }
}
```

3. **观察现象**：烧录后电机平稳转动，串口里反馈帧的 `speed` 为稳定的正数，`current` 接近你给的目标值。
4. **自查点** ✔ 电机转了且不抖？反馈 speed 与控制量同号？温度没有快速上升？

### 任务三：修改电机方向

**目标**：让同一台电机反转，并理解「为什么」。

**步骤**：

1. **改一行代码**（做什么）：把 `current_target` 改为 `-3000`，重新编译烧录。预期：电机反向旋转，反馈 `speed` 变为负数。
2. **理解原理**：电调把控制量的**符号**翻译成三相电流的方向；电流方向反了，磁场推着转子反着转。所以「改方向」本质上就是「控制量取负」。
3. **思考**：如果某个轮子的电机方向装反了（机械上转反了），代码里怎么「纠正」？—— 在该电机的控制量前乘 `-1`（或使用战队封装里已有的方向参数，讲解时结合战队现有代码展示）。
4. **自查点** ✔ 反转后反馈 speed 为负？四个任务用的正反转定义一致（以官方手册「面向输出轴逆时针为正」为基准，整车约定统一方向）？

### 任务四：修改控制量

**目标**：体验「控制量大小 → 转速/出力」的关系，并亲眼看到开环的局限。

**步骤**：

1. **阶梯测试**（做什么）：依次把控制量改为 `3000 → 6000 → 9000 → 12000`（每次重新编译，或临时用变量+按键切换），记录每个档位下反馈的 `speed` 和 `current`。预期：控制量越大，转速越快，但不是严格的线性关系（有摩擦和负载）。
2. **开环实验**（做什么）：控制量固定 `6000`，用手轻轻捏住输出轴（注意安全，隔着纸巾/戴手套）。预期：转速明显下降甚至停住——**因为没人看见转速掉了，命令还是一成不变**。这就是「开环蒙眼开车」。
3. **反向与限幅**（做什么）：试负值（如 `-5000`）；再把控制量改到 `20000`（超过合法范围）。预期：反向正常；超范围时电调按上限处理或进入保护，这就是「限幅」——**输出不允许无限大**。
4. **自查点** ✔ 每个档位 speed 有区分？堵转/超限时电调有保护？把这个「转速被捏掉」的现象记下来，1.5 节 PID 会正面解决它。

## 常见问题与排查

**排查心法（先于任何具体操作）**：调试卡住时，按「**现象 → 分层 → 假设 → 验证**」四步走。先分清问题出在哪一层：

```
供电层（灯亮不亮、电压够不够）
   ↓
通信层（收不收得到帧、波特率对不对）
   ↓
指令层（控制量发没发、ID 对不对）
   ↓
机械层（转不转得动、有没有卡死）
```

例如「电机不动」：先看电调指示灯（供电层）→ 再查能否收到反馈帧（通信层）→ 最后确认控制量是否真的发出（指令层）。逐层排除，比瞎猜快得多——这套方法论在 2.7 节会系统训练。

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 电机完全不动 | 供电没接/电压不足；CAN 线断或接反；控制量是 0；ID 写错 | 依次查供电指示灯 → 换 CAN 线 → 打印发出的帧确认 ID 与数据 |
| 串口收不到反馈帧 | 波特率不是 1 Mbps；终端电阻缺失；反馈 ID 看错 | 核对双方波特率；总线两端接终端电阻；确认「0x200+电机ID」 |
| 电机转了但方向反 | 控制量符号反了；机械安装方向与约定不一致 | 控制量取负再试；统一全车正反转约定（以官方手册为准） |
| 转速忽快忽慢/发抖 | 控制帧发送周期不稳；总线上多帧冲突；供电不足 | 稳定发送周期（1 kHz）；检查其他设备是否抢总线；量供电电压 |
| 电机发烫/有焦味 | 电流过大；长时间满载；堵转未发现 | 立刻断电，检查机械是否卡死，降控制量，检查反馈温度 |
| 多台电机一起失控 | ID 重复；控制帧数据段字节错位 | 确认每台电机 ID 唯一；按「高字节在前」逐组核对数据段 |
| 反馈数据乱跳 | 波特率不匹配；接线接触不良；总线缺终端电阻 | 核对双方波特率；摇一摇接头看是否复现；补接终端电阻 |
| 电机转着转着停了 | 堵转保护触发；CAN 掉线后电调超时保护 | 检查机械是否卡阻；检查 CAN 线是否松动、被压断 |

1. 用一句话说清「STM32 → CAN → 电调 → 电机 → 编码器 → STM32」里每一环的作用。
2. 什么是控制量、什么是反馈量？各举一个本节见过的例子。
3. 用自己的话解释开环和闭环，并给一个生活里的例子。
4. 为什么机器人电机需要减速箱？「19:1」意味着什么？
5. 什么是堵转？为什么堵转很危险？
6. CAN 帧里的 ID 有哪两个作用？两条消息同时发送时，谁先通过？
7. Yaw / Pitch / Roll 分别对应什么头部动作？云台水平旋转、上下打角分别是哪个轴？
8. 想让电机反转，最直接的做法是什么？
9. 为什么说「CAN 的 ID 越小优先级越高」？结合 `0x200` 和 `0x201` 同时发送的例子说明。
10. （实测题）打开 M3508 官方产品页，找出「额定电压、空载转速、减速比」三项分别是多少。

<details>
<summary>参考答案</summary>

1. STM32（大脑）把目标电流写成 CAN 控制帧 → CAN（神经总线）把帧广播出去 → 电调（翻译官）把指令变成三相电流 → 电机（肌肉）转动 → 编码器（里程表）测出角度转速 → 通过 CAN 反馈帧送回 STM32，完成一个循环。
2. 控制量是主控发出的命令（如目标电流 +3000）；反馈量是传感器报回的实况（如编码器报的角度、转速）。
3. 开环只发命令不看结果（蒙眼开车，受扰动就偏）；闭环用反馈修正命令（睁眼开车，自动纠偏）。例子：走路不看路 vs 看着路走。
4. 电机本身转速太快扭矩太小，减速箱用转速换扭矩。「19:1」表示转子转 19 圈输出轴转 1 圈，转速约除以 19、扭矩约乘以 19。
5. 堵转是电机被卡住转不动的状态；此时转速为 0、电流飙升、剧烈发热，可能烧毁电机，因此电调有堵转保护。
6. ID 既是地址（谁的消息）也是优先级（仲裁时 ID 小的帧先通过）。
7. Yaw 摇头（左右）、Pitch 点头（上下）、Roll 歪头（侧倾）。云台水平旋转是 Yaw 轴，上下打角是 Pitch 轴。
8. 把控制量取负（如 +3000 改成 -3000），电流方向反转，电机反转。
9. 总线是单车道，多帧同时发送时按 ID 逐位仲裁，谁先发出隐性位（1）谁让行；`0x200` 的最后一位是 0、`0x201` 是 1，所以 `0x200` 先通过——ID 越小优先级越高。
10. 以官方产品页为准（参考：额定电压 24 V，空载转速 482 rpm，减速比约 19:1）。
</details>
