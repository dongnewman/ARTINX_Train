## 核心概念

### 1. 什么是单片机

想象一家**只有一名员工的小公司**：

- 一台电脑是一家大公司：CPU、硬盘、内存、网卡……几十个部门各司其职，装在一个大机箱里。
- 单片机（MCU，Microcontroller Unit，微控制器）则是把「CPU + 存储器 + 各种外设」全部集成到**一颗指甲盖大小的芯片**上，相当于这家公司只有一个员工，什么活都得他干。

它每秒能执行几千万到几亿条指令，但只会做简单动作，并且**只忠实执行你写的程序**——程序就是它唯一的工作说明书。没有程序，它就是一块会发热的石头。

RoboMaster 比赛里，每一台机器人的「大脑」就是这样一颗芯片：它读传感器、算控制量、指挥电机，所有决策都来自你的代码。

```
        ┌───────────────── STM32 芯片（迷你公司）─────────────────┐
        │                                                        │
        │  Flash（档案柜）          RAM（办公桌）                  │
        │  程序永久存放             临时数据                       │
        │       │                       │                         │
        │       ▼                       ▼                         │
        │               CPU（唯一的员工）                          │
        │                     │ 总线（走廊）                       │
        │     GPIO  Timer  UART  CAN  DMA ……（各间办公室）          │
        └────────────────────────────────────────────────────────┘
```

**一句话总结：单片机是一颗「把电脑精简成指甲盖大小」的芯片，你的程序就是它唯一的工作说明书。**

### 2. CPU / Flash / RAM：员工、档案柜、办公桌

| 部件 | 公司里的角色 | 干什么 | 特点 | 断电之后 |
|---|---|---|---|---|
| CPU | 员工 | 执行指令、算数、做判断 | 干活快，但没有记忆 | 没事，接着干活 |
| Flash | 档案柜 | 存放你的**程序**（机器码） | 容量大、读写较慢 | **内容还在**（不丢） |
| RAM | 办公桌 | 存放**正在用的数据**（变量） | 容量小、读写飞快 | **全部清空**（丢了） |

- **烧录程序** = 把工作说明书复印一份放进档案柜（Flash）。
- **上电启动** = 员工上班，打开档案柜，把常用资料摊到办公桌（RAM）上开始干活。
- 你写程序时声明的每一个变量，运行时都住在 RAM 里；断电一瞬，它们全消失——所以重要数据要主动存进 Flash。
- 以 STM32F407 为例（RoboMaster 官方开发板 C 型同系列）：主频 168 MHz、Flash 1 MB、RAM 192 KB。Flash 就是它的「硬盘」，RAM 是它的「内存」。
- 想想看：程序下进板子后拔电再插电，它还能跑，说明程序存在哪里？

**一句话总结：CPU 干活、Flash 存程序（断电不丢）、RAM 存临时数据（断电即失）。**

### 3. GPIO：开关手脚

- **是什么**：通用输入输出（General Purpose Input/Output），芯片上的一根根引脚。STM32F407 有上百个引脚，其中大部分都可以当 GPIO 用。
- **解决什么问题**：让单片机「动手」和「感知」——每个引脚既可以当**输出**（对外给出高电平 3.3V 或低电平 0V），也可以当**输入**（读取外界给的是 0 还是 1）。
- **机器人里用在哪**：点亮 LED、读取按键、给传感器发控制信号、灯条指示……是你接触的第一个、也是最常用的外设。

输出常用「推挽输出」（Output Push Pull）：能主动输出高或低，CubeMX 里默认就是这个。输入则要配「上拉/下拉」：

- **上拉（Pull-up）**：引脚内部接一个电阻到 3.3V，悬空时读到 1——适合「按下接地」的按键。
- **下拉（Pull-down）**：引脚内部接一个电阻到 GND，悬空时读到 0。
- **浮空（Floating）**：两边都不接，悬空时读到的是**随机值**（电磁干扰会乱飘）——初学者常见坑。

```
   输出：MCU ──3.3V/0V──▶ LED（亮/灭）
   输入：按键 ──0/1────▶ MCU（读电平）
```

**一句话总结：GPIO 是单片机与外界打交道的开关手脚——输出控制世界，输入感知世界。**

### 4. Timer：闹钟

- **是什么**：定时器，一个**硬件计数器**——每来一个时钟脉冲，计数值就加 1。计满（溢出）可以自动重装并从头再来。
- **解决什么问题**：让单片机精确计时，而且**不用 CPU 盯着**——CPU 去忙别的，定时器到点「叫醒」它（通过中断，见第 8 节）。
- **机器人里用在哪**：产生稳定的控制周期（如 1 kHz 控制循环）、测量电机转速（编码器计数）、生成 PWM 波形。

它有两个旋钮：**预分频器（PSC）** 把高速时钟降频成「较慢的滴答」，**自动重装值（ARR）** 决定数多少个滴答溢出一次：

```
   溢出时间 = (PSC + 1) × (ARR + 1) ÷ 定时器时钟频率
```

**一句话总结：定时器是硬件闹钟——CPU 去忙别的，它到点准时叫你。**

### 5. PWM：可调亮度的灯、可调转速的电机

- **是什么**：脉冲宽度调制（Pulse Width Modulation）。让一个引脚以极高频率在「开/关」之间切换，用**高电平占的时间比例**（占空比）来表示大小。
- **解决什么问题**：芯片引脚只有 3.3V 和 0V 两档，没法直接输出「1.65V」。但快速开关时，外界感受到的是**平均效果**——占空比 50% 的平均电压就是 1.65V。
- **机器人里用在哪**：调节 LED 亮度（呼吸灯）、控制电机转速（摩擦轮）、驱动舵机角度。

PWM 由定时器产生：定时器从 0 数到 ARR，计数值小于 CCR（比较值）时输出高电平，超过则输出低电平：

```
   占空比 = CCR ÷ (ARR + 1) × 100%

   占空比 20%：▊▁▁▁▁▊▁▁▁▁▊▁▁▁▁   （灯暗 / 电机慢）
   占空比 80%：▊▊▊▊▁▊▊▊▊▁▊▊▊▊▁   （灯亮 / 电机快）
```

开关频率要足够高（通常几千到几万 Hz），眼睛和电机才感受不到闪烁，只觉得「大小变了」。

**一句话总结：PWM 靠「快速开关」调节平均功率——占空比越大，灯越亮、电机越快。**

### 6. UART：对讲机

- **是什么**：通用异步收发器（Universal Asynchronous Receiver/Transmitter），俗称「串口」。两根线：TX（发）、RX（收），双方**交叉连接**。
- **解决什么问题**：最简单的一对一通信。双方约定好「语速」（波特率，如 115200 表示每秒传 115200 个位），一个位一个位地把数据说出去，中间不用共享时钟线（所以叫「异步」）。
- **机器人里用在哪**：调试时打印日志（printf 重定向到串口）、连接电脑上位机、与裁判系统/遥控器接收机通信。

```
   MCU1 TX ──────▶ RX MCU2
   MCU1 RX ◀────── TX MCU2    （交叉接）

   波特率必须一致，否则听到的全是乱码
```

**一句话总结：UART 是对讲机——两根线、一对一，说好语速就能通话，调试时最常用。**

### 7. CAN：车间广播总线

- **是什么**：控制器局域网（Controller Area Network），两根差分线（CAN_H / CAN_L）组成的总线，**所有设备并联挂上去**，总线两端各接一个 120 Ω 终端电阻。
- **解决什么问题**：车间广播模式——任何一个设备喊一嗓子，总线上的所有设备都听得见，靠报文 ID 判断「是不是说给我的」；自带优先级仲裁和校验，差分信号抗干扰强，适合多设备实时通信。
- **机器人里用在哪**：RoboMaster 的电机（M3508、M2006 电调）全部通过 CAN 总线接收指令、回传转速，是整车最重要的通信方式——1.4 会深入。

和 UART 对比：UART 是对讲机（一对一），CAN 是车间广播（一对多、多对多）；UART 适合调试打印，CAN 适合车上设备互联。

```
   MCU ──┬── CAN_H ──┬── 电调1 ──┬── 电调2 ──┬── …
         └── CAN_L ──┘           ┘           ┘
```

**一句话总结：CAN 是车间广播——一条总线挂多个设备，抗干扰强，机器人电机都靠它指挥。**

### 8. 中断：快递敲门

- **是什么**：中断（Interrupt）。当某个事件发生时（引脚电平变化、定时器到点、串口收到数据），**硬件会直接打断 CPU 正在干的事**，让它先跳去执行对应的中断服务函数（ISR），处理完再回到原来的位置继续。
- **解决什么问题**：不用 CPU 反复「去门口张望」（轮询）。快递敲门（中断）是「到了才叫你」；轮询是「每隔 10 秒去门口看一眼」——中间快递到了也只能干等。
- **机器人里用在哪**：遥控器数据到达立刻处理、按键按下立刻响应、编码器计数等一切「要求及时响应」的场景。

完整流程：**保存现场 → 执行 ISR → 恢复现场 → 回到原点**。不同中断还有优先级（数值越小越优先），高优先级的可以打断低优先级的。

```
   轮询：CPU 忙… 去门口看 → 没人 → 忙… 去门口看 → 没人 → 忙…（浪费时间）
   中断：CPU 忙…              🔔 敲门！→ 立刻处理 → 回到原位继续忙
```

**一句话总结：中断是快递敲门——事件来了立刻打断处理，不用 CPU 反复去门口张望。**

### 9. DMA：自动搬运工

- **是什么**：直接存储器访问（Direct Memory Access），一个**独立于 CPU 的硬件搬运通道**。
- **解决什么问题**：大批量数据（如连续收几百字节串口数据）如果靠 CPU 一个字节一个字节搬，CPU 就没空干别的了。DMA 说好「从哪搬到哪、搬多少」，然后自己搬，搬完再通知 CPU。
- **机器人里用在哪**：遥控器数据流接收、传感器批量采样、屏幕刷新等大数据搬运场景。

CPU 搬运 = 员工自己一件件搬货；DMA = 雇了台自动传送带，员工只在搬完时说声「收到」。

**一句话总结：DMA 是自动搬运工——大批量数据它来搬，CPU 只管大事。**

### 10. 串起来看：上电后发生了什么

把这些概念串成一条时间线，你就有了单片机运行的整体画面：

```
上电 ──▶ 复位：CPU 从 Flash 的固定地址取出第一条指令
   │
   ▼
初始化：执行 CubeMX 生成的初始化代码
   （配时钟 168MHz → 配 GPIO → 配中断 → 配 DMA ……）
   │
   ▼
主循环：while(1) 里反复干你安排的事
   （读按键 → 判断 → 翻转 LED → 延时）
   │
   ▼
中断随时插入：串口来数据 / 定时器到点 / 按键边沿
   （打断主循环 → 执行 ISR → 回到原位）
```

- 初始化只跑一遍，主循环跑一辈子，中断随时插队——这就是绝大多数单片机程序的骨架。
- 后续 1.4 的电机控制、1.5 的 PID，都是在这个骨架上添砖加瓦。

### 任务一：CubeMX 创建工程

CubeMX 是一个**图形化配置工具**：你在图上点点鼠标（选引脚、配时钟），它帮你生成一整套初始化代码，省去手写几百行寄存器配置。

1. **准备工作**：新建一个全英文路径的文件夹（如 `D:\stm32\lesson1`），作为工程根目录。
2. **打开 CubeMX**：`File → New Project`，进入 MCU 选择界面（旧版叫 Access to MCU Selector，位置不同但功能一样）。
3. **选芯片**：在 Part Number 搜索框输入芯片型号（教程以 STM32F407IG 为例；RoboMaster 开发板 C 型同为 F407 系列，**实际型号看板子丝印/战队要求，封装后缀也要对**）→ 双击选中 → Start Project。
   - 自查点 ✔：芯片图上方显示你选的完整型号。
4. **配引脚**（Pinout & Configuration 页）：点开右侧芯片图，点击 `PA5` → 弹出菜单选 `GPIO_Output`；点击 `PA0` → 选 `GPIO_Input`。然后在 `System Core → GPIO` 里分别给它们起标签（User Label）：`LED`、`KEY`，并把 KEY 的上拉设为 `Pull-up`。
   - 自查点 ✔：芯片图上 PA5、PA0 变成绿色；左侧 GPIO 列表出现 LED、KEY。
5. **配时钟**（Clock Configuration 页）：输入板子实际晶振频率（HSE，常见 8 MHz 或 25 MHz，**看原理图**）→ 配置 PLL 让 SYSCLK 达到 168 MHz（F407 上限）。不会算就点自动求解按钮（旧版叫 "Resolve Clock Issues"）。
   - 自查点 ✔：图中 SYSCLK 显示 168 MHz，没有红色报错。
6. **生成工程**（Project Manager 页）：工程名用字母/数字/下划线，路径选刚建的全英文文件夹；Toolchain / IDE 选 `MDK-ARM V5` → 点右上角 `GENERATE CODE`。
   - 自查点 ✔：工程文件夹里出现 `MDK-ARM/xxx.uvprojx`。
7. **打开工程**：双击 `.uvprojx` 用 Keil 打开，左侧能看到 `Drivers/STM32F4xx_HAL_Driver` 和 `Core/Src/main.c`。
   - 自查点 ✔：按 `F7` 能编译通过（0 Error），说明环境链路完整。

### 任务二：GPIO 点灯

**先接硬件**：LED 长脚（正极）串一个 220 Ω ~ 1 kΩ 电阻，接到 3.3V；短脚（负极）接 PA5。电阻是**限流**用的——LED 导通后两端电压只有约 2V，不串电阻会烧坏引脚或 LED。

**重要规则**：自己写的代码要放在 main.c 里 `/* USER CODE BEGIN 3 */` 和 `/* USER CODE END 3 */` 之间——下次 CubeMX 重新生成代码时，**只保留这两个注释之间的内容**，写在别处会被覆盖。

```c
/* 主循环：程序初始化完成后，会在这里永远转下去 */
while (1)
{
    /* 点亮 LED：引脚输出低电平（本接法是低电平点亮） */
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
    HAL_Delay(1000);                        /* 保持 1 秒 */

    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
    HAL_Delay(1000);                        /* 熄灭 1 秒 */
}
```

- `LED_Pin`、`LED_GPIO_Port` 是 CubeMX 根据你起的 User Label **自动生成**的宏（在 main.h 里），不用自己定义。
- **编译**：Keil 里按 `F7`（Build），下面显示 `0 Error(s)` 才算过。
- **烧录**：接好 ST-Link（1.1 已配置），按 `F8` 下载到板子。
- 预期现象：上电后 LED 亮 1 秒、灭 1 秒，循环往复。
- 自查点 ✔：把 `GPIO_PIN_RESET` 和 `GPIO_PIN_SET` 对调再烧录，灯的亮灭规律是否跟着反转？为什么？

### 任务三：LED 闪烁

点灯 + 延时可以，但更常见的写法是用「翻转」：

```c
while (1)
{
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);   /* 电平翻转：亮 ↔ 灭 */
    HAL_Delay(500);                               /* 等待 500 ms */
}
```

- 预期现象：LED 以 1 Hz 闪烁（500 ms 亮 + 500 ms 灭）。
- 改 `HAL_Delay` 的参数：100 ms 是「快闪」，1000 ms 是「慢闪」，试试看。
- 说明：`HAL_Delay` 是「忙等」延时——CPU 在那空转数数，简单但浪费。更好的做法是用定时器（后续章节），本节先用它。
- 拓展：再配一个 GPIO 输出（如 PB0），做两个灯交替闪烁的「跑马灯」。

### 任务四：按键控制 LED

**先接硬件**：按键一端接 PA0、一端接 GND（利用内部上拉，无需外接电阻）。不按时 PA0 被上拉到 3.3V 读到 1；按下时 PA0 接地读到 0。

第一版代码（先写这版，观察问题）：

```c
if (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET)
{
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);   /* 检测到按下就翻转 LED */
}
```

实测你会发现：**按一下，灯有时连跳好几下**。原因有两个：

1. **机械抖动**：按键的金属触点按下/松开瞬间会弹跳，几毫秒内通断很多次，芯片看到的是「按了 N 次」。
2. **循环太快**：主循环一毫秒跑好几圈，抖动的每一次跳变都被读到了。

```
   理想：按下 ────────────┐ 松开
         ────────────────┘──────
   实际：按下 ╱╲╱╲╱╲────┐╱╲╱╲ 松开   ← 抖动！
         ───╯        ╲╱╯     └──────
```

**防抖**的思路：只认「按下边沿」（上一次是松开、这次是按下），然后**延时 20 ms 等抖动过去**，再确认一次电平。改进版：

```c
uint8_t key_last = 1;   /* 记录上一次按键电平：1 = 松开 */

while (1)
{
    uint8_t key_now = HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin);

    if (key_last == 1 && key_now == 0)          /* 检测到「按下」边沿 */
    {
        HAL_Delay(20);                          /* 等 20ms，抖动结束 */
        if (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == 0)   /* 再确认一次 */
        {
            HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);     /* 确认按下，翻转 LED */
        }
    }
    key_last = key_now;                         /* 记住本次电平，供下次判断边沿 */
}
```

- 预期现象：每按一次，灯**恰好**翻转一次；长按也只触发一次。
- 自查点 ✔：快速连按 10 次，灯翻转 10 次；按住不放，灯不再乱跳。
- 说明：这是最简单的「延时防抖」，对教学够用；更专业的定时器/状态机防抖后续章节再学。

### 任务五（选做）：PWM 呼吸灯

把「点灯」升级成 PWM 调光，预习一下 1.4 的内容：

1. CubeMX 里点 `PA5` → 改选 `TIM2_CH1`，左侧 Timers → TIM2 → Channel1 选 `PWM Generation CH1`。
2. 参数设置里 Prescaler 填 `83`、Counter Period 填 `999`（频率 = 定时器时钟 ÷ (83+1) ÷ (999+1)，定时器时钟看 CubeMX 时钟树，F407 上通常为 84 MHz，算出约 1 kHz）。
3. 生成工程后写代码：

```c
HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);      /* 启动 PWM 输出 */

int b;                                         /* 亮度 0~999 */
while (1)
{
    for (b = 0; b <= 999; b++) {               /* 渐亮 */
        __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, b);
        HAL_Delay(1);
    }
    for (b = 999; b >= 0; b--) {               /* 渐暗 */
        __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, b);
        HAL_Delay(1);
    }
}
```

- 预期现象：LED 像呼吸一样缓缓变亮再变暗——这就是占空比在 0%→100% 之间来回变化的效果。

## 常见问题与排查

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 编译报错 `LED_Pin undefined` | 引脚没配成 GPIO / 没起 User Label | 回 CubeMX 检查引脚和标签，重新生成 |
| 灯怎么都不亮 | 引脚接错；低电平点亮的板子写了 SET；没烧录成功 | 查原理图 LED 接法；万用表量引脚电平；看 Keil 是否下载成功 |
| 按一下按键灯跳好几下 | 没做防抖 | 加边沿检测 + 20 ms 延时 |
| 按键不按时读到的值乱变 | 输入配成了浮空，悬空电平乱飘 | 输入配内部上拉/下拉 |
| 下载报 `No target connected` | ST-Link 没接好 / 驱动问题 | 回看 1.1；检查 SWDIO/SWCLK 接线 |
| 程序行为全乱、延时不对 | 时钟树晶振频率填错 | 核对原理图晶振，重新配时钟 |
| Keil 打开后工程是空的 | CubeMX 里 Toolchain 没选 MDK-ARM V5 | Project Manager 里改选项重新生成 |
| 报路径错误 | 工程路径含中文或空格 | 把工程移到全英文路径 |

定位问题的通用思路（2.7 会系统训练）：**现象 → 假设 → 获取证据 → 缩小范围**。灯不亮就先用万用表量引脚电平，确认是「代码没跑」还是「硬件没接对」。

## 课后自测

1. 用你自己的话解释：CPU、Flash、RAM 在单片机里各管什么？断电之后，谁还记得你的程序？
2. 为什么按一次机械按键，程序可能检测到好几次「按下」？至少说出一种解决方法。
3. GPIO 输出「高电平」是不是一定能点亮 LED？为什么？
4. PWM 的占空比从 30% 调到 80%，LED 亮度和电机转速分别怎么变？
5. 轮询和中断有什么区别？举一个「必须用中断」的场景。
6. 输入引脚配成「浮空」且什么都不接，读到的电平会怎样？应该怎么配？
7. main() 里的 `while(1)` 如果退出会怎样？

<details>
<summary>参考答案</summary>

1. CPU 执行指令、干活；Flash 存程序，断电不丢；RAM 存正在用的变量，断电清空。断电后「记得程序」的是 Flash。
2. 机械触点弹跳，按下/松开瞬间在几毫秒内多次通断；且主循环跑得太快，把每次跳变都读到了。解决：边沿检测 + 延时 20 ms 防抖（或定时器/状态机防抖）。
3. 不一定。LED 是否点亮看的是**两端有没有电压差**：高电平点亮接法（引脚→电阻→LED→GND）输出高电平亮；低电平点亮接法（3.3V→电阻→LED→引脚）输出低电平才亮。
4. LED 更亮（平均功率变大）、电机更快（平均电压变高）。
5. 轮询是 CPU 每隔一会儿主动检查一次；中断是事件发生时硬件立刻打断 CPU。必须用中断的场景：对响应时间要求高的事件，如遥控器数据到达、电机编码器计数。
6. 读到随机值（悬空电平受电磁干扰乱飘）。应该配内部上拉或下拉。
7. 程序会「跑飞」——CPU 会继续顺序执行后面未知的内容，行为不可预测。所以嵌入式主循环通常是死循环（或用 RTOS 接管）。

</details>
