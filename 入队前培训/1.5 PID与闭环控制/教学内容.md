## 核心概念

### 概念一：开环与闭环、

上一节课里我们做过这样的事：想让它转快点，就把电流调大点。问题是——电流发出去了，电机到底转了多少？不知道。如果轮子卡住了、电池电压掉了、地面变滑了，转速早就变了，可我们还蒙在鼓里。这种「只看指令、不看结果」的控制方式，叫**开环控制（Open-Loop Control）**。

- **开环**：输入 → 系统 → 输出，一路向前，没有回头路。
- **闭环控制（Closed-Loop Control）/ 反馈控制（Feedback）**：不停地「看结果 → 算差距 → 修正输出」，输出反过来影响输入。

```
开环：  指令 ──→ 控制器 ──→ 电机 ──→ 转速（漂了没人管）

闭环：  目标 ──→(⊕)──→ PID ──→ 电机 ──→ 转速 ──┐
                ↑                              │
                └────── 编码器测量 ←───────────┘
                 (⊕ = 比一比：Target − Feedback)
```

机器人比赛里为什么广泛使用闭环控制：
1. **负载会变**：装弹、爬坡、对手推搡，同样的电流带不动同样的转速。
2. **电压会掉**：电量下降，同一个电流值对应的实际力矩变小。
3. **条件不可预测**：地面摩擦、轮子磨损每天都在变。

「开环按标定好的值发」听起来也行，但它假设世界不变——赛场上没有这种事。

### 概念二：Target / Feedback / Error

**先给结论：控制 = 不断「测差距、消差距」。这三个词就是闭环的全部家当。**

想象你在洗澡调水温（宿舍可能是固定水温的热水器——但请先想象一个能调的老式水龙头）：

| 术语 | 洗澡里的角色 | 机器人里的角色 |
|---|---|---|
| **Target**（目标值） | 你想要的水温，比如 38°C | 你设定的目标转速，比如 1000 RPM |
| **Feedback**（当前值 / 反馈值） | 手摸到的实际水温 | 编码器测到的当前转速 |
| **Error**（误差） | 差多少：38 − 现在的温度 | Target − Feedback |
| **Output**（输出 / 控制量） | 阀门拧多大 | 发给电调的电流值 |

**Error 是有正负的，符号 = 方向**：

```
手摸 35°C，想要 38°C → Error = +3 → 太凉 → 开大热水（正向输出）
手摸 41°C，想要 38°C → Error = −3 → 太烫 → 关小热水（反向输出）
```

机器人里同理：转速比目标低，Error 为正，加大电流；转速比目标高，Error 为负，减小电流。**如果符号搞反了，系统就会「越错越拧」——转速越低越发反向电流，最后满速反转**（这不是玄学，是正反馈，常见坑见排查表）。

闭环做的事只有一件：**让 Error 尽快变成 0，并保持住**。PID 就是「怎么根据 Error 拧阀门」的一套算法——下一步就拆开讲。

---

### 概念三：P —— 比例（Proportional）

**先给结论：P 是主力输出——差多少，就拧多少；差得越多，拧得越大。**

继续洗澡：水太凉，你就把热水阀拧大一点。凉得越多，拧得越大；已经差不多了，就只拧一点点。这个「输出与误差成正比」的动作就是 P：

```
输出P = Kp × Error
```

- Kp 叫**比例系数**：Error 翻倍，P 项输出就翻倍。
- 举例：Kp = 10，Error = +3 → P 项 = +30；Error = +6 → P 项 = +60。
- P 的特点是**立即反应、没有延迟**，反应速度和 Kp 成正比。Kp 越大，同样的误差拧得越猛。

P 的死穴：**光靠 P 会差一截**。因为 P 靠「误差」吃饭：

```
电机要维持 1000 RPM，必须持续得到 600 的电流（克服摩擦）。
只开 P：输出 = Kp × Error。
若 Kp = 2，要输出 600，就得 Error = 300 → 转速只能稳定在 700 RPM。
Kp 调大到 10：Error = 60 → 稳定在 940 RPM。好一点，但还是差 60。
```

发现了吗——**P 真把误差干到 0，它自己就没力气了**（Error=0 → 输出=0 → 转速掉下来 → 又产生 Error）。这个「差一点点」的稳定状态叫**稳态误差（Steady-State Error）**，或者我们经常说的**静差**。Kp 越大它越小，但 Kp 太大系统会震荡（为什么震荡？输出变化太快，电机跟不上，来回过头）。

- Kp 调大：跟得更快、更有力、稳态误差变小。
- Kp 调太大：超调、震荡、啸叫（「超调」= 冲过目标值再被拉回来）。


---

### 概念四：I —— 积分（Integral）

**先给结论：I 负责算旧账——只要误差一直没清零，它就一直加码，直到把「差一点点」补上。**

洗澡继续：把热水开大了一点，水温还是差 1 度，你就「再拧一点点」；过了会儿还是差，就「再拧一点点」。误差存在的时间越长，你累计拧的量就越大。这个「按误差的累计来加码」的动作就是 I：

```
积分项 = 误差 × 时间 的累计（Error 对时间的积分）
输出I = Ki × 积分项
```

- 只要 Error 不是 0，积分项就一直在累加，输出就一直在加大 → 直到误差被完全消灭。**P 留下的稳态误差，就靠 I 来补。**
- 上面「维持 1000 RPM 需要 600 电流」的例子：加了 I 之后，误差虽然小，但积分项会把输出一路推到 600 并停在那里——误差归零，输出保留。这就是 I 的本事：**从「误差」里攒出「维持所需的力」。**

I 的死穴：**记仇太久会出事**。误差大、时间长时，积分会累计到很大，等到误差已经变负了（已经冲过头了），它还在按旧账猛输出——表现为「冲过头、半天回不来」，这叫**积分饱和（Integral Windup）**。通常的解决方法是给积分**限幅**（见代码一节），进阶方案（积分分离、抗饱和）可以稍微留个印象。

- Ki 调大：静差消得快。
- Ki 调太大：超调变大、震荡、积分饱和。

---

### 概念五：D —— 微分（Derivative）

**先给结论：D 负责预测——看误差正在怎么变，快到了就提前收手。**

洗澡最后一幕：水温噌噌往上涨，眼看快到你想要的 38°C 了，有经验的人会提前把阀门往回拧一点——等真到了 38°C 再收手，惯性（管道里还有热水）会让它冲过头。这个「看变化快慢、提前刹车」的动作就是 D：

```
微分项 = 误差的变化率 = (这次的 Error − 上次的 Error) / dt
输出D = Kd × 微分项
```

- Error 减小得越快，微分项越负 → 提前把输出往回拉，**抑制超调**，相当于给系统加了个「阻尼」，像汽车悬挂里的减震器。
- D 不直接消灭稳态误差（误差不变时微分项为 0），它是「稳定剂」。

D 的死穴：**怕噪声**。编码器数值抖一下，误差就「突然变一下」，微分把这种突变放大，输出就开始乱抖。转速越低、编码器分辨率越低，越明显。所以：
- D 能不加就不加，很多速度环只用 PI。
- 微分滤波、微分先行这些进阶方案留给 2.5。

- Kd 调大：超调变小、曲线更稳。
- Kd 调太大：输出高频抖动、电机嗡嗡响。

### 概念六：合起来——PID 与参数效果表

三项加起来就是 PID 的完整公式（离散形式见下一节代码）：

```
u(t) = Kp·e(t)  +  Ki·∫e(t)dt  +  Kd·de(t)/dt
       └─ 现在 ─┘  └── 过去 ──┘  └── 未来(趋势) ─┘
```

调大某个参数会发生什么，一张表说清（这是本节要背下来的唯一一张表）：

| 调大谁 | 响应速度 | 超调 | 震荡 | 稳态误差 | 主要副作用 |
|---|---|---|---|---|---|
| **Kp** | 变快 | 可能变大 | 过大时震荡 | 减小，但消不掉 | 太大时啸叫、失控感 |
| **Ki** | 略变快 | 变大 | 过大时震荡 | **消除** | 积分饱和（冲过头回不来） |
| **Kd** | 略变快（提前量） | **减小** | 可抑制 | 几乎不影响 | 放大噪声，输出抖动 |

**典型调参顺序（新手请照做）：**

1. **先 P**：Ki = Kd = 0，从 0 开始慢慢加 Kp，加到「基本跟得上、稍微差一点」。
2. **再 I**：慢慢加 Ki，加到稳态误差消失、冲过头在可接受范围内。
3. **最后 D**：如果超调还太大，再加一点点 Kd；**能不加就不加**。
4. 每次只改一个参数、只动一点（比如 ×1.5 或 ×0.7），改完观察再动手。一次改三个等于掷骰子。

调参实录示例（对照着写自己的调参记录）：

```
第 1 步：Kp=1   → 转速升到 700 就上不去了（差 300）→ 记录：跟得上，有静差
第 2 步：Kp=1.5 → 升到 810，开始有点抖 → 记录：静差变小，出现抖动苗头
第 3 步：Kp=1.2, Ki=0.3 → 稳定在 995 左右，轻微冲过头 → 记录：静差基本消除
第 4 步：Kp=1.2, Ki=0.3, Kd=0.05 → 曲线平滑，1 秒内稳定 → 收工
```

> **一句话总结：P 看现在、I 算旧账、D 猜未来；调参顺序一般是先 P、再 I、最后 D。**

### 概念七：离散 PID 代码（在单片机里怎么算）

**先给结论：连续公式到了单片机里，积分变「累加」、微分变「差分」，每隔固定时间算一次。**

单片机按固定周期（控制周期 dt，比如 1ms）执行一次下面的函数。「积分」就是每次把 `Ki×Error×dt` 累加到 `i_term` 上；「微分」就是拿这次的 Error 减上次的 Error 再除以 dt：

```c
/* ---------------- pid.h ---------------- */
typedef struct {
    float kp, ki, kd;        /* 三个参数                          */
    float i_term;            /* 积分累计值（输出单位，见下）       */
    float i_max;             /* 积分限幅：防止积分累计过头         */
    float out_max, out_min;  /* 输出限幅：不超出电调允许的电流范围 */
    float last_error;        /* 上一次的误差，用于算微分           */
} PID_t;

void PID_Init(PID_t *pid, float kp, float ki, float kd,
              float out_max, float i_max);

/* 每个控制周期调用一次，dt 必须固定（如 0.001f = 1ms） */
float PID_Calc(PID_t *pid, float target, float Feedback, float dt);

/* ---------------- pid.c ---------------- */
#include "pid.h"

void PID_Init(PID_t *pid, float kp, float ki, float kd,
              float out_max, float i_max)
{
    pid->kp = kp;  pid->ki = ki;  pid->kd = kd;
    pid->out_max = out_max;
    pid->out_min = -out_max;          /* 本例按双向电机设计 */
    pid->i_max   = i_max;
    pid->i_term  = 0.0f;
    pid->last_error = 0.0f;
}

float PID_Calc(PID_t *pid, float target, float Feedback, float dt)
{
    /* 第 1 步：误差 = 目标 - 当前（差多少） */
    float error = target - Feedback;

    /* 第 2 步 P：差多少拧多少，立即响应 */
    float p_term = pid->kp * error;

    /* 第 3 步 I：把误差按时间累加起来（积分 → 累加）。
       这里乘上 ki 再累加，积分值直接就是「输出单位」，
       限幅时好理解：积分最多能顶多少输出，一目了然。 */
    pid->i_term += pid->ki * error * dt;
    if (pid->i_term >  pid->i_max) pid->i_term =  pid->i_max;   /* 积分限幅 */
    if (pid->i_term < -pid->i_max) pid->i_term = -pid->i_max;

    /* 第 4 步 D：误差的变化率（微分 → 差分），「快到了提前收手」 */
    float d_term = pid->kd * (error - pid->last_error) / dt;
    pid->last_error = error;

    /* 第 5 步：三项求和，输出限幅后发给电调 */
    float output = p_term + pid->i_term + d_term;
    if (output > pid->out_max) output = pid->out_max;
    if (output < pid->out_min) output = pid->out_min;
    return output;
}
```

初始化示例（数值仅为示例，按你手上的电机和电调电流范围调整）：

```c
PID_t speed_pid;
PID_Init(&speed_pid, /*kp=*/1.0f, /*ki=*/0.3f, /*kd=*/0.0f,
         /*out_max=*/5000.0f,     /* 电调允许的最大电流值，量纲与实际一致 */
         /*i_max=*/4000.0f);      /* 积分限幅：量级同输出限幅 */
```

> 小注：真机工程里 D 常改成「作用在测量值上」（用 Feedback 的变化率代替 Error 的变化率，也叫微分先行），这样目标突然跳变时输出不会被打出一个大尖峰——本节演示文档的仿真器就是这种写法。这里先按课本形式写，2.5 再展开。

> 与战队工程对应：框架里的 PID 用的是 `algorithm/Pid.hpp` 里的 `Pid` 类，一次 `SetParams(p, i, d, f, max, imax, isLoop)` 设好参数，每个周期调 `UpdateResult(target, feedback)` 直接拿输出。它比本节这个 `PID_t` 多了三样：① 前馈系数 `f`（kf）；② 积分限幅 `imax` + 抗饱和开关 `I_stop`；③ 微分低通滤波（`SetDerivativeMode`）。2.5 会对着它逐条展开。

两个「现在先照做、原理以后细学」的点（本节先埋下伏笔，2.5 会展开）：

1. **dt 必须固定**：PID 参数是和 dt 配套的。dt 从 1ms 变成 10ms，同样的参数效果完全不同。所以调用 `PID_Calc` 的代码要放在**定时器中断**（或 RTOS 周期任务）里，不要放在 `while(1)` 里裸跑——那里每次循环时间不定。如果在主循环里跑，请先确认你的主循环周期稳定。
2. **积分限幅**：`i_max` 一般取在「输出限幅」量级（本例可设 `out_max` 左右）。它防止积分项无限累计，是应对积分饱和的第一道防线。

### 概念八：把 1.4 的知识接起来——速度环数据流

**先给结论：闭环就是把 1.4 学过的「读反馈」和「发控制量」中间，加上一步「算 PID」。**

回顾 1.4 建立的链路，现在它在每个控制周期里完整转一圈：

```
        ┌────────────────────────────────────────────────┐
        │                                                │
        ▼                                                │
  [Target 目标转速]                                        │
        │                                                │
        ▼                                                │
  (⊕) 比一比：Error = Target − Feedback                    │
        │                                                │
        ▼                                                │
  [PID_Calc] → Output（控制量，电流）                      │
        │                                                │
        ▼                                                │
  [STM32 → CAN → 电调]                                    │
        │                                                │
        ▼                                                │
  [电机] → 转速                                           │
        │                                                │
        ▼                                                │
  [编码器 → 电调 → CAN → STM32]                           │
        │                                                │
        └────────────────────────────────────────────────┘
        （1.4 学过的东西全部没变，只是中间多了 PID 这一步）
```

- 编码器给的是「转过的角度/圈数」，要自己换算成转速（RPM）——1.4 已经做过。
- 换算完记得**滤波**（滑动平均即可），否则微分项会被噪声折腾。
- 单位统一：Target 和 Feedback 必须用同一个单位（都 RPM 或都 rad/s），Error 才有意义。

### 概念九：术语速查表

本节新词都在这里，忘了就回来看一眼：

| 术语 | 一句话解释 |
|---|---|
| 开环（Open-Loop） | 只看指令不看结果，蒙眼开车 |
| 闭环（Closed-Loop） | 测结果 → 算差距 → 修正，睁眼开车 |
| Target（目标值） | 想要的值（水温 38°C / 转速 1000 RPM） |
| Feedback（当前值） | 传感器测到的实际值 |
| Error（误差） | Target − Feedback，有正负（方向） |
| Output（输出） | 控制器算出来的控制量（电流） |
| 稳态误差 | 稳定后仍差的那一截，靠 I 消灭 |
| 超调（Overshoot） | 阶跃后冲过目标值 |
| 震荡（Oscillation） | 稳定不下来，来回晃 |
| 积分饱和（Windup） | 积分累计过头，冲出去回不来 |
| dt（控制周期） | 每次算 PID 的间隔，必须固定 |
| 限幅 | 给输出/积分设上下限，防止失控 |

### 任务一：电机速度闭环（核心任务，约 45 分钟）

**准备**：确认 1.4 的两段代码还能跑：① `Encoder_GetSpeedRPM()` 能读出实时转速；② `Motor_SetFeedback()` 能发电流让电机转。

**步骤：**

1. **把 pid.c / pid.h 加入工程**：复制上面的代码，编译通过。
   ✔ 自查：0 error, 0 warning（警告也别放过）。
2. **搭好控制周期**：在 1ms 定时器中断（或已有的周期任务）里调用：

   ```c
   /* 中断里每 1ms 执行一次 */
   void TIM_Control_Callback(void)
   {
       float Feedback_rpm = Encoder_GetSpeedRPM();       /* 1.4 学的：读反馈 */
       float out = PID_Calc(&speed_pid, speed_target, Feedback_rpm, 0.001f);
       Motor_SetFeedback((int16_t)out);                  /* 1.4 学的：发控制量 */
   }
   ```

   ✔ 自查：给 `speed_target` 一个值，电机能转；说明「读→算→发」链路通了。

### 中间插一课：怎么「读」一条响应曲线

调参不是玄学，是「看图说话」。拿到一条阶跃响应曲线，先找这四个东西：

```
转速
  ↑         ┌──── 超调量：冲过头多少
  │        ╱ ╲
  │       ╱   ╲___╭──────── 稳态：误差还剩多少
  │      ╱        ╲
  │     ╱
  │    ╱
  │___╱
  └────┴────┴──────┴──→ 时间
       └─ 上升时间 └─ 调节时间（进 2% 带不再出来）
```

1. **上升时间**：从 10% 爬到 90% 目标值花多久。越短越「有力」（主要靠 Kp）。
2. **超调量**：冲过目标多少（如目标 1000，冲到 1200，超调 20%）。靠 Kd 压、靠 Ki 别太大。
3. **稳态误差**：稳定后和目标差多少。有静差 → 加 I。
4. **震荡**：稳定后是否还在来回晃、晃几下。晃 → Kp/Ki 太大。

判读口诀：**「慢」加 Kp，「差」加 Ki，「冲」加 Kd，「抖」减 Kp（或减 Kd）。**

## 常见问题与排查

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 电机高频抖动 / 啸叫 | Kp 过大 | Kp 减半再试 |
| 转速稳定在目标以下一截 | 只有 P，存在稳态误差 | 加 I（Ki 慢慢加） |
| 阶跃后冲过头很多 | Kd 太小 / 没加，或 Kp 偏大 | 先降 Kp，再加一点点 Kd |
| 低速时输出抽动 | D 放大了编码器噪声 | 减小 Kd；滤波方案见 2.5 |
| 目标改大后冲过头、半天回不来 | 积分饱和 | 检查 i_max 是否设置；临时清积分再调 |
| 电机越转越快直到满速 | 误差符号反了（变成正反馈） | 检查编码器方向 / 电机正反转定义 |
| 输出一直顶在限幅值 | 参数整体太大或目标超范围 | 目标调小、参数整体缩小 |
| 每次上电表现都不一样 | 控制周期不稳定 | 确认在定时器中断里调用 PID |
| 转速数值乱跳 | 编码器换算错误或未滤波 | 先静止读码，确认 0；加滑动平均滤波 |
| 改小 Kp 没反应 | 积分项还在「记仇」 | 调参前先清积分（重置 i_term） |

<details>
<summary>参考答案（先自己想，再看答案）</summary>

1. Target 是想要的值，Feedback 是传感器测到的实际值，Error = Target − Feedback。Error 为负说明实际值超过了目标（如转速比设定值还快），此时控制量应往反方向调整。
2. P 项输出 = Kp × Error，转速要维持必须持续有电流，但 Error 归零时 P 项输出也归零，所以系统会停在「差一点点」的平衡点（稳态误差）。I 把误差随时间累加：只要还有误差，积分项就不断增大，直到误差被完全消灭；稳态时误差为 0，积分项保留为维持输出所需的电流。
3. D 看误差的变化率：误差在快速缩小，说明马上就到位了，D 提前把输出往回拉，避免惯性冲过头。它怕噪声：编码器数值抖动会让微分项剧烈跳动。
4. 伪代码四步：error = target − Feedback；积分项累加并限幅；微分项 = (error − last_error) / dt；输出 = 三项和，限幅后发出。dt 固定是因为积分/微分都以 dt 为基准，dt 变了相当于偷偷改了 Ki 和 Kd，参数全部作废。
5. 例：开环 = 微波炉按说明书热 2 分钟（不管饭实际热没热）；闭环 = 电饭煲跳到保温（不断测温、停火、再加温）。
6. 响应变快、更有力，但超调变大；Kp 太大时会震荡甚至啸叫。（以真机实测为准。）
7. Ki 减小后积分「记仇」变轻：冲过头的高度变小、回到目标的速度变快，最后仍能消掉稳态误差，只是消得慢一点。
8. 按顺序：① 误差符号（编码器方向 / 电机方向定义，最常见）；② 输出限幅是否设置过大或未设置；③ 目标值是否合理。都排除了再怀疑参数。
