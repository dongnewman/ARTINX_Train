# 1.1 环境配置

> 本节目录 / 建议课时：120 分钟（讲解 30 + 实操 90）｜前置要求：无

一句话：把「写代码、编译、烧录」的全套工具装进电脑，然后让第一个程序真正跑起来。从今天起，你的电脑就不再是写作业的电脑，而是一台「机器人工厂」。

## 学习目标

- [ ] 说清编辑器、编译器、IDE 三者的区别，并各举一个本节安装的例子
- [ ] 独立完成 VS Code、MSYS2+GCC、Git、Python 的安装与验证
- [ ] 在命令行把 `hello.c` 编译成 `hello.exe` 并运行
- [ ] 画出 PC 程序与 STM32 程序两条「源码 → 运行」流水线
- [ ] 会用 `gcc --version`、`python --version`、`git --version`、`code --version` 验证安装
- [ ] 认识 Keil MDK、STM32CubeMX、ST-Link 各自扮演的角色
- [ ] 遇到「不是内部或外部命令」时，会检查 PATH 并重开终端

## 核心概念

### 概念〇：先看全景——本节要装的 8 个工具

先不急着动手，花一分钟看完整张地图。本节要装的工具分两组：

| 工具 | 一句话是什么 | 类比 | 这节用它做什么 |
|---|---|---|---|
| VS Code | 写代码的编辑器 | 一支好用的笔 | 编辑 `.c` 文件 |
| MSYS2 | Windows 上的工具仓库 + 仓库管理员 | 工具超市 + 配送员 | 提供 GCC 和终端 |
| GCC | C 语言编译器 | 翻译官（PC 版） | 把 `.c` 翻译成 `.exe` |
| Python | 脚本语言运行环境 | 计算器/万能小助手 | 装好备用，调试分析会用到 |
| Git | 版本管理工具 | 游戏存档系统 | 管理代码版本（1.6 节细学） |
| STM32CubeMX | STM32 图形化配置工具 | 芯片的「装配图纸生成器」 | 生成工程骨架（1.3 节细学） |
| Keil MDK | 单片机开发的 IDE | 集成工具箱（含翻译官） | 编译 STM32 程序 |
| ST-Link | 烧录 + 调试用的硬件 | 数据线 + 听诊器 | 把程序送进单片机 |

两组流水线贯穿全节，先记住它们的形状：

```
PC 流水线：    hello.c ──gcc 编译──▶ hello.exe ──▶ 在本机运行
STM32 流水线： main.c  ──Keil 编译──▶ main.hex ──ST-Link 烧录──▶ 在板子上运行
```

**一句话总结：8 个工具 = 1 支笔（VS Code）+ 2 个翻译官（GCC、Keil 内置编译器）+ 1 个工具箱（Keil）+ 1 根数据线（ST-Link）+ 4 个辅助（MSYS2、Python、Git、CubeMX）。**

### 概念一：编辑器、编译器、IDE——三种软件角色

新手最容易混的三个词，用「写文章」来类比一次讲透：

- **编辑器（Editor）= 笔**。它只负责让你舒服地写字，不负责让字「跑起来」。VS Code 就是一支很好用的笔：语法高亮（关键字变色）、自动补全（打一半它帮你补）、括号配对，写代码手感极佳。
- **编译器（Compiler）= 翻译官**。你写的是 C 语言，CPU 只认机器语言（一串 0 和 1），中间需要翻译。编译器读入你的 `.c` 文件，吐出 CPU 能执行的机器码文件。PC 上的翻译官叫 **GCC**；STM32 上 Keil 内置的翻译官叫 **Arm Compiler（armclang）**。
- **IDE（集成开发环境）= 集成工具箱**。把笔、翻译官、调试器、工程管理全部打包进一个软件，打开就能干活。**Keil MDK** 就是给单片机开发用的工具箱；VS Code 本体只是笔，装上插件后才能「拼装」出半个工具箱。

三者关系一句话：

```
编辑器（笔）     → 负责「写」
编译器（翻译官） → 负责「翻译」
IDE（工具箱）    → 把笔 + 翻译官 + 调试器装进一个软件
```

顺便拓宽一下眼界：这三类软件在行业里都有很多选择（本节不安装，知道名字即可）：

- 编辑器：VS Code、Vim、Notepad++、Sublime Text
- 编译器：GCC、Clang、Arm Compiler（armclang）、MSVC
- IDE：Keil MDK、Visual Studio、CLion、STM32CubeIDE、IAR Embedded Workbench

对新手来说：**先认准本节这套组合，等熟悉了再折腾别的**。工具是服务于开发的，别在选工具上花太多时间。

**一句话总结：编辑器用来写，编译器用来翻译，IDE 把整条流水线的工具打包成一个软件。**

### 概念二：编译与运行——PC 程序的一生

你在 PC 上写的程序，从敲下第一行代码到屏幕上出现结果，要经历四个阶段：

```
hello.c ──▶ gcc 编译 ──▶ hello.exe ──▶ 运行
(人类能读)   (翻译)      (机器能读)    (输出 Hello, ARTINX!)
```

1. **写源码**：用 VS Code 新建 `hello.c`，写下人类能读的 C 语言。
2. **编译**：在终端敲 `gcc hello.c -o hello.exe`，gcc 把整个文件翻译成机器语言，打包成 `hello.exe`。编译成功时翻译官**一句话都不说**（没有输出就是最好的消息）；翻译不动时会告诉你哪一行有问题——这叫**编译报错**。
3. **得到可执行文件**：`hello.exe` 就是成品，双击也能运行。
4. **运行**：在终端敲 `.\hello.exe`，CPU 执行机器码，`printf` 的内容出现在屏幕上。

编译失败长什么样？假如你把某行的分号删了再编译，会看到类似这样的输出（`:` 后面是行号和原因）：

```
hello.c: In function 'main':
hello.c:6:19: error: expected ';' before 'return'
```

翻译官罢工时会尽量告诉你「哪一行、什么问题」，学会读报错是本节第一个技能点。

两个新手最容易踩的理解坑，提前打好预防针：

1. **机器语言是什么**：CPU 只认一串 0 和 1 组成的指令。你写的 `printf(...)` 经过翻译，会变成一大串人类读不懂的机器码——`hello.exe` 里装的就是它。用记事本强行打开 `.exe` 只会看到乱码，别试（试了也没关系）。
2. **改了源码必须重新编译**：`.exe` 是编译那一刻源码的「快照」。你改完 `hello.c` 里的文字直接运行 `hello.exe`，输出不会变——必须先重新执行 `gcc hello.c -o hello.exe`。很多新手卡在这里：「我明明改了代码，怎么输出没变？」

**一句话总结：编译就是把 `.c` 翻译成 `.exe`，运行就是让 `.exe` 执行；编译时翻译官沉默 = 成功，开口 = 报错；改了源码必须重新编译。**

### 概念三：STM32 的编译、烧录、调试流水线

STM32 是意法半导体（ST）出的一种单片机（MCU）——你可以把它理解成「指甲盖大小的微型电脑芯片」，是以后机器人上跑我们代码的「大脑」（1.3 节细讲）。

给 STM32 写程序和给 PC 写程序最大的不同：**程序不在写代码的这台电脑上运行，而在另一块芯片上运行**。所以流水线多出两步——烧录和调试：

```
main.c ──Keil 编译──▶ main.hex ──ST-Link 烧录──▶ 板子上的 STM32 ──▶ LED 亮起
(源码)   (翻译+打包)   (固件)      (送进芯片)      (芯片执行)
```

- **编译**：在 Keil 里点 Build（快捷键 F7）。Keil 内置的翻译官（Arm Compiler）把工程里所有 `.c` 文件翻译、打包，产出固件文件（`.hex`；还生成一个带调试信息的 `.axf`，Keil 下载时实际用它，新手记住「编译产出固件」即可）。
- **烧录（下载）**：点 Download（快捷键 F8），Keil 通过 **ST-Link** 这个硬件把固件写进单片机的 Flash（芯片里断电也不丢的存储区）。**类比：把歌从电脑拷进 MP3**——Flash 就是芯片的「内置 MP3 存储」。
- **运行**：烧录一完成，芯片自动开始执行你的程序，板子上的 LED 亮起。
- **调试**：程序不听话时，点 Start Debug（快捷键 Ctrl+F5）进入调试模式，可以让程序**暂停**在任意一行（断点）、按 F10 **一行一行执行**（单步）、随时查看变量值。**调试器 = 医生的听诊器**，能「听」到芯片内部每一步在干什么。

**一句话总结：STM32 流水线 = 编译（Keil 翻译）→ 烧录（ST-Link 送进芯片）→ 运行（板子执行），比 PC 多出的「烧录」就是把程序送进另一块芯片。**

### 概念四：ST-Link——数据线兼听诊器

ST-Link 是一个 U 盘大小的硬件，ST 官方出品。它有双重身份：

1. **数据线**：烧录时，把编译好的固件从电脑送进单片机。连接方式叫 SWD，通常接四根线：`SWDIO`（数据）、`SWCLK`（时钟）、`GND`（地）、`3V3`（供电）——线序以板子丝印为准，插错方向不会烧（先核对再上电）。
2. **听诊器**：调试时，Keil 通过它给芯片「下指令」——暂停在断点、单步执行、读变量，甚至修改变量。没有它，芯片里发生了什么你完全看不见。

Windows 端：Keil MDK 安装时已经顺带装好了 ST-Link 的 USB 驱动；插上 ST-Link 后，设备管理器里应出现 `STMicroelectronics` 字样的设备，这是「硬件连通」的第一个信号。

**一句话总结：ST-Link 是电脑与单片机之间的桥梁——烧录时当数据线，调试时当听诊器。**

### 概念五：命令行与 PATH——为什么敲 gcc 就能启动程序

终端（命令行）是程序员最常用的工具之一：一个黑色的窗口，敲命令、回车、看输出。你在 VS Code 里按 <kbd>Ctrl</kbd>+<kbd>`</kbd> 就能打开内置终端（PowerShell）。

现在思考一个问题：你在终端敲 `gcc --version`，系统怎么知道 `gcc` 这个程序在哪？答案是 **PATH**——一份「程序文件夹通讯录」：

```
你在终端敲：gcc --version
     │
     ▼ 系统：gcc.exe 在哪？翻 PATH 通讯录——
  C:\Windows\System32        → 没有
  C:\Program Files\...       → 没有
  C:\msys64\ucrt64\bin       → 找到了！运行它 ✔
     │
     ▼
  终端打印 gcc 的版本信息
```

- PATH 是一个环境变量，里面存着一串文件夹路径，系统按顺序逐个翻找你要的程序。
- 安装 MSYS2 后，`gcc.exe` 躺在 `C:\msys64\ucrt64\bin` 里。只有把这个文件夹**加进 PATH**，任何终端才找得到它。
- **PATH 是启动终端时读入的**：改完 PATH 后，已经开着的终端（包括 VS Code 内置终端）不会自动刷新——**必须重开**。

报错「'gcc' 不是内部或外部命令，也不是可运行的程序或批处理文件」翻译成人话就是：「我把 PATH 通讯录翻遍了，没找到 gcc.exe」。这不是没装好，而是系统**找不到**。

**一句话总结：系统按 PATH 列表找程序；报「不是内部或外部命令」= PATH 没配好，或改了 PATH 没重开终端。**

### 概念六：本节黑话速查表

第一次接触开发的同学会遇到一堆「行话」，这里集中翻译一遍。以后听到这些词，回来翻这张表：

| 黑话 | 人话 |
|---|---|
| 终端 / 命令行 / Shell | 敲命令、看输出的黑窗口（PowerShell、MSYS2 UCRT64 都是终端） |
| 编译（build） | 把源码翻译打包成可运行文件的过程 |
| 固件（firmware） | 烧进单片机里的程序文件（`.hex`/`.axf`/`.bin`） |
| 烧录 / 下载（flash / download） | 把固件写进单片机 Flash 的动作 |
| Flash | 单片机里断电不丢的程序存储器 |
| 调试（debug） | 暂停程序、单步执行、观察变量，找出它为什么不听话 |
| 断点（breakpoint） | 让程序跑到某一行就暂停的标记 |
| 驱动（driver） | 让操作系统认识某个硬件的翻译软件 |
| 开源（open source） | 源代码公开，任何人都能看、能用 |
| 仓库（repository） | 一个项目的「档案库」，存代码和所有历史版本（1.6 节细学） |

**一句话总结：行话不用背，见到不懂的词回来查这张表。**

## 动手实践

> 安装顺序建议：先 PC 三件套（VS Code → MSYS2+GCC → Git/Python），立刻用任务四尝到「程序跑起来」的甜头；再装 STM32 三件套（Keil → CubeMX → ST-Link 烧录）。
> 所有安装包只从官方下载页获取（链接见「延伸资源」），不要随便搜「XX 下载站」。
> 环境要求：Windows 10/11 64 位，预留 10GB 以上磁盘空间，网络畅通。
> Mac 用户注意：MSYS2、Keil MDK 都是 Windows 软件，Mac 上请提前准备 Windows 环境（虚拟机或双系统）。（**具体以战队统一安排为准**）

### 任务〇：课前准备——注册账号（约 10 分钟，建议课前完成）

装 Keil 和 CubeMX 时都需要登录账号，而注册 + 邮箱验证可能要等几分钟，建议提前办好：

1. **做什么**：
   - Arm 账号：打开 Keil 官方下载页（https://www.keil.com/download/product/），点右上角注册（Register），用常用邮箱注册并完成验证。
   - ST 账号：打开 STM32CubeMX 页面（https://www.st.com/en/development-tools/stm32cubemx.html），点登录区注册 ST 账号并完成验证。
2. **预期现象**：两个账号都能正常登录各自官网，邮箱收到验证邮件。
3. **自查点 ✔**：把账号密码记在手机备忘录里（**不要用与学号相关的弱密码**）。

### 任务一：安装 VS Code（编辑器，约 10 分钟）

1. **做什么**：打开 VS Code 官网（https://code.visualstudio.com），点 Windows 下载按钮，运行安装包。一路 Next 即可。
2. **安装选项**：出现「选择附加任务」页面时，勾上「**添加到 PATH**」（英文界面为 *Add to PATH*）；「将"通过 Code 打开"操作添加到资源管理器右键菜单」建议也勾上。
3. **预期现象**：桌面出现 VS Code 图标；打开后左侧是文件栏，中间是编辑区。界面默认英文，可选装「Chinese (Simplified)」语言包，非必需。
4. **自查点 ✔**：在 VS Code 里按 <kbd>Ctrl</kbd>+<kbd>`</kbd> 打开内置终端，输入 `code --version`，回车后输出版本号即成功。

### 任务二：安装 MSYS2 + GCC（编译器，约 25 分钟）

1. **做什么**：打开 MSYS2 官网（https://www.msys2.org），下载 x86_64 安装器，安装到默认位置 `C:\msys64`。**安装路径不要有中文和空格**。
2. **打开 UCRT64 终端**：开始菜单搜索「MSYS2 UCRT64」并打开——这是 MSYS2 提供的终端，绿底黑字提示符 `$`。
3. **更新仓库**：在 UCRT64 终端里输入以下命令并回车，中途问 `[Y/n]` 就按 Y：

   ```bash
   pacman -Syu
   ```

   更新完成后，按提示**关掉终端，重新打开一次**。
4. **安装 GCC**：

   ```bash
   pacman -S mingw-w64-ucrt-x86_64-gcc
   ```

5. **验证（在 UCRT64 终端内）**：输入 `gcc --version`，应输出类似 `gcc (MSYS2) 14.2.0` 的版本信息。
6. **让任何终端都能用 gcc（PATH 配置）**：打开 Windows 设置 → 系统 → 关于 → 高级系统设置 → 环境变量 → 系统变量里找到 `Path` → 编辑 → 新建一行 `C:\msys64\ucrt64\bin` → 一路确定。**改完重开所有终端（包括 VS Code）**。
7. **自查点 ✔**：新开一个 PowerShell，输入 `gcc --version` 能输出版本信息，即全线打通。

### 任务三：安装 Git 与 Python（各约 10 分钟）

**Git（版本管理工具）**：

1. **做什么**：打开 Git 官网下载页（https://git-scm.com/download/win），下载 64 位安装包。
2. **安装选项**：一路 Next 用默认配置即可；某一步会让你选默认编辑器，可以改成 VS Code（也可保持默认，不影响使用）。
3. **自查点 ✔**：终端输入 `git --version`，输出 `git version 2.x.x` 即成功。

**Python（脚本语言）**：

1. **做什么**：打开 Python 下载页（https://www.python.org/downloads/），下载 Windows 安装包。
2. **安装选项（最关键一步）**：安装第一页**务必勾选「Add python.exe to PATH」**，再点 Install Now。漏勾是新手第一大坑（症状：`python` 命令被 Windows 商店抢走）。
3. **自查点 ✔**：终端输入 `python --version`，输出 `Python 3.x.x` 即成功。

### 任务四：编译并运行第一个程序（约 15 分钟）

1. **做什么**：用 VS Code 新建文件 `hello.c`（建议单独建一个 `C:\code\lesson1` 文件夹存放），内容如下：

   ```c
   #include <stdio.h>          /* 引入「标准输入输出」工具包 */

   int main(void) {            /* 程序入口：一切从这里开始执行 */
       printf("Hello, ARTINX!\n");  /* 打印一句话，\n 是换行 */
       return 0;               /* 告诉系统：正常结束 */
   }
   ```

2. **编译**：在 VS Code 内置终端里先进入文件所在目录（右键文件夹 → 「在集成终端中打开」），执行：

   ```bash
   gcc hello.c -o hello.exe
   ```

   **预期现象：什么都没有输出**。翻译官沉默 = 成功，文件夹里多出一个 `hello.exe`。
3. **运行**：

   ```bash
   .\hello.exe
   ```

   **预期现象**：终端输出 `Hello, ARTINX!`。
4. **自查点 ✔**：把 `printf` 里的文字改成自己的名字，重新编译运行，输出跟着变。
5. **故意试错（强烈推荐）**：删掉某一行结尾的分号再编译一次，读一读 gcc 的报错——注意 `hello.c:6:19` 这类「文件名:行号:列号」格式，它直接告诉你错误在哪一行。

### 任务五：安装 Keil MDK（STM32 的 IDE，约 30 分钟）

1. **做什么**：打开 Keil 官方下载页（https://www.keil.com/download/product/），注册/登录 Arm 账号后下载 **MDK-Arm** 安装包，运行安装。
2. **安装选项**：**安装路径不要带中文**，其余一路默认。MDK 安装时会顺带装好 ST-Link 的 USB 驱动。
3. **许可证**：个人学习使用免费的 **MDK Community** 版本（非商业用途免费，见 https://www.keil.arm.com/mdk-community/ 的激活指引）。不激活也能编译小于 32KB 的代码（Lite 模式），但建议按页面指引激活。
4. **装芯片支持包（DFP）**：打开 Keil 里的 Pack Installer（工具栏绿色图标），搜索战队开发板使用的 STM32 系列（**以战队当前使用的开发板型号为准，讲解时现场演示**），安装对应的 DFP 包——没有它，Keil 不认识我们的芯片。
5. **自查点 ✔**：新建工程（Project → New µVision Project）时，芯片列表里能搜到我们的 STM32 型号。

### 任务六：安装 STM32CubeMX（配置工具，约 20 分钟）

1. **做什么**：打开 ST 官方页面（https://www.st.com/en/development-tools/stm32cubemx.html），注册/登录 ST 账号后下载安装（下载需要登录是正常的；若安装时提示需要 Java 运行环境（JRE），按提示安装 64 位 JRE 即可）。
2. **预期现象**：打开 CubeMX，点 New Project 能看到芯片选择器（按型号/系列筛选的搜索框）。
3. **自查点 ✔**：搜索我们板子的芯片型号，点开后能看到芯片的引脚图（正面视图）。
4. CubeMX 的用法（选引脚、配时钟、生成 Keil 工程）留到 1.3 节细讲，本节装好即可。

### 任务七：烧录第一个程序到开发板（约 30 分钟，讲解时演示）

1. **做什么**：领取战队开发板与 ST-Link（**设备由战队统一准备，讲解时说明领取方式**）。用杜邦线连接 ST-Link 与板子上的 SWD 口：`SWDIO`、`SWCLK`、`GND`、`3V3` 四根线（线序以板子丝印为准，不确定就问学长学姐）。
2. **打开示例工程**：（**讲解时结合战队现有示例工程演示**，此处不虚构具体路径）点 Build（F7）编译，看下方 Build Output 输出 `0 Error(s)`。
3. **烧录**：Options for Target → Debug 选项卡 → 选择「ST-Link Debugger」→ 点 Download（F8）。
4. **预期现象**：下载进度条走完，板子上的 LED 亮起/闪烁——你的代码第一次在芯片里跑起来了。
5. **调试初体验**：点 Start Debug（Ctrl+F5）进入调试模式 → 在 `main` 函数里某一行左侧点一下设置**断点** → 点运行，程序会停在断点行 → 按 F10 一行一行走，观察程序执行的顺序。
6. **自查点 ✔**：能指着屏幕说出「刚才的编译、烧录、运行分别发生在哪几个动作上」。

## 常见问题与排查

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| `gcc` 不是内部或外部命令 | PATH 没配，或配完没重开终端 | 检查 PATH 里有没有 `C:\msys64\ucrt64\bin`；配好后**重开所有终端**再试 |
| 输入 `python` 弹出 Microsoft Store | 安装时没勾 Add to PATH，或商店「应用执行别名」抢占 | 重装并勾选；或在设置里关闭 python 的应用执行别名 |
| 终端中文输出乱码 | 终端代码页不是 UTF-8 | 先执行 `chcp 65001`；新手练习期间可先用英文输出 |
| gcc 报错 `expected ';'` 之类 | 代码语法错误（缺分号/括号/引号） | 读报错里的「文件名:行号」，去那一行附近找 |
| `gcc: error: hello.c: No such file or directory` | 终端当前目录和文件所在目录不一致 | 用 `dir`（PowerShell）或 `ls`（MSYS2）看当前目录，先 `cd` 到文件所在目录 |
| 改了源码但运行结果没变 | 改完没重新编译，`.exe` 还是旧的 | 每次改完源码都要重新执行 `gcc hello.c -o hello.exe` |
| 找不到「环境变量」窗口 | Windows 设置层级太深 | Win+X → 系统 → 高级系统设置 → 环境变量；或直接搜索「编辑系统环境变量」 |
| Keil 新建工程搜不到 STM32 型号 | 没装对应系列的 DFP 支持包 | Pack Installer 里搜索芯片系列并安装 |
| Keil 编译 0 Error 但烧录失败 | ST-Link 未连接/没选对调试器 | 查四根线；Options for Target → Debug 选 ST-Link Debugger |
| 插上 ST-Link 电脑毫无反应 | 驱动没装 / 线或 USB 口接触不良 | 设备管理器看有无 `STMicroelectronics` 设备；换 USB 口、换线 |
| `pacman` 下载极慢或失败 | 网络 / 镜像源问题 | 换网络重试；或搜索「MSYS2 国内镜像」配置镜像源 |
| VS Code 终端里找不到 gcc | VS Code 开在 PATH 修改之前 | 完全退出 VS Code 再打开 |

## 课后自测

1. 用一句话分别说明编辑器、编译器、IDE 是干什么的，并各举一个本节安装的例子。
2. 写出把 `hello.c` 编译成可执行文件并运行的完整命令。
3. PC 程序与 STM32 程序两条流水线的共同点是什么？不同点是什么？
4. 终端报「'gcc' 不是内部或外部命令」，列出你要依次检查的三件事。
5. `.hex` 文件是什么？它和 `.c` 文件是什么关系？
6. （思考题）为什么给 STM32 开发必须有一个叫 ST-Link 的硬件，而给 PC 开发不需要任何额外硬件？

<details><summary>参考答案</summary>

1. 编辑器负责「写」代码（VS Code）；编译器负责把 C 语言翻译成机器语言（GCC / Keil 内置的 Arm Compiler）；IDE 是把编辑器、编译器、调试器打包在一起的工具箱（Keil MDK）。
2. `gcc hello.c -o hello.exe`，然后 `.\hello.exe`。
3. 共同点：都是 源码 → 编译 → 得到可执行产物 → 运行。不同点：PC 程序在本机直接运行 `.exe`；STM32 程序多出「烧录」一步——通过 ST-Link 把固件（`.hex`/`.axf`）写进板子上单片机的 Flash，然后由芯片执行。
4. ① PATH 里有没有 `C:\msys64\ucrt64\bin`；② 改了 PATH 后有没有重开终端；③ gcc 是否真的装上了（在 MSYS2 UCRT64 终端里试 `gcc --version`）。
5. `.hex` 是编译后的固件，是给芯片执行的机器语言「安装包」；`.c` 是人类写的源码。编译把 `.c` 变成 `.hex`（Keil 还会生成带调试信息的 `.axf`）。
6. 因为程序要跑在**另一块芯片**上，必须用硬件把固件送进芯片的 Flash；同时 ST-Link 兼任调试器，能暂停、单步、观察芯片内部状态。PC 程序就在本机运行，编译完直接执行即可。
</details>
