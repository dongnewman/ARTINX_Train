三种角色：编辑器 / 编译器 / IDE

角色定义类比（一句话）本节例子
编辑器 Editor编写、修改源代码的软件，不负责执行笔VS Code
编译器 Compiler把源代码翻译成机器语言（0/1 指令）的程序翻译官GCC、Arm Compiler
IDE 集成开发环境编辑器 + 编译器 + 调试器 + 工程管理的套件工具箱Keil MDK
关系：编辑器负责写，编译器负责翻译，IDE 把整条流水线打包成一个软件。
拓展：编辑器还有 Vim / Notepad++，编译器还有 Clang / MSVC，IDE 还有 Visual Studio / STM32CubeIDE——先认准本节组合。

流水线一：PC 程序的一生

hello.c

→

翻译成机器语言

hello.exe

→

四个阶段

1. 写：VS Code 编写 hello.c
2. 编译：终端执行 gcc 命令
3. 产物：hello.exe（机器码）
4. 运行：终端执行 .\hello.exe

命令

gcc hello.c -o hello.exe
.\hello.exe

编译无输出 = 成功

读编译报错：翻译官的定位信息

报错示例（故意删掉一个分号）

hello.c: In function 'main':
hello.c:6:19: error: expected
';' before 'return'

格式：文件名:行号:列号: 原因

两条铁律

1. 编译成功时翻译官沉默：没有输出 = 成功，生成 hello.exe。
2. 改了源码必须重新编译：.exe 是编译那一刻源码的快照，不重编译输出不会变。

新手第一大坑：改了 printf 里的文字，直接运行 .exe 发现没变——因为忘了重新编译。

LED 亮起

· 与 PC 的区别：程序跑在另一块芯片上，多出「烧录」一步；烧录 = 把固件写进单片机 Flash（类比：把歌拷进 MP3）。
· 调试：Ctrl+F5 进入调试模式，断点暂停、F10 单步执行、观察变量。

ST-Link：数据线兼调试器

定义与双重身份

ST 官方烧录调试器（硬件），连接电脑与单片机：
· 数据线：烧录时把固件经 SWD 接口写进芯片 Flash；
· 听诊器：调试时让程序暂停、单步、读变量（类比一句话带过）。

连接与验证

SWD 四根线：
SWDIO 数据、SWCLK 时钟、GND 地、3V3 供电
（线序以板子丝印为准，先核对再上电）
驱动随 Keil MDK 安装；设备管理器出现 STMicroelectronics 设备即连通。

Keil 中启用：Options for Target → Debug → 选择 ST-Link Debugger。

PATH：系统找程序的「通讯录」

定义

PATH 是环境变量，存一串文件夹路径。终端敲命令时，系统按顺序在这些文件夹里找同名程序，找到即运行，找不到报错。

查找 gcc 的过程

C:\Windows\System32    无
C:\Program Files\...   无
C:\msys64\ucrt64\bin   找到 → 运行

修改入口：高级系统设置 → 环境变量 → Path

报错「'gcc' 不是内部或外部命令」= PATH 里没有它所在文件夹；改完 PATH 必须重开终端才生效。

PART 2
动手实践

安装、验证、跑起来

每个工具四步走：下载 → 安装选项 → 验证命令 → 自查点

安装 1/4：VS Code（编辑器）

下载与安装选项

官网 code.visualstudio.com 下载 Windows 版，一路 Next。
附加任务勾选 添加到 PATH；右键菜单「通过 Code 打开」建议勾选。

验证与使用

code --version

输出版本号即成功。内置终端：Ctrl+` 打开，后续所有命令都在这里跑。

功能定位：语法高亮、自动补全、插件扩展；可选装中文语言包（非必需）。

安装 2/4：MSYS2 + GCC（编译器）

概念

MSYS2：Windows 包管理器 + 类 Unix 工具集（终端 + pacman）。GCC：C 语言编译器（经 MinGW-w64 提供）。
安装到 C:\msys64，路径无中文、无空格；官网 www.msys2.org。

UCRT64 终端内执行

pacman -Syu
pacman -S mingw-w64-ucrt-x86_64-gcc

第一条更新仓库（按 Y 回车）；更新完按提示重开终端。

PATH 与验证

PATH 添加 C:\msys64\ucrt64\bin，改完重开所有终端；

gcc --version

输出 gcc (MSYS2) 版本信息即全线打通。

安装 3/4：Git 与 Python

Git：版本管理

git-scm.com/download/win 下载 64 位安装包，一路 Next（默认编辑器可选 VS Code）。

git --version

输出 git version 即成功；用法在 1.6 节展开。

Python：脚本语言

python.org/downloads 下载安装包；第一页务必勾选 Add python.exe to PATH，再 Install Now。

python --version

漏勾症状：python 命令打开 Microsoft Store。

第一个程序：编译并运行

hello.c

#include <stdio.h>   /* 引入标准输入输出工具包 */

int main(void) {      /* 程序入口 */
    printf("Hello, ARTINX!\n");
    return 0;         /* 正常结束 */
}

编译与运行

gcc hello.c -o hello.exe
.\hello.exe

编译无输出 = 成功；运行输出 Hello, ARTINX!

自查：改文字重编译，输出跟着变；故意删一个分号，读报错行号。

安装 4/4：Keil MDK（IDE）

是什么

单片机集成开发环境：编辑器 + Arm Compiler 编译器 + 调试器 + 工程管理。
下载：keil.com/download/product（需 Arm 账号）；安装路径无中文，自带 ST-Link 驱动。

许可与支持包

个人学习使用免费 MDK Community 许可（非商业）：keil.arm.com/mdk-community。
Pack Installer 中安装对应 STM32 系列的 DFP 芯片支持包。

验证：Project → New µVision Project 时，芯片列表能搜到我们的 STM32 型号。

安装 4/4：STM32CubeMX（配置工具）

是什么

ST 官方图形化配置工具：选芯片、配引脚与时钟，自动生成初始化代码和 Keil 工程。
下载：st.com 官方页面（需 ST 账号）；若提示需要 Java 运行时（JRE），按提示安装 64 位 JRE。

验证

New Project → 搜索芯片型号 → 看到芯片引脚图即成功。

详细用法（选引脚、配时钟、生成工程）在 1.3 节展开。

任务：烧录并调试第一个程序

  1. 接线：ST-Link 接板子 SWD 口四根线：SWDIO / SWCLK / GND / 3V3（线序以丝印为准）
  2. 打开示例工程（讲解时提供），F7 编译，Build Output 显示 0 Error
  3. Options for Target → Debug 选 ST-Link Debugger，F8 下载烧录
  4. 预期：进度条走完，板子 LED 亮起——代码第一次在芯片里运行
  5. 调试：Ctrl+F5 进入调试，断点暂停、F10 单步、观察变量

开发板与 ST-Link 由战队统一准备（领取方式讲解时说明）；示例工程结合战队现有工程演示。
