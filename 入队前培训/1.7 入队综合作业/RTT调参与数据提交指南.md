# RTT 调参与数据提交指南

## 1. 这次 RTT 要完成什么

RTT 在作业中有两个用途：

1. 上行：从 C 板读取目标转速、实际转速、误差、PID 输出和当前参数，实时画曲线并保存 CSV。
2. 在线调参：通过战队 RTT 调试器把新 PID 参数写入下位机公开的参数结构体，再由固件校验、应用并回传确认。

只看到终端文字不算完成；只保存 CSV、不用数据解释参数变化也不算完成。

## 2. 下位机输出格式

战队工具按 `Key:value` 解析，每行用逗号分隔并以换行结束：

```cpp
SEGGER_RTT_printf(0,
    "Time:%lu,Mode:%d,Target:%.2f,Speed:%.2f,Error:%.2f,Output:%.2f,Kp:%.5f,Ki:%.5f,Kd:%.5f\n",
    Time::GetTick(), mode, target_rpm, speed_rpm,
    target_rpm - speed_rpm, output, kp, ki, kd);
```

建议控制周期 1 ms、RTT 输出周期 5 ms。若丢样明显，先降低下位机输出频率，不要只调低界面刷新率。

## 3. 启动工具

1. 解压 `ARTINX_RTT工具_去Git.zip`。
2. 安装 Python 依赖：

```powershell
python -m pip install PyQt5 pyqtgraph numpy pandas matplotlib pyocd psutil
```

3. 启动带 PID 写入功能的版本：

```powershell
python rtt_debugger\rrt_qtmonitor.py
```

4. 目标芯片选择 `STM32F407IGHx`。
5. 选择当前工程或当前固件对应的 ELF/MAP 路径。
6. 先只启动监控，确认变量列表持续更新，再打开示波器视图。

## 4. 在线参数写入

框架中的 `components/Debug/DebugTask.cpp` 提供了 `g_host_control` 参数结构体示例。使用时要特别注意：

- 它当前只是共享数据结构，最终工程必须由你实现“校验并应用到 PID”的逻辑；
- 工具使用调试器直接写内存，写入地址必须来自当前固件；
- 每次重新编译后，地址可能变化；
- 写入前保持电机在 0 档或低速档，并使用小输出限幅；
- 参数生效后应通过 `Kp/Ki/Kd` 回传字段确认，不要只相信按钮提示。

推荐下位机应用顺序：

```text
读取共享结构体快照
→ 校验通道、ID、数值范围和有限性
→ 判断参数是否真的变化
→ 电机进入安全状态或清除积分
→ SetParams(...)
→ 更新“当前生效参数”回传字段
```

## 5. 三轮数据怎么保存

至少保存：

| 文件 | 内容 |
|---|---|
| `A_baseline.csv` | 只有 P 的低速/中速基线 |
| `B_tuning.csv` | 只改变一个参数后的对比 |
| `C_final_all_gears.csv` | 0/低/中/高/0 完整循环 |

每次记录前，在报告里先写“这一轮只改什么、预计会发生什么”；记录后再写实际现象。不要录完所有数据才倒推理由。

## 6. 曲线最少要看什么

- `Target` 与 `Speed` 同图：看上升、超调、稳态误差和调节时间。
- `Error`：看误差是否长期偏一侧，是否存在明显振荡。
- `Output`：看输出是否长时间顶住限幅。
- `Mode`：确认按键切换时间与目标变化一致。
- `Kp/Ki/Kd`：确认每一段数据对应的真实参数。

## 7. 数据质量检查

交付前打开 CSV 检查：

- 第一行字段名完整；
- `Time` 基本单调递增；
- 没有把 `Time:` 文本污染到数值列；
- 一行的字段数稳定；
- 目标变化前后至少各有 1 s 数据；
- 文件名与报告中的轮次、参数一致；
- 记录的固件确实是产生该 CSV 的固件。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 连接不上 | 检查调试器、供电、芯片型号、占用该调试器的其他软件 |
| 有文本无变量 | 检查 `Key:value`、逗号和换行格式 |
| 曲线卡顿 | 降低下位机输出频率，减少字段，不要在 1 kHz 控制循环中无限打印 |
| 写入成功但参数没变 | 核对地址、结构体布局、固件应用逻辑和回传字段 |
| 重新编译后写入异常 | 重新从 MAP/ELF 获取地址，旧地址禁止继续使用 |
| 参数一改电机猛冲 | 停机；检查限幅、积分清零、数值范围和速度方向 |
