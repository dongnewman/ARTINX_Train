# 1.7 入队综合作业

这次作业只做一件事：把一台 CAN 电机做成一个能切换四档速度、能闭环跟踪、能用数据调参的小型控制系统。

最终效果必须是：按一次 C 板用户按键，档位依次按照 **0 → 低速 → 中速 → 高速 → 0** 循环；板载 RGB LED 用不同颜色显示档位；电机由 PID 速度环控制；运行曲线由战队 RTT 工具实时观察并保存为 CSV；PID 参数要经过多轮 RTT 实验调整，而不是直接照抄。

> 安全前提：电机必须固定在台架上，输出轴周围不得有线缆和松散物，首次运行从 0 档和小输出限幅开始。任何失控、异响、过热或 CAN 掉线都应立即断电。

## 作业目标

- [ ] 能在战队 C 板代码框架中找到并使用 CAN 电机、PID、RTT 和任务调度接口。
- [ ] 能对 C 板用户按键做边沿检测和非阻塞防抖，按一次只切换一次档位。
- [ ] 能实现 0、低、中、高四档目标速度，并用板载 RGB LED 显示当前档位。
- [ ] 能在固定周期内执行速度 PID，正确处理限幅、停机和参数更新。
- [ ] 能用 RTT 同时观察目标转速、实际转速、误差和 PID 输出，并保存 CSV。
- [ ] 能借助 RTT 在线修改 PID 参数，保留至少三轮调参记录并解释现象。
- [ ] 能完成安全、可重复、可测量的验收演示。

## 一、统一任务定义

### 1. 硬件范围

统一使用：

- RoboMaster 开发板 C 型；
- 战队统一指定的一台 DJI CAN 电机及其电调；
- ST-Link、DAP-Link 或 J-Link 调试器；
- 稳固的空载电机台架；
- 具有限流能力的合适电源；
- 战队提供的去 Git 代码框架与 RTT 工具。

不允许自行增加遥控器、外接按键或外接指示灯来替代 C 板上的按键和 RGB LED。可以增加保护罩、固定件和理线件。

### 2. C 板按键与 RGB LED

根据《RoboMaster 开发板 C 型用户手册》：

| 功能 | 单片机引脚 | 有效电平 |
|---|---|---|
| 用户按键 KEY | PA0 | 按下为低电平 |
| 蓝色 LED | PH10 | 高电平点亮 |
| 绿色 LED | PH11 | 高电平点亮 |
| 红色 LED | PH12 | 高电平点亮 |

这些引脚可能尚未在起始工程的 CubeMX 配置中启用。你需要核对 `.ioc`、重新配置 GPIO，并检查重新生成代码后自定义代码是否仍然存在。

### 3. 四档状态与灯色

| 档位 | 目标转速 | LED | 说明 |
|---|---:|---|---|
| 0 档 | 0 RPM | 熄灭 | 上电默认状态；PID 输出必须为 0 |
| 低速 | 1000 RPM | 蓝色 | 首次闭环与方向检查使用 |
| 中速 | 3000 RPM | 绿色 | 主要调参档位 |
| 高速 | 5000 RPM | 红色 | 完成低、中速验证后才允许进入 |
| 故障 | 0 RPM | 红色闪烁 | CAN 超时或异常，输出为 0 |

如果导师在发放硬件时公布了不同的统一转速表，以公布值为准，并在报告首页写清楚。不能每个人自行选择不同的验收转速。

### 4. 按键行为

每次确认一次“按下边沿”后，状态循环一次：

```text
上电
  ↓
0 档 ──按下──> 低速 ──按下──> 中速 ──按下──> 高速
  ↑                                               │
  └───────────────────按下────────────────────────┘
```

最低要求：

- 上电必须进入 0 档；
- 按住按键不能连续跳档；
- 机械抖动不能造成一次按键跳过多个档位；
- 防抖不得使用会阻塞控制任务几十毫秒的 `HAL_Delay()`；
- 0 档和故障状态必须清空 PID 积分并发送 0 控制量。

推荐使用“原始电平变化 → 等待稳定 20 ms → 确认边沿”的非阻塞状态机。

## 二、程序功能要求

### 1. 软件模块建议

建议至少划分为四个职责：

```text
Button       读取 PA0、消抖、产生一次按下事件
ModeManager  管理 0/低/中/高档与目标转速
MotorCtrl    读取 CAN 反馈、执行 PID、发送电流命令
Telemetry    发布 RTT 字段、接收在线参数、保存实验依据
```

模块名字可以不同，但不能把所有逻辑都堆在一个无限循环里。

### 2. 固定周期速度环

速度环必须在稳定的周期任务中运行。推荐沿用框架中的 1 ms 控制任务；如果实际使用其他周期，必须在报告中说明并让 PID 计算与该周期一致。

```text
档位 → target_rpm ─┐
                   ├→ error → PID → current_cmd → CAN 电调 → 电机
CAN 反馈 → speed_rpm┘                                  │
       ↑                                                │
       └──────────────────── 编码器反馈 ────────────────┘
```

PID 至少满足：

- 误差方向为 `target - feedback`；
- 输出限幅与积分限幅有效；
- 参数集中定义，不能散落在多个文件；
- 0 档、故障、重新使能时清除积分；
- 在线修改参数时拒绝 NaN、负限幅和明显越界值；
- 调参过程中仍保留硬件级断电手段。

### 3. CAN 掉线保护

记录最近一次电机反馈时间。如果连续 100 ms 没有收到该电机的有效反馈：

1. 立即把目标与输出清零；
2. 进入故障状态；
3. 红灯闪烁；
4. 不得自动恢复高速运行；
5. 排除故障后，重新上电或执行导师规定的复位流程，从 0 档重新开始。

### 4. RTT 上传字段

RTT 输出必须使用稳定、清晰的键名。建议每 5 ms 上传一次：

```cpp
SEGGER_RTT_printf(0,
    "Time:%lu,Mode:%d,Target:%.2f,Speed:%.2f,Error:%.2f,Output:%.2f,Kp:%.5f,Ki:%.5f,Kd:%.5f\n",
    Time::GetTick(), mode, target_rpm, speed_rpm,
    target_rpm - speed_rpm, output, kp, ki, kd);
```

控制任务可以是 1 kHz，但 RTT 不要无节制打印。字段过多或频率过高会造成丢样，也会干扰控制任务。

### 5. RTT 在线调参

使用战队 RTT 调试器的 PID 参数写入区域，把上位机参数写到下位机公开的 `volatile` 参数结构体。下位机应完成：

- 检查目标电机 ID 与通道；
- 检查 Kp、Ki、Kd、输出限幅、积分限幅是否在允许范围；
- 只在参数发生变化时应用；
- 应用后清除旧积分，避免参数切换瞬间产生大输出；
- 把当前生效参数重新通过 RTT 上传，形成闭环确认。

注意：战队工具当前采用调试器直接写内存的方式，不等同于 SEGGER RTT Down Channel。必须使用当前固件对应的 ELF/MAP 地址，重新编译后地址可能变化。

## 三、PID 调参实验

### 1. 统一顺序

1. 电机断电，确认按键和四种 LED 状态正确。
2. 只接 CAN 反馈，不输出电流，确认转速符号和电机 ID 正确。
3. 进入低速档，小输出限幅，先设置 `Ki = 0`、`Kd = 0`，从较小 Kp 开始。
4. 逐步增加 Kp，直到响应明显变快但仍无持续振荡。
5. 如有稳定静差，再逐步增加 Ki，并观察积分是否长时间顶住限幅。
6. 只有在噪声和超调现象确实需要时才尝试 Kd；每次只改一个参数。
7. 在低速通过后，再验证中速和高速，不允许直接从未知参数开始高速实验。

### 2. 至少保留三轮记录

| 轮次 | 目的 | 需要保留的证据 |
|---|---|---|
| A | 只有 P 的基线 | CSV、参数、响应曲线、现象描述 |
| B | 调整 P 或加入 I | CSV、只改了哪个参数、变化原因 |
| C | 最终参数 | 三档完整切换 CSV、稳定性指标、选择理由 |

至少一轮应保留“不够好”的参数。调参报告要说明它为什么不好，而不是只交最终数字。

### 3. 需要观察的指标

- 上升时间：进入目标附近用了多久；
- 超调量：最高转速超过目标多少；
- 稳态误差：稳定后平均速度与目标的差；
- 调节时间：进入并持续保持在误差带内用了多久；
- 输出饱和比例：PID 输出有多少时间顶在限幅；
- 档位切换：四档循环是否顺序正确、有没有跳档；
- 数据完整性：CSV 时间是否单调、字段是否齐全、是否明显丢样。

## 四、验收标准

### 1. 功能验收

- 上电 3 秒内电机不转，LED 显示 0 档；
- 连续按键 8 次，档位严格按 0/低/中/高循环两轮；
- 每次按键只切换一次，按住不连跳；
- 蓝/绿/红分别对应低/中/高，0 档熄灭；
- 三个非零档位均由 PID 闭环控制，不允许直接写固定电流冒充调速；
- CAN 反馈断开后 100 ms 内输出归零并进入故障显示。

### 2. 性能验收

在统一空载台架和统一目标转速下：

- 低、中、高三档稳定后的平均误差均不超过目标值的 ±5%；
- 进入每个档位后 2 s 内进入 ±5% 误差带；
- 无持续振荡、无长时间输出饱和；
- 四档循环运行 5 min，不出现异常跳档、掉线后继续输出或明显温升异常。

若硬件条件使统一阈值不合理，导师应在发题前统一修改，而不是在验收现场针对个人临时放宽。

### 3. RTT 验收

- 能实时看到 `Time/Mode/Target/Speed/Error/Output/Kp/Ki/Kd`；
- 能选取目标与实际转速绘制同一张曲线；
- 能保存至少三份 CSV；
- 能在线修改 PID，并从回传字段确认新参数已生效；
- CSV 文件名包含轮次、关键参数或时间，例如 `B_Kp0.8_Ki0.02_20260910.csv`。

## 七、推荐开发节奏

### 第 1 步：只做 LED 和按键

电机不通电，完成 GPIO 配置、按键防抖、四档状态机和 LED 映射。

### 第 2 步：只读 CAN 反馈

确认电机 ID、CAN 通道、反馈频率、速度单位和方向。

### 第 3 步：小输出开环检查

固定电机、限制输出，只验证发送方向与停止路径。开环仅用于检查，不计入最终功能。

### 第 4 步：低速闭环

接入速度 PID，先 P 后 I，观察 RTT 曲线。

### 第 5 步：在线调参与三档验证

通过 RTT 修改参数，保留每轮 CSV；低速通过后再进入中速和高速。

### 第 6 步：故障、长时间与答辩测试

完成 CAN 掉线、连续按键、5 min 循环和随机现场修改。

## 八、常见问题与排查

| 现象 | 常见原因 | 排查顺序 |
|---|---|---|
| 按一次跳两档 | 没做边沿检测或防抖 | 先看 PA0 原始值，再看消抖状态，再看事件计数 |
| LED 颜色相反或混色 | PH10/11/12 映射或电平写错 | 用单色测试逐个核对蓝/绿/红 |
| 电机不转 | 供电、CAN、ID、控制帧、输出为 0 | 按硬件到软件顺序逐层检查 |
| 一给 Kp 就反向加速 | 速度符号或误差方向错误 | 检查 `target - feedback` 与安装方向 |
| 目标为 0 仍有输出 | 积分未清零或模式未关断 | 检查 0 档分支和 PID Reset |
| RTT 有数据但没有曲线 | 键值格式不规范或字段变动 | 固定 `Key:value`、逗号分隔、换行结束 |
| 在线参数写入无效 | 地址来自旧固件或下位机未应用 | 重新编译，核对 MAP/ELF 地址和回传参数 |
| CSV 时间重复/缺行 | 输出过快、UI 刷新与采样混淆 | 降低下位机打印频率，检查 MCU 时间戳 |

## 九、答辩现场修改

导师随机选择一个局部改动，限时完成并重新验证，例如：

- 把低速档改成新的统一数值；
- 修改 LED 颜色映射；
- 将防抖时间从 20 ms 改为 30 ms；
- 新增一列 RTT 字段；
- 修改 CAN 超时阈值；
- 解释并修复一个速度方向错误。

现场修改的目标不是比手速，而是确认你能找到正确位置、理解因果并用数据复验。
